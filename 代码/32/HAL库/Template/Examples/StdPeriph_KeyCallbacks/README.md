# STM32F103ZE 标准库：通用长短按与回调

这是独立的标准外设库示例源码，尚未接入当前 HAL 工程。
在 STM32F103ZE 的标准库工程中添加 key.c、main.c，并添加 key.h 所在的头文件路径。
使用本例 main.c 时替换原有 main，不能同时保留两个 main。

## 工程前提

- 器件：STM32F103ZE；使用高容量启动文件 startup_stm32f10x_hd.s。
- 宏定义：STM32F10X_HD、USE_STDPERIPH_DRIVER。
- 提供 CMSIS、system_stm32f10x.c、标准库头文件和 stm32f10x_conf.h。
- 添加 stm32f10x_gpio.c、stm32f10x_rcc.c 及相应头文件。
- 标准库时钟配置必须与实际晶振一致；SystemCoreClockUpdate 只更新频率变量。
- SysTick_Handler 只保留一个定义。若 stm32f10x_it.c 已定义，合并其中的逻辑。
- 本例占用 SysTick 作为 1ms 时基；已有时基时应直接使用它的毫秒计数。

## 引脚与功能

| 按键 | 配置 | 短按 | 长按 | 长按阈值 |
|---|---|---|---|---|
| PA0 | 下拉，按下接高电平 | 翻转 PB5 LED | 两灯全亮 | 1000ms |
| PE2 | 上拉，按下接低电平 | 翻转 PE5 LED | 两灯全灭 | 1200ms |
| PE3 | 上拉，按下接低电平 | 蜂鸣器响 100ms | 切换持续鸣叫 | 1500ms |
| PE4 | 上拉，按下接低电平 | 翻转两灯 | 两灯及蜂鸣器全关 | 2000ms |

PB8 是蜂鸣器使能输出。本例按有源蜂鸣器或带驱动模块实现；无源蜂鸣器需由定时器产生方波，并由这些回调启停。
LED 默认低电平亮，蜂鸣器默认高电平工作；这只是可修改的接线假设。
请根据原理图修改 main.c 顶部的 LED1_ACTIVE_LEVEL、LED2_ACTIVE_LEVEL、BEEP_ACTIVE_LEVEL。

## 三种传参

1. Key_Init 的 port、pin、active_level：决定读取哪个按键，以及什么电平表示按下。
2. on_short、on_long：传入功能函数的地址，分别绑定短按和长按行为。
3. arg：功能函数使用的用户参数。示例中相同 Led_Toggle 配合 &led1 或 &led2，控制不同 LED。

初始化传 Led_Toggle，不要写 Led_Toggle()；前者是函数地址，后者是立即调用函数。
Key_t 对象和 arg 指向的对象必须在整个使用期间有效；示例使用静态对象。
本例短按、长按回调共享一个 arg；如需分别传参，可扩展成 short_arg、long_arg。
不需要的回调允许传 NULL。

## 状态与时间

每个 Key_t 都保存自己的消抖状态、时间和长按已触发标志，因此可同时跟踪多个按键。
Key_Process 先把输入电平统一成“按下/松开”，再进行消抖和事件判断。
按下或松开的采样状态持续稳定 20ms 后才确认。
按压计时从最终确认的那一段稳定按下的起始采样开始；松开计时截止于最终确认的稳定松开开始。
按住达到长按阈值时触发一次，松开不再触发短按；短按在确认松开时触发。
相等阈值归为长按。松开消抖时间不计入按住时长。
全部时间使用 uint32_t 毫秒差值，支持正常的计数回绕；主循环必须保持及时扫描。
扫描周期 5ms，因此事件时间存在扫描粒度误差；短于消抖时间的按压不产生事件。
上电时已按住的键也会在消抖确认后被识别。

SysTick 中断只更新计数，所有按键回调都在主循环执行。
回调中不能添加阻塞延时或等待松开的循环，否则其他按键不能及时扫描。
蜂鸣器定时响采用“启动时记录时间，主循环到期关闭”，没有 Delay_ms。
多个按键在同一次扫描触发时，回调按数组顺序执行；如果同时操作同一输出，后执行的回调决定最终结果。

## 学习顺序

1. 看 App_GPIO_Init，确认上下拉和输出电平。
2. 看 Key_t，区分配置和运行状态。
3. 看 Key_Init，理解保存参数和函数地址。
4. 看 Key_Process，依次理解采样、消抖、按下、松开、长按单次触发。
5. 看 App_Keys_Init，把实际引脚和功能绑定起来。
6. 看主循环，理解为什么四个按键可以共用一个函数。
