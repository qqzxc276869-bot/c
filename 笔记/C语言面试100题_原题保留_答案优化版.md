# 一、基本数据类型的考察（1-4）

## 第 1 题

### 原题

```text
1、请填写 bool , float, 指针变量 与“零值” 比较的 if 语句。
提示：这里“零值”可以是 0, 0.0, FALSE 或者“空指针”。例如 int 变量 n 与“零值”比较的 if 语句为：
if ( n == 0 )
if ( n != 0 )
以此类推。
（1）请写出 bool flag 与“零值”比较的 if 语句：
（2）请写出 float x 与“零值”比较的 if 语句：
（3）请写出 char *p 与“零值”比较的 if 语句
```

### 优化答案

（1）`bool flag`：

```c
if (flag) {
    /* flag 为真 */
}

if (!flag) {
    /* flag 为假 */
}
```

（2）`float x`：对**计算得到的浮点数**，通常不要直接用 `== 0.0f`，而是给出允许误差：

```c
#include <math.h>

const float EPSILON = 1e-6f;

if (fabsf(x) < EPSILON) {
    /* x 可认为等于 0 */
}
```

也可以写成：

```c
if (x >= -EPSILON && x <= EPSILON) {
    /* x 接近 0 */
}
```

（3）指针：

```c
if (p == NULL) {
    /* 空指针 */
}

if (p != NULL) {
    /* 非空指针 */
}
```

> 原资料把“浮点数绝对不能用 `==`”说得过于绝对。关键是：浮点计算结果常有舍入误差，因此判断“接近 0”时通常使用误差范围。

## 第 2 题

### 原题

```text
2、以下为 Linux 下的 32 位 C 程序，请计算 sizeof 的值。
char str[] = “Hello” ;
char *p = str ;
int n = 10;
请计算
（1）sizeof (str) =
（2）sizeof (p) =
（3）sizeof (n) =
（4）void Func ( char str[100])
{
…… ;
}
请计算 sizeof(str) =
（5）void *p = malloc(100);
请计算 sizeof(p) =
```

### 优化答案

题目已经限定为 **Linux 32 位 C 程序**，按常见 32 位环境：

```text
（1）sizeof(str) = 6
（2）sizeof(p)   = 4
（3）sizeof(n)   = 4
（4）sizeof(str) = 4
（5）sizeof(p)   = 4
```

解释：

- `char str[] = "Hello"` 实际包含 `H e l l o \0`，所以数组大小为 6。
- `p` 是指针，32 位环境中通常占 4 字节。
- `int` 在题目环境中为 4 字节。
- 函数形参中的 `char str[100]` 会调整为 `char *str`，因此 `sizeof(str)` 求的是指针大小。
- `malloc(100)` 虽然申请了 100 字节，但 `sizeof(p)` 仍只计算指针本身，不会得到 100。

## 第 4 题

### 原题

```text
4、用变量a给出下面的定义
e) 一个有10个指针的数组，该指针是指向一个整型数 的;
f) 一个指向有10个整型数数组的指针 ;
g) 一个指向函数的指针，该函数有一个整型参数并返 回一个整型数;
h) 一个有10个指针的数组，该指针指向一个函数，该 函数有一个整型参数并返回一个整型数;
```

### 优化答案

```c
/* e) 10 个 int* 组成的数组 */
int *a[10];

/* f) 指向“含 10 个 int 的数组”的指针 */
int (*a)[10];

/* g) 指向函数的指针：参数 int，返回 int */
int (*a)(int);

/* h) 10 个函数指针组成的数组 */
int (*a[10])(int);
```

判断复杂声明时，可以先找到变量名 `a`，再按括号和运算符优先级向外读。

# 二、数组、指针、内存、结构体常考点（5-28）

## 第 5 题

### 原题

```text
5、设有以下说明和定义：
typedef union {long i; int k[5]; char c;} DATE;
struct data { int cat; DATE cow; double dog;} too;
DATE max;
则语句 printf("%d",sizeof(struct date)+sizeof(max));的 执行结果是：_____
```

### 优化答案

**按原题代码，程序无法正确编译。**

原因是定义的是：

```c
struct data
```

但 `sizeof` 中写的是：

```c
sizeof(struct date)
```

`struct date` 并没有定义。

如果题目本意是：

```c
sizeof(struct data) + sizeof(max)
```

那么结果还取决于平台的数据模型和内存对齐规则。原资料给出的 `52` 只是在特定环境下，并且把 `struct date` 当作 `struct data` 后得到的结果。

另外，`sizeof` 的返回类型是 `size_t`，规范打印应使用：

```c
printf("%zu", sizeof(struct data) + sizeof(max));
```

## 第 6 题

### 原题

```text
6、请问以下代码有什么问题：
int main()
{
char a;
char *str=&a;
strcpy(str,"hello");
printf(str);
return 0;
}
```

### 优化答案

主要有两个问题。

`str` 只指向变量 `a` 的 1 字节空间：

```c
char a;
char *str = &a;
```

但 `"hello"` 需要 6 字节（5 个字符加 `'\0'`），因此：

```c
strcpy(str, "hello");
```

会发生越界写入，属于**未定义行为**。

另外：

```c
printf(str);
```

把字符串本身当作格式字符串，也不安全。应写成：

```c
char str[6];

strcpy(str, "hello");
printf("%s", str);
```

## 第 7 题

### 原题

```text
7、请问以下代码有什么问题：
char* s="AAA";
printf("%s",s);
s[0]='B';
printf("%s",s);
有什么错？
```

### 优化答案

`"AAA"` 是字符串字面量，不允许通过指针修改它：

```c
char *s = "AAA";
s[0] = 'B';   // 未定义行为
```

如果不需要修改，应写：

```c
const char *s = "AAA";
```

如果需要修改，应使用字符数组：

```c
char s[] = "AAA";

s[0] = 'B';
printf("%s", s);   // BAA
```

## 第 9 题

### 原题

```text
9、 c和c++ 中的struct有什么不同？
```

### 优化答案

在 C 中，`struct` 主要用于组织数据，本身没有 C++ 中那套成员函数、继承和访问控制机制。

在 C++ 中，`struct` 可以包含：

- 成员函数；
- 构造函数、析构函数；
- 继承；
- 访问控制等。

C++ 中 `struct` 和 `class` 最典型的区别是默认访问权限：

```text
struct：默认 public
class ：默认 private
```

默认继承权限也有类似差别。

## 第 10 题

### 原题

```text
10、void getmemory(char *p)
{
p=(char *) malloc(100);
strcpy(p,“hello world”);
}
int main( )
{
char *str=NULL;
getmemory(str);
printf(“%s/n”,str);
free(str);
return 0;
}会出现什么问题？
```

### 优化答案

`getmemory(str)` 不能把新申请的地址写回 `main` 中的 `str`。

C 的参数是**值传递**，调用：

```c
getmemory(str);
```

只是把 `str` 当前保存的地址值复制给形参 `p`。函数内部：

```c
p = malloc(100);
```

只改变了局部变量 `p`，`main` 中的 `str` 仍然是 `NULL`，而申请到的内存地址丢失，造成内存泄漏。

正确方法之一是使用二级指针：

```c
int getmemory(char **p)
{
    *p = malloc(100);

    if (*p == NULL)
        return 0;

    strcpy(*p, "hello world");
    return 1;
}
```

调用：

```c
char *str = NULL;

if (getmemory(&str)) {
    printf("%s\n", str);
    free(str);
}
```

另外，原题中的：

```c
printf("%s/n", str);
```

换行应写成 `\n`，不是 `/n`。

## 第 11 题

### 原题

```text
11、 char szstr[10];
strcpy(szstr,"0123456789");
产生什么结果？为什么？
```

### 优化答案

会发生**数组越界写入**，属于未定义行为。

`"0123456789"` 有 10 个可见字符，还需要结尾的 `'\0'`，实际至少需要 11 字节：

```c
char szstr[11];

strcpy(szstr, "0123456789");
```

原资料说“一定出现段错误”不严谨。越界后可能崩溃，也可能暂时看起来正常，但行为没有保证。

## 第 12 题

### 原题

```text
12、数组和链表的区别？
```

### 优化答案

| 对比项 | 数组 | 链表 |
|---|---|---|
| 内存布局 | 通常连续 | 节点可以分散 |
| 随机访问 | `O(1)` | 通常 `O(n)` |
| 中间插入/删除 | 往往需要移动元素 | 已知节点位置时主要修改指针 |
| 额外空间 | 较少 | 每个节点还要保存指针 |
| 缓存友好性 | 通常较好 | 通常较差 |
| 长度变化 | 静态数组固定，动态数组可扩容 | 很容易动态增长 |

原资料“数组固定、链表随机存储”只是最简化的概括。

## 第 13 题

### 原题

```text
13、 void main()
{
char aa[10];
printf(“%d”,strlen(aa));
}
会出现什么问题？打印结果是是多少？
```

### 优化答案

`aa` 是未初始化的局部字符数组，其内容是不确定的：

```c
char aa[10];
```

`strlen(aa)` 会一直向后寻找 `'\0'`。如果数组中没有及时出现 `'\0'`，就会读出数组边界，因此属于**未定义行为**，不能说只是“打印一个未知值”。

正确示例：

```c
char aa[10] = {0};

printf("%zu", strlen(aa));   // 0
```

同时，标准 `main` 建议写成：

```c
int main(void)
```

## 第 14 题

### 原题

```text
14、给定结构struct  A
{
char t:4;
char k:4;
unsigned short i:8;
unsigned long m;
};问sizeof(A) = ?
```

### 优化答案

这道题**不能从 C 标准得到唯一固定值**。

原因包括：

- 位域的分配方式与编译器实现有关；
- `char`、`unsigned short` 作为位域基础类型本身就带有实现相关性；
- `unsigned long` 在不同平台可能为 4 或 8 字节；
- 结构体还受对齐和填充影响。

因此：

```c
sizeof(struct A)
```

应在指定编译器、ABI 和编译选项下实际验证。原资料给出的 `8` 只能理解为某个具体环境下的结果。


```text
char str   1

```

因此常见答案：

```text

```

严格来说仍取决于编译器的结构体对齐规则。

## 第 17 题

### 原题

```text
17、程序哪里有错误
wap( int* p1,int* p2 )
{
int *p;
*p = *p1;
*p1 = *p2;
*p2 = *p; }
```

### 优化答案

问题在于：

```c
int *p;
```

只是定义了一个未初始化指针。随后：

```c
*p = *p1;
```

直接解引用这个不确定地址，产生未定义行为。

这里根本不需要指针临时变量：

```c
void swap(int *p1, int *p2)
{
    int temp = *p1;
    *p1 = *p2;
    *p2 = temp;
}
```

## 第 19 题

### 原题

```text
19、 (void *)ptr 和 (*(void**))ptr的结果是否相同？其 中ptr为同一个指针。
```

### 优化答案

按原题写法：

```c
(*(void**))ptr
```

本身就不是一个规范、清晰的标准 C 表达式。

如果题目真正想比较的是：

```c
(void *)ptr
```

和：

```c
*(void **)ptr
```

那么二者**不相同**。

- `(void *)ptr`：只是把 `ptr` 的值转换成 `void *`，不访问 `ptr` 指向的内存。
- `*(void **)ptr`：先把 `ptr` 转成 `void **`，然后进行解引用，会读取 `ptr` 所指内存中的一个“指针值”。

因此原资料给出的“值相同”结论不严谨，通常是错误的。

## 第 20 题

### 原题

```text
20、要对绝对地址0x100000赋值，我们可以用
(unsigned int*)0x100000 = 1234;
那么要是想让程序跳转到绝对地址是0x100000去执行 ,应该怎么做？
```

### 优化答案

原题中这句本身就有问题：

```c
(unsigned int*)0x100000 = 1234;
```

如果要向绝对地址写值，典型嵌入式写法应是：

```c
*(volatile unsigned int *)0x100000 = 1234;
```

如果要把 `0x100000` 当成一个 `void func(void)` 函数入口并调用，可写：

```c
((void (*)(void))0x100000)();
```

也可以拆开：

```c
void (*func)(void) = (void (*)(void))0x100000;
func();
```

但要注意：整数地址转换成函数指针以及直接跳到绝对地址执行，都高度依赖具体 MCU、ABI、编译器和启动环境，不是可移植 C。

## 第 22 题

### 原题

```text
22、关于内存的思考题（1）你能看出有什么问题？
void GetMemory(char *p)
{
    p = (char *)malloc(100);
}
void Test(void)
{
    char *str = NULL;
    GetMemory(str);
    strcpy(str, "hello world");
    printf(str);
}
```

### 优化答案

问题在于 `GetMemory` 的参数 `p` 是按值传递的。

```c
p = malloc(100);
```

只改变了函数内部的局部形参 `p`，不会改变 `Test` 中的：

```c
char *str = NULL;
```

所以调用结束后 `str` 仍然是 `NULL`。随后：

```c
strcpy(str, "hello world");
```

会向空指针写数据，产生未定义行为。

同时，`malloc` 得到的地址在函数返回后丢失，还会造成内存泄漏。

正确方法：使用 `char **` 或直接返回申请到的指针。

## 第 23 题

### 原题

```text
23、关于内存的思考题（2）你能看出有什么问题？
char *GetMemory(void)
{
    char p[] = "hello world";
    return p;
}
void Test(void)
{
    char *str = NULL;
    str = GetMemory();
    printf(str);
}
请问运行 Test 函数会有什么样的结果？
```

### 优化答案

`p` 是 `GetMemory` 函数内部的局部数组：

```c
char p[] = "hello world";
```

它具有自动存储期。函数返回后，数组 `p` 的生命周期结束，因此：

```c
return p;
```

返回的是一个**悬空指针**。

随后：

```c
printf(str);
```

继续访问这块已经失效的内存，属于未定义行为。

正确做法可以是：

- 由调用者提供缓冲区；
- 使用动态内存；
- 或在确实合适的场景使用 `static` 数组。

## 第 25 题

### 原题

```text
25、关于内存的思考题（3）你能看出有什么问题？
void GetMemory2(char **p, int num)
{
    *p = (char *)malloc(num);
}
void Test(void)
{
    char *str = NULL;
    GetMemory2(&str, 100);
    strcpy(str, "hello");
    printf(str);
}
请问运行 Test 函数会有什么样的结果？
```

### 优化答案

这次使用了二级指针：

```c
GetMemory2(&str, 100);
```

函数内部：

```c
*p = malloc(num);
```

能够真正修改调用者的 `str`，所以在 `malloc` 成功的前提下，可以输出：

```text
hello
```

但原程序还存在两个问题：

1. 没有检查 `malloc` 是否成功；
2. 使用完没有 `free(str)`，因此会产生内存泄漏。

建议：

```c
if (str != NULL) {
    strcpy(str, "hello");
    printf("%s", str);
    free(str);
    str = NULL;
}
```

## 第 26 题

### 原题

```text
26、关于内存的思考题（4）你能看出有什么问题？
void Test(void)
{
    char *str = (char *)malloc(100);
    strcpy(str, "hello");
    free(str);
    if(str != NULL)
    {
        strcpy(str, "world");
        printf(str);
    }
}
请问运行 Test 函数会有什么样的结果？
```

### 优化答案

`free(str)` 之后，`str` 通常不会自动变成 `NULL`，但它已经不再指向一块有效的已分配对象，此时它是**悬空指针**。

所以：

```c
if (str != NULL)
```

不能判断这块内存是否仍然有效。

后面的：

```c
strcpy(str, "world");
```

属于释放后继续使用（use-after-free），是未定义行为。

推荐：

```c
free(str);
str = NULL;
```

## 第 27 题

### 原题

```text
27、 关键字volatile有什么含意? 并给出三个不同的例 子。
```

### 优化答案

`volatile` 表示这个对象的值可能以普通程序流程无法预测的方式发生变化，因此编译器不能把对它的访问简单缓存起来或随意消除。

典型场景：

1. **内存映射硬件寄存器**

```c
#define STATUS_REG (*(volatile unsigned int *)0x40000000)
```

2. **主程序和中断服务程序共享的简单状态标志**

```c
volatile int irq_flag;
```

3. **由硬件、DMA 或特殊执行环境异步修改的数据**

需要注意：

> `volatile` 不是线程同步工具，不保证原子性，也不能替代互斥锁或 C11 原子类型。

## 第 28 题

### 原题

```text
28、嵌入式系统经常具有要求程序员去访问某特定的  内存位置的特点。在某工程中，要求设置一绝对地址  为0x67a9的整型变量的值为0xaa66。编译器是一个纯 粹的ANSI编译器。写代码去完成这一任务。
```

### 优化答案

原题要求的是地址 `0x67a9`，值 `0xaa66`。典型嵌入式写法：

```c
*(volatile unsigned int *)0x67a9 = 0xaa66;
```

如果目标实际是 16 位寄存器，更明确的写法可能是：

```c
#include <stdint.h>

*(volatile uint16_t *)0x67a9 = 0xaa66;
```

但这里要注意两点：

- 整数地址转指针的结果依赖具体实现，并不是完全可移植的 ANSI C；
- `0x67a9` 是奇地址，某些处理器不允许 16/32 位非对齐访问。

另外，原资料答案里把 `0xaa66` 写成了 `0xaa55`，与题目要求不一致。

### 原题

很多编译器还支持：

```c
#pragma once
```

但传统、通用的写法仍是 include guard。

### 原题

```text
30、#include  <filename.h>    和 #include
“filename.h”  有什么区别？
```

### 优化答案

通常：

```c
#include <filename.h>
```

主要按照编译器配置的系统头文件搜索路径查找。

而：

```c
#include "filename.h"
```

通常会先按实现规定从当前源文件附近或用户头文件路径查找，找不到后再继续搜索其它包含路径。

更严谨地说，**具体搜索顺序由编译器实现和编译参数决定**，不能简单理解成“尖括号只搜标准库、双引号只搜当前目录”。

## 第 31 题

### 原题

```text
31、const  有什么用途？（请至少说明两种）
```

### 优化答案

`const` 的常见用途至少包括：

1. 定义只读对象：

```c
const int MAX_COUNT = 100;
```

2. 限制通过指针修改数据：

```c
void print_text(const char *str);
```

3. 区分“指针指向内容不可改”和“指针本身不可改”：

```c
const int *p;          // 不能通过 p 修改 *p
int *const p2 = &x;    // p2 自身不能改指向
const int *const p3 = &x;
```

在 C 中，`const` 是类型限定符。原资料提到“const 修饰函数定义体”更偏向 C++ 成员函数语境，不适合作为纯 C 的核心答案。

## 第 32 题

### 原题

```text
32、 static有什么用途？（请至少说明两种）
```

### 优化答案

`static` 在 C 中最常见的用途有三类。

局部变量：

```c
void f(void)
{
    static int count = 0;
}
```

它仍然只在函数内部可见，但具有静态存储期，程序运行期间一直存在，并在多次调用之间保留值。

文件作用域变量：

```c
static int g_value;
```

具有**内部链接**，只在当前翻译单元中可见。

函数：

```c
static void helper(void)
{
}
```

同样具有内部链接，只供当前 `.c` 文件使用。

### 原题


### 优化答案

通常在一个 `.c` 文件中**定义**：

```c

```

在头文件中**声明**：

```c
extern int g_count;
```

## 第 35 题

### 原题

```text
35、全局变量可不可以定义在可被多个.C文件包含的 头文件中？为什么？
```

### 优化答案

一般**不应该直接在会被多个 `.c` 文件包含的头文件中定义普通全局变量**：

```c
/* bad.h */

```

因为多个源文件包含该头文件后，通常会产生多个定义并导致链接问题。

```c
/* good.h */
```

```c
int g_value = 10;
```

如果在头文件中写：

```c
static int g_value;
```

则每个 `.c` 文件会得到自己的独立副本，它们并不是一个共享的全局变量。

```text
37、 Heap与stack的差别。
```

常见实现中的区别：

| 项目 | Stack（栈） | Heap（堆） |
|---|---|---|

## 第 50 题

### 原题

```text
50、用两个栈实现一个队列的功能？要求给出算法和 思路！
```

### 优化答案

设两个栈：

```text
stack_in
stack_out
```

入队：

```text
直接 push 到 stack_in
```

出队：

```text
如果 stack_out 非空：
    直接从 stack_out pop

如果 stack_out 为空：
    把 stack_in 的所有元素依次 pop
    再 push 到 stack_out
    然后从 stack_out pop
```

伪代码：

```c
enqueue(x):
    stack_in.push(x)

dequeue():
    if stack_out.empty():
        while !stack_in.empty():
            stack_out.push(stack_in.pop())

    if stack_out.empty():
        error

    return stack_out.pop()
```

每个元素最多在两个栈之间搬运一次，所以均摊时间复杂度为 `O(1)`。

原资料第（2）步把条件写成了“B 不为空时搬运 A”，逻辑应为 **B 为空时** 才搬运。

## 第 54 题

### 原题

```text
54、在 C++  程序中调用被 C 编译器编译后的函数， 为什么要加 extern “C”？
```

### 优化答案

C++ 支持函数重载，编译器通常会对函数名进行 **name mangling（名字修饰）**；C 不采用 C++ 这种重载和符号修饰规则。

在 C++ 中：

```cpp
extern "C" {
    void foo(int);
}
```

表示该声明采用 C 语言链接方式，使 C++ 代码能正确链接到由 C 编译器生成的函数符号。

常见跨 C/C++ 头文件：

```c
#ifdef __cplusplus
extern "C" {
#endif

void foo(int x);

#ifdef __cplusplus
}
#endif
```

具体符号是否叫 `_foo` 等是平台实现细节，不应死记。

## 第 55 题

### 原题

```text
55、请简述以下两个 for 循环的优缺点。

for (i=0; i<N; i++)
{
    if (condition)
        DoSomething();
    else
        DoOtherthing();
}

if (condition)
{
    for (i=0; i<N; i++)
        DoSomething();
}
else
{
    for (i=0; i<N; i++)
        DoOtherthing();
}
```

### 优化答案

在 `condition` **整个循环期间都不会变化**的前提下，第二种写法把判断放在循环外：

```c
if (condition) {
    for (...) ...
} else {
    for (...) ...
}
```

优点：

- 条件只判断一次；
- 循环体内部没有分支；
- 某些情况下更利于编译器优化。

缺点：

- 两段循环代码重复；
- 可维护性较差；
- 代码体积可能增大。

第一种写法更紧凑，也能在 `condition` 每次循环可能变化时保持正确。

如果 `condition` 会随循环改变，那么两段程序**根本不等价**，不能把判断移到循环外。

## 第 56 题

## 第 57 题

### 原题

```text
57、 do……while和while……do有什么区别？
```

### 优化答案

`while` 是先判断条件，再执行循环体：

```c
while (condition) {
    work();
}
```

因此循环体可能一次都不执行。

`do...while` 是先执行，再判断：

```c
do {
    work();
} while (condition);
```

因此循环体至少执行一次。

题目中的“while……do”并不是标准 C 的语法名称，C 中对应的是普通 `while` 循环。

## 第 70 题

### 原题

```text
70、找出程序的错误。
main()
{
    char *src="hello,world";
    char *dest=NULL;
    int len=strlen(src);
    dest=(char*)malloc(len);
    char *d=dest;
    char *s=src[len];
    while(len--!=0)
        d++=s--;
    printf("%s",dest);
    return 0;
}
```

### 优化答案

原程序有多处错误。

第一处：

```c
dest = (char *)malloc(len);
```

如果要保存一个长度为 `len` 的 C 字符串，还要给结尾的 `'\0'` 留空间：

```c
malloc(len + 1)
```

第二处：

```c
char *s = src[len];
```

`src[len]` 是一个 `char`，不是 `char *`。如果要从字符串最后一个字符开始：

```c
char *s = src + len - 1;
```

第三处：

```c
d++ = s--;
```

这既没有对字符解引用，而且左侧也不是可赋值的正常目标。题目意图应类似：

```c
*d++ = *s--;
```

第四处：复制完成后还必须补：

```c
*d = '\0';
```

第五处：应检查 `malloc` 是否成功，并在使用结束后 `free(dest)`。

一个正确实现：

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    const char *src = "hello,world";
    size_t len = strlen(src);

    char *dest = malloc(len + 1);
    if (dest == NULL)
        return 1;

    for (size_t i = 0; i < len; i++)
        dest[i] = src[len - 1 - i];

    dest[len] = '\0';

    printf("%s", dest);

    free(dest);
    return 0;
}
```

## 第 77 题

### 原题

```text
77、写出二分查找的代码 。
```

### 优化答案

前提：数组必须已经按升序排列。

```c
int binary_search(const int *arr, int n, int key)
{
    int low = 0;
    int high = n - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (arr[mid] < key) {
            low = mid + 1;
        } else if (arr[mid] > key) {
            high = mid - 1;
        } else {
            return mid;
        }
    }

    return -1;
}
```

使用：

```c
low + (high - low) / 2
```

比直接写 `(low + high) / 2` 更能避免整数加法溢出。

### 优化答案

可以使用 Brian Kernighan 算法：

```c
unsigned int count_bits(unsigned char x)
{
    unsigned int count = 0;

    while (x != 0) {
        x &= (unsigned char)(x - 1);
        count++;
    }

    return count;
}
```

每次：

```c
x &= x - 1;
```

都会清除最低位的一个 `1`，因此循环次数恰好等于置 1 位的数量。

```c
void int_to_string(int value, char *out)
```

```c
int my_strcmp(const char *s1, const char *s2)
```

```text
> 0 ：s1 大于 s2
```

## 第 82 题

### 原题

```text

```

### 优化答案

如果要求**原地逆序**：

```c
void reverse_string(char *str)
{
    char *left = str;
    char *right = str;

    while (*right != '\0')
        right++;

    if (right == str)
        return;

    right--;

    while (left < right) {
        char temp = *left;
        *left = *right;
        *right = temp;

        left++;
        right--;
    }
}
```

例如：

```text
hello -> olleh
```

时间复杂度 `O(n)`，额外空间 `O(1)`。

题目本质是找“连续相同字符的最长一段”。

例如：



```c
int longest_run(const char *str)
{
    if (str == NULL || *str == '\0')
        return 0;

    int max_len = 1;
    int current = 1;

    for (int i = 1; str[i] != '\0'; i++) {
        if (str[i] == str[i - 1]) {
            current++;
        } else {
            if (current > max_len)
                max_len = current;

            current = 1;
        }
    }

    if (current > max_len)
        max_len = current;

    return max_len;
}
```

时间复杂度为 `O(n)`。

## 第 85 题

### 原题

```text
85、华为面试题：怎么判断链表中是否有环？
```

### 优化答案

使用 Floyd 快慢指针。

```c
typedef struct Node {
    int data;
    struct Node *next;
} Node;

int has_cycle(Node *head)
{
    Node *slow = head;
    Node *fast = head;

    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;

        if (slow == fast)
            return 1;
    }

    return 0;
}
```

原理：

- 慢指针每次走 1 步；
- 快指针每次走 2 步；
- 如果链表有环，两者最终会在环内相遇。

复杂度：

```text
时间 O(n)
空间 O(1)
```

## 第 87 题

```text

```

### 优化答案

定义：

```c
typedef struct DuNode {
    int data;
    struct DuNode *prev;
    struct DuNode *next;
} DuNode;
```

删除节点：

```c
#include <stdlib.h>

void delete_node(DuNode **head, DuNode *p)
{
    if (head == NULL || p == NULL)
        return;

    if (p->prev != NULL)
        p->prev->next = p->next;
    else
        *head = p->next;

    if (p->next != NULL)
        p->next->prev = p->prev;

    free(p);
}
```

在 `p` 后插入节点：

```c
int insert_after(DuNode *p, int value)
{
    if (p == NULL)
        return 0;

    DuNode *node = malloc(sizeof(*node));
    if (node == NULL)
        return 0;

    node->data = value;
    node->prev = p;
    node->next = p->next;

    if (p->next != NULL)
        p->next->prev = node;

    p->next = node;
    return 1;
}
```

```c
typedef struct Node {

}
```

```text
800×?? + 9×??
```

如果原题实际想算的是：

```text
809 × 12 + 1
```

则为：

```text
9709
```

因此建议面试时指出：**条件能推出 12，但原等式本身写错了。**

## 第 100 题

### 原题

```text
100、有两个磁盘文件A和B,各存放一行字母，要求把 这两个文件中的信息合并（按字母顺序排列），输出 到一个新文件C中。
```

### 优化答案

可以把两个文件的字符读入同一个缓冲区，排序后写入文件 C。

```c
#include <stdio.h>
#include <stdlib.h>

static int cmp_char(const void *a, const void *b)
{
    unsigned char x = *(const unsigned char *)a;
    unsigned char y = *(const unsigned char *)b;

    return (x > y) - (x < y);
}

int main(void)
{
    FILE *fa = fopen("A", "r");
    FILE *fb = fopen("B", "r");

    if (fa == NULL || fb == NULL) {
        if (fa) fclose(fa);
        if (fb) fclose(fb);
        return 1;
    }

    size_t size = 0;
    size_t capacity = 128;
    char *buf = malloc(capacity);

    if (buf == NULL) {
        fclose(fa);
        fclose(fb);
        return 1;
    }

    FILE *in[2] = {fa, fb};

    for (int k = 0; k < 2; k++) {
        int ch;

        while ((ch = fgetc(in[k])) != EOF) {
            if (ch == '\n' || ch == '\r')
                continue;

            if (size == capacity) {
                capacity *= 2;
                char *tmp = realloc(buf, capacity);

                if (tmp == NULL) {
                    free(buf);
                    fclose(fa);
                    fclose(fb);
                    return 1;
                }

                buf = tmp;
            }

            buf[size++] = (char)ch;
        }
    }

    fclose(fa);
    fclose(fb);

    qsort(buf, size, sizeof(buf[0]), cmp_char);

    FILE *fc = fopen("C", "w");
    if (fc == NULL) {
        free(buf);
        return 1;
    }

    fwrite(buf, sizeof(buf[0]), size, fc);

    fclose(fc);
    free(buf);

    return 0;
}
```

实际面试中，如果已知 A、B 两个文件本身已经各自有序，还可以使用类似“归并”的方法，边读边写，避免把所有字符全部放入内存后再整体排序。

# 高频易错点速记

1. `sizeof(数组)` 和 `sizeof(指针)` 完全不同，数组形参又会调整为指针。  
2. C 字符串必须为结尾的 `\0` 预留空间。  
3. 未初始化字符数组不能直接交给 `strlen`。  
4. `malloc` 要检查返回值；申请成功后要配对 `free`。  
5. `free` 后原指针通常不会自动变成 `NULL`，但已经成为悬空指针。  
6. C 的函数参数都是值传递；需要修改调用者的指针时，常用二级指针或返回新指针。  
7. `static` 局部变量考察“静态存储期”；文件作用域 `static` 更核心的是“内部链接”。  
8. `volatile` 常用于硬件寄存器/中断共享状态，但不等于线程安全。  
9. 宏是文本替换，宏参数带 `++`、`--` 等副作用非常危险。  
10. signed/unsigned 混合运算、结构体对齐、位域布局和指针大小都要注意平台差异。  
11. 判断 2 的幂时应写 `x > 0 && (x & (x - 1)) == 0`。  
12. 链表判环常用 Floyd 快慢指针；二分查找的前提是数据已经有序。  
13. ISR 应短小，慎用浮点和 `printf` 等高开销/可能不可重入的操作。  
14. 面试资料中的“标准答案”也可能存在错误，遇到实现相关或未定义行为时要明确说明。
