## 第一章：时钟、存储器映射与 GPIO

本章对应《6_GPIO输入输出》28 页。先认时钟和端口，再选引脚模式，最后用原理图判断 LED、按键的有效电平；配置与操作都要对应实际接线。

### 1.1 时钟为什么重要（第 1～4 页）

时钟给 CPU 和外设提供工作节拍。配置外设时要分清两件事：

- **时钟频率**：这个模块每秒得到多少个时钟周期。
- **外设时钟使能**：是否允许这个模块使用相应的时钟。

课件第 3 页采用的是下面这一组配置，不是芯片上电后必然处于的状态：

```text
外部晶振 HSE 8 MHz → PLL 倍频 9 倍 → SYSCLK 72 MHz
                                       ↓ AHB 不分频
                                    HCLK 72 MHz
                         ┌─────────────┴──────────────┐
                     APB1 除以 2                  APB2 不分频
                     PCLK1 36 MHz                 PCLK2 72 MHz
```

| 名称 | 在本组配置中的频率 | 用途或例子 |
| --- | --- | --- |
| SYSCLK | 72 MHz | 系统时钟选择后的输出 |
| HCLK | 72 MHz | CPU、AHB、存储器、DMA 等使用 |
| PCLK1 | 36 MHz | USART2/3、UART4/5、SPI2/3、TIM2～5 等所在总线 |
| PCLK2 | 72 MHz | GPIOA～G、AFIO、USART1、SPI1、TIM1/TIM8 等所在总线 |
| ADC 时钟 | 12 MHz | 本例由 PCLK2 除以 6 得到 |

**核对提醒：**第 3 页“Cortex 系统时钟为 SYSCLK 八分频、9 MHz”不能理解成 CPU 只运行在 9 MHz。原时钟树中的 HCLK/8 分支可供 SysTick 使用；本例 CPU 使用 HCLK=72 MHz。SysTick 还可以选择 HCLK，因此它也不一定使用 9 MHz。

**理解补充：**第 3 页图中 APB 定时器旁还有一个倍频条件：APB 预分频为 1 时，定时器时钟等于对应 PCLK；预分频不为 1 时，定时器时钟等于 2×PCLK。因此 PCLK1=36 MHz，不代表 TIM2 也只能获得 36 MHz。

先记住：STM32F103ZE **最高支持 72 MHz**，当前频率要看实际初始化；打开 GPIOB 时钟，不等于把系统配置成 72 MHz。

### 1.2 存储器映射：为什么写地址可以控制外设（第 5～7 页）

存储器映射就是把 Flash、SRAM 和外设寄存器放进统一的地址空间。CPU 对某个外设地址执行读写，硬件就会完成相应操作。

32 位地址共有 2³² 个字节地址，也就是 4 GiB 地址空间。**地址空间很大，不代表芯片真的装了 4 GiB 存储器。**

| 地址范围 | 课件图中的主要区域 | 初学时怎样理解 |
| --- | --- | --- |
| `0x00000000～0x1FFFFFFF` | Code 区 | 包含片内 Flash、系统存储器及启动别名等；不是整块都是真实 Flash |
| `0x20000000～0x3FFFFFFF` | SRAM 区 | 包含实际片内 SRAM 及相关地址区域 |
| `0x40000000～0x5FFFFFFF` | 片上外设区 | GPIO、RCC、串口、定时器等寄存器在这里 |
| `0x60000000～0x9FFFFFFF` | 外部存储器窗口 | 配合 FSMC 访问外接存储器；不是自动增加了 1 GiB RAM |
| `0xA0000000～0xBFFFFFFF` | 包含 FSMC 控制寄存器窗口的区域 | 只有已实现的地址有效，并非整段都是寄存器 |
| `0xC0000000～0xDFFFFFFF` | 本课件芯片映射中未使用 | 不能当作空闲 RAM 任意读写 |
| `0xE0000000～0xFFFFFFFF` | 内核和系统区域 | 包含 NVIC、SCB、SysTick 等；并非每个地址都有寄存器 |

STM32F103ZE 实际的片内 Flash 为 512 KiB，SRAM 为 64 KiB。常用起始地址分别是 `0x08000000` 和 `0x20000000`。

**核对提醒：**第 7 页说上电后先把 Flash 中的代码放进 SRAM，再从 SRAM 运行，这不是普通 STM32 工程的默认过程。通常程序直接从 Flash 取指执行；启动代码会把有初值的可写数据复制到 RAM，并清零相应数据区。只有专门配置的 RAM 函数或 RAM 启动程序，才把相应代码放在 RAM 执行。

第 7 页启动表可以这样读：

| BOOT0 | BOOT1 | 启动选择 |
| --- | --- | --- |
| 0 | 任意 | 主 Flash；普通用户程序通常采用这一方式 |
| 1 | 0 | 系统存储器；芯片厂商提供的 Bootloader |
| 1 | 1 | SRAM |

这里的“启动选择”与地址映射别名有关，不表示物理 Flash 的基地址被用户随意改写。BOOT 接线还应核对实际开发板。

**理解补充：**头文件已经把常用地址封装成名字。例如 `GPIOB` 表示 GPIOB 外设，`GPIO_Pin_5` 表示选择第 5 个引脚的掩码。标准库函数继续封装这些寄存器操作，所以学习地址映射不等于必须放弃标准库。

### 1.3 GPIO 是什么（第 8～11 页）

GPIO 是通用输入输出。`PB5` 表示 **GPIOB 端口的第 5 个引脚**。每个端口的编号范围是 0～15，具体哪些引脚引出到封装上，还要看芯片型号和封装。

- 输入：读取外部信号，例如按键是否按下。
- 输出：控制外部电路，例如 LED。
- 复用：引脚交给串口、定时器、I²C 等外设使用。

第 11 页内部结构图，先沿三条路径理解：

1. **数字输入路径**：引脚 → 输入电路 → 输入数据寄存器 IDR。
2. **普通输出路径**：软件写输出数据 → 输出驱动电路 → 引脚。
3. **复用输出路径**：片内外设产生信号 → 输出驱动电路 → 引脚。

同一个引脚采用哪条路径，由模式配置决定。图里的保护二极管是保护结构，不代表引脚可以随意接入超过允许范围的电压。

### 1.4 GPIO 的八种工作模式（第 10～19 页）

下表使用标准外设库中可以直接写进代码的真实名称；课件中部分名称是简写。

| 类别 | 标准库模式 | 核心含义 | 常见用途 |
| --- | --- | --- | --- |
| 浮空输入 | `GPIO_Mode_IN_FLOATING` | 不启用内部上拉或下拉，电平由外部决定 | 有明确外部驱动的数字输入 |
| 上拉输入 | `GPIO_Mode_IPU` | 没有外部驱动时，弱上拉使引脚倾向高电平 | 按下接地的按键 |
| 下拉输入 | `GPIO_Mode_IPD` | 没有外部驱动时，弱下拉使引脚倾向低电平 | 按下接 3.3 V 的按键 |
| 模拟输入 | `GPIO_Mode_AIN` | 关闭数字输入路径，供模拟功能使用 | ADC 输入 |
| 普通推挽输出 | `GPIO_Mode_Out_PP` | 软件控制，主动输出高、低电平 | LED、普通数字控制 |
| 普通开漏输出 | `GPIO_Mode_Out_OD` | 软件控制，可拉低或释放；通常需要上拉 | 需要开漏特性的信号 |
| 复用推挽输出 | `GPIO_Mode_AF_PP` | 由外设控制高低电平 | USART TX、定时器 PWM 等 |
| 复用开漏输出 | `GPIO_Mode_AF_OD` | 外设控制拉低或释放 | I²C 等开漏总线 |

#### 输入模式怎样看图（第 12～15 页）

- **浮空输入**：内部不替你确定默认高低。若外部也没有明确驱动，读数可能不稳定；“浮空”不等于固定为 0。
- **上拉输入**：内部弱电阻接向 VDD。外部按键仍可以把引脚拉到 GND，所以“上拉”不等于永远为 1。
- **下拉输入**：内部弱电阻接向 GND。外部按键接通 3.3 V 时仍能读到 1。
- **模拟输入**：模拟信号走模拟通路，不能把普通 GPIO 高低电平读取当作 ADC 数值。

#### 输出模式怎样看图（第 16～19 页）

推挽输出中，上、下两个驱动管配合工作：输出高时上方 P-MOS 导通，输出低时下方 N-MOS 导通。它能够主动驱动两个电平。

开漏输出只使用拉低的驱动路径：

```text
写 0：下方驱动管导通 → 引脚被拉低
写 1：下方驱动管关闭 → 引脚被释放，成为高阻状态
```

**“开漏写 1”不是主动输出高电平。**有合适的上拉时才会被拉高。普通输出与复用输出的区别主要是信号来自软件，还是来自片内外设；“复用”本身不等于推挽。

**理解补充：**F1 的上下拉输入使用同一种硬件输入配置，再由 ODR 对应位选择：1 为上拉，0 为下拉。用 `GPIO_Mode_IPU/IPD` 时，标准库替你完成这个选择。

### 1.5 GPIO 初始化与读写步骤（第 23～24 页）

课件的库开发流程可以固定记成：**准备配置变量 → 开时钟 → 填参数 → 调初始化函数 → 读写引脚。**

| 步骤 | 代码或成员 | 这一行解决什么问题 |
| --- | --- | --- |
| 准备配置变量 | `GPIO_InitTypeDef GPIO_InitStructure;` | 用一个变量保存本次配置；没有重新定义库里的结构体类型 |
| 开端口时钟 | `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);` | 允许 GPIOB 外设工作 |
| 选引脚 | `GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5;` | 本次选择 5 号引脚，端口由 GPIO_Init 第一个参数决定 |
| 选模式 | `GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;` | 本例采用推挽输出 |
| 选输出速度等级 | `GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;` | 输出电路的速度等级，输入模式下不靠它控制采样速度 |
| 应用参数 | `GPIO_Init(GPIOB, &GPIO_InitStructure);` | 库函数真正修改硬件配置 |
| 输出或读取 | `GPIO_ResetBits(GPIOB, GPIO_Pin_5);`、`GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0);` | 控制输出或观察输入；读 PA0 前也要配置 GPIOA |

`GPIO_Speed_50MHz` **不会自动输出 50 MHz 方波**。这里只是输出速度等级；LED 示例通常用 `GPIO_Speed_2MHz` 即可。

**理解补充：**`GPIO_InitStructure.GPIO_Mode = ...` 只是给普通内存里的配置成员赋值；没有 `GPIO_Init()`，参数不会自动送入外设。局部配置变量放在函数开头，各声明一次，适合常见 ARMCC5/C90 工程。


读库函数时，可以对应到下面这些硬件寄存器：

| 寄存器 | 主要用途 | 不要混淆 |
| --- | --- | --- |
| CRL / CRH | 配置 0～7 / 8～15 号引脚的模式 | 修改配置变量后仍需调用 GPIO_Init |
| IDR | 读取引脚实际输入电平 | 读取按键应看输入，不是输出锁存值 |
| ODR | 保存输出锁存值；上下拉输入时还参与选择上拉/下拉 | 读取 ODR 不等于测量引脚真实电压 |
| BSRR / BRR | 按位设置高/低输出锁存值 | 用命令位设置目标引脚，避免普通 ODR 读改写的竞争 |

### 1.7 按键接线与读取（第 25～26 页）

第 25 页图中有四个按键：

| 按键 | 引脚 | 按下时接到哪里 | 推荐输入模式 | 松开 / 按下 |
| --- | --- | --- | --- | --- |
| WK_UP / KEY_UP | PA0 | 3.3 V | 下拉输入 | 0 / 1 |
| KEY0 | PE4 | GND | 上拉输入 | 1 / 0 |
| KEY1 | PE3 | GND | 上拉输入 | 1 / 0 |
| KEY2 | PE2 | GND | 上拉输入 | 1 / 0 |

下拉或上拉保证按键断开时有确定电平；闭合后由接线决定有效电平。不能一概说“读到 1 就是按下”。

课件提到的 `KEY_Init()`、`KEY_Scan()` 是应用层自己编写的函数，不是标准库固定提供的接口：前者初始化引脚，后者读取按键并返回自己约定的结果。机械按键还存在抖动，简单电平读取不能自动完成消抖。

#### 可独立使用的标准库示例：按住 PA0 点亮 PB5

按前面的原理图接线；本例按住亮、松开灭，**不包含按一次翻转、长短按或消抖**。工程应已包含标准库 GPIO/RCC 源文件、系统文件及 STM32F103ZE 对应的高容量启动文件。它与其他章节的 `main()` 示例不能同时放进一个工程编译。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_gpio.h"

static void LED_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
    GPIO_SetBits(GPIOB, GPIO_Pin_5);  /* 先准备默认灭灯电平 */

    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);
}

static void KEY_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPD;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
}

static uint8_t KEY_Scan(void)
{
    return (uint8_t)GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0);
}

int main(void)
{
    LED_Init();
    KEY_Init();

    while (1)
    {
        if (KEY_Scan() != 0U)
        {
            GPIO_ResetBits(GPIOB, GPIO_Pin_5);  /* 按下：亮 */
        }
        else
        {
            GPIO_SetBits(GPIOB, GPIO_Pin_5);    /* 松开：灭 */
        }
    }
}
```

这里的 `KEY_Scan()` 返回当前电平，所以按住期间会持续返回 1，不能把它误认为只报告一次“新按下事件”。

### 1.8 时钟周期与简单延时的提醒（第 20、22 页）

频率 f 与周期 T 的关系是 `T=1/f`。例如 CPU 使用 72 MHz 时，一个 CPU 时钟周期约为 13.89 ns。

**核对提醒：**课件穿插了传统 51 单片机“一个机器周期等于 12 个时钟周期”的说明，这不能套到 Cortex-M3。STM32 不同指令和不同访存情况的耗时也不全相同。

课件通过 `__NOP()` 介绍空操作，但循环延时还包含计数、分支、编译优化和中断等影响；不能只数几条 `__NOP()` 就保证精确的毫秒或微秒。需要稳定延时时，使用后续课件中的 SysTick 或定时器，并先确认实际时钟。

### 1.9 JTAG、SWD 与下载器接线（第 27～28 页）

## 第二章：SysTick 滴答定时器

本章对应《7_滴答定时器》11 页。先分清计数时钟、计数周期和中断请求，再选择“持续 1 ms 时基”或“独立轮询延时”；两种示例分别使用。

### 2.1 SysTick 在哪里，能做什么

**课件知识点｜P2～P3**

SysTick 是 Cortex-M3 内核中的系统定时器。STM32F103ZE 的 SysTick 是一个 **24 位向下计数器**，常用于简单延时、周期软件时基，也可由实时操作系统用作系统节拍。它与 TIM2 这类片上通用定时器是不同的硬件资源。

把它想成一个不断倒数的计数器：装入一个重装载值，随着输入时钟递减；从 1 变成 0 时产生到零事件，随后重新装载，继续下一轮。是否计数、是否提出异常请求是两件独立的事。

SysTick 异常入口是 `SysTick_Handler()`。它属于内核异常，优先级可配置，但不通过普通外设的 NVIC ISER 位使能；`CTRL.TICKINT` 才是到零异常请求的开关。

**核对纠错｜P3 的“即使在睡眠模式下也能工作”有条件。**不能把普通 Sleep 推广成 Stop、Standby 等所有低功耗模式。计数依赖所选输入时钟是否继续运行；当相关时钟停止时，SysTick 也停止。调试暂停还会改变实时观察结果，因此不要把断点前后的计数当成真实墙上时间。[ST PM0056，SysTick 设计提示](https://www.st.com/resource/en/programming_manual/cd00228163.pdf)


| 程序中的名字 | 来源与作用 |
| --- | --- |
| SystemCoreClock | 系统文件维护的 HCLK 频率变量，单位 Hz |
| SystemCoreClockUpdate() | 根据当前时钟寄存器更新上述变量，不切换时钟源 |
| SysTick_Config(ticks) | CMSIS 提供的配置函数；本章采用 HCLK 时钟，设置周期并开启请求 |
| SysTick_Handler(void) | 中断向量要求的入口名称，由程序提供实现、CPU 自动进入 |
| Tick_ms | 示例自己定义的软件变量，只有入口中每 1 ms 加一次时才表示毫秒数 |

### 2.2 先认四个寄存器

**课件知识点：P4～P7。**

SysTick 基地址为 `0xE000E010`。课件把重装载寄存器叫作 RELOAD；CMSIS 结构体中实际使用 `SysTick->LOAD`，其中的有效字段名为 RELOAD。

| 寄存器 | 偏移 | 先记住的作用 |
| --- | --- | --- |
| `CTRL` | `0x00` | 选择时钟，开启计数和异常请求，查询到零标志 |
| `LOAD` | `0x04` | 低 24 位保存周期重装载值 |
| `VAL` | `0x08` | 读取当前计数值；写任意值会清当前值与 COUNTFLAG |
| `CALIB` | `0x0C` | 校准信息；入门时按实际输入时钟计算即可 |

`CTRL` 的常用位如下。

| 位 | 名称 | 在 STM32F103ZE 上的含义 |
| --- | --- | --- |
| bit 0 | ENABLE | 1：计数器工作；0：停止计数 |
| bit 1 | TICKINT | 1：从 1 数到 0 时提出 SysTick 异常请求 |
| bit 2 | CLKSOURCE | 1：HCLK；0：HCLK/8 |
| bit 16 | COUNTFLAG | 自上次清除以来，是否至少发生过一次到零 |

在这里，“外部时钟源”是相对内核计时源的说法，STM32F103 接入的是 **HCLK/8**，不是让使用者另接一个外部引脚。若已确认 HCLK=72 MHz，则两种选择分别是 72 MHz 和 9 MHz；72 MHz 不是芯片上电后无条件成立的事实。

### 2.3 LOAD 为什么通常要减一

**课件知识点｜P3、P7、P10；核对补充周期公式。**

对于正常的连续周期计数：

```text
ticks = 目标周期 × SysTick 输入时钟频率
LOAD  = ticks - 1
周期  = (LOAD + 1) / SysTick 输入时钟频率
```

`ticks` 是一轮需要的时钟周期数，`LOAD` 是写进寄存器的数，不能把两者混为一谈。

| HCLK | SysTick 输入时钟 | 目标周期 | ticks | LOAD |
| --- | --- | --- | --- | --- |
| 72 MHz | HCLK，72 MHz | 1 ms | 72000 | 71999 |
| 72 MHz | HCLK/8，9 MHz | 1 ms | 9000 | 8999 |
| 72 MHz | HCLK/8，9 MHz | 1 μs | 9 | 8 |

硬件 LOAD 的最大值是 `0xFFFFFF`，连续周期最多包含 `2^24 = 16777216` 个时钟周期。因此在 72 MHz 输入下，一次最长约 233.017 ms；在 9 MHz 输入下，约 1.864 s。需要更长时间时，可累计短周期，不能把超范围的数硬塞进 LOAD。

**核对补充：**LOAD=0 不适合作为正常的到零触发配置，因为到零事件依赖从 1 到 0 的变化。入门示例避开这一边界，令 ticks 至少为 2。上面的公式讲连续周期；短忙等的实际耗时还会包含配置、循环和中断处理的时间，不应宣称具有零误差。

### 2.4 读 CTRL、写 VAL 都有副作用

**课件知识点｜P5 的 CTRL 图、P6 的 VAL 图。**

- 读 `CTRL` 会清 COUNTFLAG。`SysTick->CTRL |= ...`、`&= ...` 也会先读寄存器，因此同样包含清标志的读取。
- 写 `VAL` 的任意数值，都会清当前计数值和 COUNTFLAG。`SysTick->VAL = 123U` 的效果不是“把当前值设成 123”。

COUNTFLAG 是一个“发生过”的标志，不是事件次数。若轮询两次之间到零 10 次，读到的仍只是 1。调试器持续读取 CTRL 也可能抢先清掉这个标志。

COUNTFLAG 与“SysTick 异常是否挂起”不是同一状态，不能认为读 CTRL 就等同于清除内核里的挂起异常。初始化和运行期间，应由一套代码负责 SysTick，避免轮询延时、系统节拍和 RTOS 同时争用它。

### 2.5 两个函数，职责不同

**课件知识点｜P8～P10；与工程内 `misc.c`、`misc.h`、`core_cm3.h` 源码核对。**

| 函数 | 来源 | 会做什么 | 不会自动做什么 |
| --- | --- | --- | --- |
| `SysTick_CLKSourceConfig(...)` | SPL，`misc.c` | 改 CTRL 的 CLKSOURCE 位 | 不计算 LOAD，不重新计算延时系数 |
| `SysTick_Config(ticks)` | CMSIS，`core_cm3.h` | 设置 LOAD、清 VAL、设置 SysTick 优先级，选择 HCLK 并开启计数与异常请求 | 不替你改硬件时钟树 |

课件 P10 的标题仍写 `SysTick_CLKSourceConfig`，但页内代码实际是 **`SysTick_Config()`**。其中“Cortex-M0”英文注释是这份旧 CMSIS 源码里的注释，不表示 STM32F103 的内核变成了 M0。

`SysTick_Config()` 的参数传 ticks，调用前不要再减一：

```c
/* 已完成硬件时钟配置后，再更新这个软件频率变量。 */
SystemCoreClockUpdate();

/* 假如 SystemCoreClock=72000000，则函数内部写 LOAD=71999。 */
if (SysTick_Config(SystemCoreClock / 1000U) != 0U)
{
    /* 进入工程自己的错误处理。 */
}
```

**核对补充：调用顺序会改变最终时钟。**

```c
SysTick_CLKSourceConfig(SysTick_CLKSource_HCLK_Div8);
SysTick_Config(9000U); /* 又把 CLKSOURCE 设为 HCLK。 */
```

假设 HCLK=72 MHz，这两句结束后的周期约为 125 μs，而不是 1 ms，因为最终源是 72 MHz。反过来，若在 Config 后选 HCLK/8，9000 个周期才对应 1 ms；若仍传 72000，就会变成 8 ms。

若要求初次周期也从干净状态开始，不要依赖先启动再切换产生的短暂状态；可以停表后直接完成 CTRL、LOAD、VAL 的最终配置。对于第一份 1 ms 中断练习，直接保持 `SysTick_Config(SystemCoreClock/1000U)` 使用的 HCLK，最容易核对。

**旧版本边界｜对应 P10 的真实代码。**课件及本地旧 CMSIS 使用 `if (ticks > 0xFFFFFF) return 1;`，随后执行减一：这会漏掉 ticks=0，并拒绝 `0x1000000`。因此“函数返回成功”不等于零参数正确，也不要把新版 CMSIS 的边界检查直接套过来。正常毫秒参数不受此边界差异影响。[Arm CMSIS 接口说明](https://arm-software.github.io/CMSIS_5/Core/html/group__SysTick__gr.html)

### 2.6 用法 A：持续的 1 ms 中断时基

**对应课件 P11 的第一项应用；以下是补充的完整核心代码。**

```c
#include "stm32f10x.h"

volatile uint32_t Tick_ms = 0U;

uint32_t Tick_Init_1ms(void)
{
    uint32_t ticks;

    SystemCoreClockUpdate();
    ticks = SystemCoreClock / 1000U;

    /* 同时避开课件旧 CMSIS 的零参数问题。 */
    if ((ticks < 2U) || (ticks > 0xFFFFFFU))
    {
        return 1U;
    }

    return SysTick_Config(ticks);
}

void SysTick_Handler(void)
{
    Tick_ms++;
}

void DelayMs_Tick(uint32_t ms)
{
    uint32_t start;

    start = Tick_ms;
    while ((uint32_t)(Tick_ms - start) < ms)
    {
        /* 等待中断更新软件时间；SysTick 仍持续运行。 */
    }
}
```

`Tick_ms` 是软件变量，只有中断函数里的 `++` 才会增加它。`volatile` 告诉编译器，每次读取都要考虑它可能被中断修改；它不等于给任意复合操作加锁。

主函数应检查初始化返回值。全工程只保留一个 `SysTick_Handler()` 定义；若 `stm32f10x_it.c` 中已有同名函数，把计时逻辑放进原定义，避免重复定义。

`DelayMs_Tick()` 是阻塞延时：等待期间 CPU 在循环里转，但允许的中断仍可执行。如果在中断中调用，而 SysTick 又不能抢占该中断，`Tick_ms` 就不会前进，等待可能永久无法结束。初学时仅在主循环使用它。

无符号差值写法可以处理一次正常的计数回绕；前提是等待与检查间隔没有跨越完整的 32 位计数周期。不要改成简单比较 `Tick_ms >= start + ms`，那样在加法回绕附近容易判断错。

### 2.7 时间片：一次时基照顾多个任务

**对应课件 P11 的 LED、按键、串口检查。**

LED 每 500 ms 变化一次，不代表每轮都要阻塞 500 ms。主循环可记录各项任务上次执行的时刻：

```c
/* 逻辑示意：LED_Toggle、Key_Scan、UART_Poll 是各自模块提供的函数。 */
now = Tick_ms;

if ((uint32_t)(now - led_time) >= 500U)
{
    led_time = now;
    LED_Toggle();
}

if ((uint32_t)(now - key_time) >= 10U)
{
    key_time = now;
    Key_Scan();
}

UART_Poll();
```

这是单线程主循环按时检查条件，并没有自动变成操作系统的多任务调度。各个处理函数仍应短小；如果某个函数忙等很久，其他主循环任务也会被拖住。串口中断可以先把接收数据放入缓冲区，再由主循环处理。

### 2.8 用法 B：HCLK/8 的短忙等延时

**对应课件 P11 第二项；这是与用法 A 二选一的独占示例。**

若 HCLK 已确认是 72 MHz，则 HCLK/8=9 MHz，每微秒 9 个计数时钟。若旧代码把 `fac_us` 当“每微秒计数数”，此时应为 9；改成 HCLK 后就应为 72。只改 CLKSOURCE、不改 LOAD 计算或延时系数，结果会差 8 倍。

下面每次最多等 1000 μs，避免较大参数乘法溢出和超过 24 位 LOAD。它只用于 **没有使用 1 ms SysTick 时基、HAL 系统节拍或 RTOS 的裸机练习**。

```c
#include "stm32f10x.h"

void DelayUs_Polling_72MHz(uint32_t us)
{
    uint32_t piece;

    while (us != 0U)
    {
        piece = (us > 1000U) ? 1000U : us;

        SysTick->CTRL = 0U;
        SysTick->LOAD = piece * 9U - 1U;
        SysTick->VAL = 0U;
        /* CLKSOURCE=0：HCLK/8；TICKINT=0：只轮询。 */
        SysTick->CTRL = SysTick_CTRL_ENABLE_Msk;

        while ((SysTick->CTRL & SysTick_CTRL_COUNTFLAG_Msk) == 0U)
        {
        }

        SysTick->CTRL = 0U;
        SysTick->VAL = 0U;
        us -= piece;
    }
}

void DelayMs_Polling_72MHz(uint32_t ms)
{
    while (ms != 0U)
    {
        DelayUs_Polling_72MHz(1000U);
        ms--;
    }
}
```

这里保留“设定数值 → 清当前值 → 开始 → 等 COUNTFLAG → 停止”的学习流程。它会反复覆盖 SysTick 配置；不能和前面的 Tick_ms 方案拼在一起使用。若时钟不再是 72 MHz，常数 9 就不成立。中断插入、函数和寄存器访问开销也会增加实际耗时，微秒精度需要用示波器或逻辑分析仪验证；需要稳定短脉冲时可进一步学习通用定时器。

## 第三章：NVIC 与外部中断

本章按《8_STM32-中断、外部中断》整理，以 STM32F103ZE、标准外设库为例。先理解 CPU 怎样转去处理中断，再把 GPIO、AFIO、EXTI、NVIC 串成完整路径。

### 3.1 中断怎样改变程序执行流程（第 1～2 页）

```text
主程序正在执行
    → 硬件提出中断请求
    → 满足响应条件时，CPU 保存必要现场
    → 执行相应的中断服务函数
    → 中断返回，恢复原程序
```

课件的“暂停游戏去接电话”是在帮助理解执行流程。中断也可以处理普通的周期计时、串口收发等通知，不只是严重错误或紧急事故。

要分清两个容易混用的“外部”：

| 名称 | 指什么 | 例子 |
| --- | --- | --- |
| 内核异常 | Cortex-M3 内核提供的异常 | SysTick、HardFault、PendSV 等 |
| NVIC 的外部 IRQ | 相对 CPU 内核而言的外设中断 | USART1、TIM2、EXTI0 等；不一定来自芯片引脚 |
| GPIO 外部中断 EXTI | 通过引脚电平边沿提出的请求 | PA0 按键触发 EXTI0 |

**核对提醒：**第 2 页把内核能力、STM32 产品系列及具体型号的中断数量放在一起讲。对本章 F103ZE，应认对应高容量启动文件及头文件中的 IRQ 表：外部 IRQ 编号为 0～59，共 60 个通道。不要把其他 STM32 型号的 68 个通道直接套过来；也不要把内核向量区域的 16 个位置都当成 16 个可用普通中断，其中还包含初始栈指针和保留项。

### 3.2 NVIC 负责什么（第 2～7 页）

NVIC 是嵌套向量中断控制器，主要管理中断通道的使能、挂起状态和优先级。外设是否真的提出请求，还由对应外设自己的配置决定。

**打开 NVIC 通道，不等于外设一定会产生中断。**例如 EXTI0 还要有正确引脚映射、触发边沿和中断允许。

NVIC 是内核外设，不需要像 GPIO 那样通过 RCC 另开一个 NVIC 时钟开关。全局中断屏蔽、当前正在执行的更高优先级中断等，仍然会影响 CPU 何时响应。

### 3.3 抢占优先级、子优先级和分组（第 3～7 页）

#### 先记住两条规则

- **优先级数值越小，优先级越高。**
- 抢占优先级决定能否打断当前中断；子优先级主要决定多个同抢占级请求都在等待时，先处理哪个。

STM32F103 实现 4 个有效优先级位，放在每个优先级字节的高 4 位。第 4 页的“只实现 3 位”是说明裁剪原理的例子，不是说本芯片只有 3 位。

第 3、5、6 页的表可以整理为：

| 标准库分组 | 抢占优先级位数 / 可取值 | 子优先级位数 / 可取值 | AIRCR.PRIGROUP 编码 |
| --- | --- | --- | --- |
| `NVIC_PriorityGroup_0` | 0 位 / 只能取 0 | 4 位 / 0～15 | 7 |
| `NVIC_PriorityGroup_1` | 1 位 / 0～1 | 3 位 / 0～7 | 6 |
| `NVIC_PriorityGroup_2` | 2 位 / 0～3 | 2 位 / 0～3 | 5 |
| `NVIC_PriorityGroup_3` | 3 位 / 0～7 | 1 位 / 0～1 | 4 |
| `NVIC_PriorityGroup_4` | 4 位 / 0～15 | 0 位 / 只能取 0 | 3 |

标准库的“Group 2”和原始 PRIGROUP 编码 2 不是一回事；不要把标准库分组宏直接混入 CMSIS 的原始编码参数。

以 Group2 为例：

| 中断 | 抢占优先级 | 子优先级 |
| --- | --- | --- |
| A | 1 | 3 |
| B | 2 | 0 |
| C | 1 | 0 |

- A 可以抢占正在执行的 B，因为 1 比 2 高。
- C 不能仅凭子优先级 0 就打断正在执行的 A；它们的抢占优先级相同。
- 如果 A、C 同时等待响应，先处理 C。

**核对提醒：**第 7 页“分组函数只能调用一次”应理解为工程约定：通常在系统初始化时统一设置一次，避免不同模块互相改掉规则。硬件并不是禁止第二次调用；改变分组会改变已有优先级值的解释，所以不应随意修改。

第 3 页把中断地址说成“不允许修改”也过于绝对：芯片规定向量项和中断号的对应关系，启动文件与链接结果提供具体处理函数地址；向量表还可以按规则通过 VTOR 重定位。初学者应使用启动文件规定的函数名，不能随意给处理函数换名。

### 3.4 EXTI 线怎样对应 GPIO（第 8～11 页）

STM32F103ZE 的 EXTI 有 19 条中断/事件线：

| EXTI 线 | 来源 |
| --- | --- |
| 0～15 | GPIO 引脚输入 |
| 16 | PVD 输出 |
| 17 | RTC 闹钟 |
| 18 | USB 唤醒 |

同编号的 GPIO 引脚竞争同一条线，端口由 AFIO 选择：

![中断课件第 10 页：同编号引脚到 EXTI 的选择](C:/Users/27686/Desktop/嵌入式/笔记/32/课件6至10_配图/EXTI_GPIO映射.png)

所以 PA0 和 PB0 **不能同时**接入 EXTI0；PA0 接 EXTI0、PB1 接 EXTI1 则可以。选择关系在 `AFIO->EXTICR[]` 中设置，标准库使用：

```c
GPIO_EXTILineConfig(GPIO_PortSourceGPIOA, GPIO_PinSource0);
```

这一行只选择信号来源，不负责配置 GPIO 的输入模式，也不负责开启 EXTI 或 NVIC。GPIO、AFIO 需要按用途开启 RCC 时钟，NVIC 不需要 RCC 时钟使能。

边沿必须结合电路判断：

| 按键接法 | 按下的变化 | 按下触发应选 |
| --- | --- | --- |
| 课件 GPIO 图中的 PA0，下拉，按下接 3.3 V | 0 → 1 | 上升沿 `EXTI_Trigger_Rising` |
| PE2，上拉，按下接 GND | 1 → 0 | 下降沿 `EXTI_Trigger_Falling` |

双边沿 `EXTI_Trigger_Rising_Falling` 会检测两个方向的变化；软件仍要结合电平与接线分辨按下、松开。第 15 页的 PE2 下降沿示例与上拉按键接地的接法一致。

### 3.5 16 条 GPIO 线为什么只有 7 个入口（第 12～13 页）

| EXTI 线 | 标准库 IRQ 名 | F103ZE 的外部 IRQ 号 | 中断函数名 |
| --- | --- | --- | --- |
| EXTI0 | `EXTI0_IRQn` | 6 | `EXTI0_IRQHandler` |
| EXTI1 | `EXTI1_IRQn` | 7 | `EXTI1_IRQHandler` |
| EXTI2 | `EXTI2_IRQn` | 8 | `EXTI2_IRQHandler` |
| EXTI3 | `EXTI3_IRQn` | 9 | `EXTI3_IRQHandler` |
| EXTI4 | `EXTI4_IRQn` | 10 | `EXTI4_IRQHandler` |
| EXTI5～9 | `EXTI9_5_IRQn` | 23 | `EXTI9_5_IRQHandler` |
| EXTI10～15 | `EXTI15_10_IRQn` | 40 | `EXTI15_10_IRQHandler` |

例如 EXTI5 和 EXTI8 都会进入 `EXTI9_5_IRQHandler()`，函数内部检查各条线自己的挂起标志，再处理相应来源。

**理解补充：**“只有 7 个入口”不等于同时只能使用 7 根 GPIO 中断线。不同线可以共用入口，靠各自的 PR 标志区分。IRQ 号也不是用户配置的优先级数值；`EXTI0_IRQn=6` 不等于优先级为 6。

课件向量表中的 `0x00000058` 一类数值是向量表项相对表基址的位置，不要当成实际中断函数机器码的固定地址。

### 3.6 初始化的每一步在做什么（第 7、14～16 页）

以“PA0 下拉输入、按下接 3.3 V、上升沿中断”为例：

| 步骤 | 典型调用 | 作用 |
| --- | --- | --- |
| 1. 统一优先级分组 | `NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);` | 规定抢占与子优先级各占 2 位 |
| 2. 开 GPIOA、AFIO 时钟 | `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA \| RCC_APB2Periph_AFIO, ENABLE);` | GPIO 用于输入；AFIO 用于选择 EXTI 来源 |
| 3. 填好 PA0 下拉参数后应用 | `GPIO_Init(GPIOA, &GPIO_InitStructure);` | 松开时得到稳定低电平 |
| 4. PA0 映射到 EXTI0 | `GPIO_EXTILineConfig(GPIO_PortSourceGPIOA, GPIO_PinSource0);` | 让 EXTI0 观察 PA0 |
| 5. 填好中断模式和上升沿后应用 | `EXTI_Init(&EXTI_InitStructure);` | 配置 EXTI0 并允许该线请求 |
| 6. 清旧标志 | `EXTI_ClearITPendingBit(EXTI_Line0);`、`NVIC_ClearPendingIRQ(EXTI0_IRQn);` | 分别清外设来源与 NVIC 挂起 |
| 7. 填好通道、优先级后应用 | `NVIC_Init(&NVIC_InitStructure);` | 允许 CPU 响应 EXTI0 |
| 8. 定义中断入口 | `void EXTI0_IRQHandler(void)` | 由 CPU 自动进入，检查、清来源标志并记录事件 |

**核对提醒：**第 16 页先写 GPIO_Init、再写 AFIO 时钟，是概括步骤；实际代码还必须先开对应 GPIO 时钟，再访问、初始化 GPIO。第 7 页设置 NVIC 时，也应先把结构体成员填完整，再调用 `NVIC_Init()`。

### 3.7 可独立使用的标准库例程

本例配置 PA0 上升沿通知；主循环翻转课件图中的 PB5 LED。它演示初始化与中断流程，没有加入按键消抖，机械按键一次按下可能产生多次上升沿。不要把它当成可靠的“一次按下只翻转一次”成品。

工程需要标准库 GPIO、RCC、EXTI、misc 源文件以及匹配 STM32F103ZE 的启动文件。若工程已经有 `EXTI0_IRQHandler()`，修改原有定义，不能再增加第二份。本例与 GPIO 章节的完整 `main()` 示例独立使用。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_gpio.h"
#include "stm32f10x_exti.h"
#include "misc.h"

volatile uint8_t key_event = 0;

static void Key_EXTI_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    EXTI_InitTypeDef EXTI_InitStructure;
    NVIC_InitTypeDef NVIC_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA |
                          RCC_APB2Periph_GPIOB |
                          RCC_APB2Periph_AFIO, ENABLE);

    /* PB5：课件原理图中的低有效 LED */
    GPIO_SetBits(GPIOB, GPIO_Pin_5);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    /* PA0：松开为低，按下接 3.3 V */
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPD;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    GPIO_EXTILineConfig(GPIO_PortSourceGPIOA, GPIO_PinSource0);

    EXTI_InitStructure.EXTI_Line = EXTI_Line0;
    EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;
    EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Rising;
    EXTI_InitStructure.EXTI_LineCmd = ENABLE;
    EXTI_Init(&EXTI_InitStructure);

    EXTI_ClearITPendingBit(EXTI_Line0);
    NVIC_ClearPendingIRQ(EXTI0_IRQn);

    NVIC_InitStructure.NVIC_IRQChannel = EXTI0_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);
}

void EXTI0_IRQHandler(void)
{
    if (EXTI_GetITStatus(EXTI_Line0) != RESET)
    {
        EXTI_ClearITPendingBit(EXTI_Line0);
        key_event = 1U;
    }
}

int main(void)
{
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    Key_EXTI_Init();

    while (1)
    {
        if (key_event != 0U)
        {
            key_event = 0U;
            if (GPIO_ReadOutputDataBit(GPIOB, GPIO_Pin_5) == Bit_SET)
            {
                GPIO_ResetBits(GPIOB, GPIO_Pin_5);
            }
            else
            {
                GPIO_SetBits(GPIOB, GPIO_Pin_5);
            }
        }
    }
}
```

代码中的 `volatile` 提醒编译器：这个变量会在中断与主循环之间共享。`key_event` 是“发生过事件”的标志，多次事件可能合并；它不是完整的事件计数队列。

### 3.8 清标志、返回值与中断函数（第 14～16 页）

`EXTI_GetITStatus(EXTI_Line0)` 检查 EXTI0 的挂起与中断允许状态：

- `RESET` 的数值为 0：没有满足检查条件的有效中断状态。
- `SET` 的数值为 1：对应线有挂起标志，并且允许中断。
- `!= RESET` 表示“不等于 0”；这里并不会执行芯片复位。

`EXTI_ClearITPendingBit()` 清除硬件挂起标志，不会退出当前函数。若只处理任务、不清标志，请求可能再次挂起，退出后又进入同一个中断。

```text
PA0：0 → 1
    → EXTI0 记录挂起标志
    → NVIC 与 CPU 满足响应条件
    → 进入 EXTI0_IRQHandler
    → 检查标志、清标志、记录事件
    → 返回原程序，主循环处理事件
```

不要在 `main()` 中手动调用中断函数来“启动中断”；不要在中断里长期等待按键松开。依赖低优先级 SysTick 的延时若放进更高优先级中断，可能永远等不到计数变化。

### 3.9 寄存器步骤与课件第 17～18 页纠错

课件开始把库函数对应到寄存器，先记住以下分工即可：

| 寄存器 | 对应功能 |
| --- | --- |
| `AFIO->EXTICR[]` | 选哪一个端口接入同编号 EXTI 线 |
| `EXTI->IMR` | 对应位为 1，允许中断请求 |
| `EXTI->RTSR` | 开上升沿触发 |
| `EXTI->FTSR` | 开下降沿触发 |
| `EXTI->PR` | 挂起标志，写 1 清除 |
| `NVIC->ISER[]` | 对应位写 1，使能外部 IRQ |
| `NVIC->IP[]` | CMSIS 中按字节访问各个 IRQ 的优先级 |

**核对提醒一：清 EXTI 的 PR 必须写 1。**

```c
EXTI->PR = (1U << 0);       /* 正确：只清 EXTI0 标志 */
```

不能用 `PR &= ~mask` 清除；也不要用 `PR |= mask`，否则会把读到的其他挂起位一并写 1 清掉。清 NVIC 挂起也不能替代清外设 PR。

**核对提醒二：ISER 是写 1 执行使能，写 0 不影响其他通道。**第 17 页的读改写可改成直接写掩码，或直接用 CMSIS 函数：

```c
NVIC->ISER[0] = (1U << 6);  /* EXTI0_IRQn 是 6 */
/* 同一操作的常用写法：NVIC_EnableIRQ(EXTI0_IRQn); */
```

**核对提醒三：第 17 页优先级数组写法有实质错误。**课件中的 `NVIC->IP[1]` 在 CMSIS 里是一个 8 位优先级字节，不能把它当成 32 位 IPR1 再移位 16 位来修改 EXTI0。

- 对 EXTI0，按字节访问应是 `NVIC->IP[6]`。
- 若按硬件 32 位 IPR 寄存器描述，IRQ6 位于 IPR1 的 bits 23:16，不是课件文字中的 bits 15:8。
- F103 的有效优先级位在该字节的高 4 位。

初学时优先写下面这一行，避免混淆字节下标和字寄存器位域：

```c
NVIC_SetPriority(EXTI0_IRQn, 1U);
```

传入的是未左移的编码值，函数内部处理位置；编码值如何拆成抢占与子优先级仍取决于分组。若使用前面完整标准库例程，直接填写 `NVIC_InitStructure` 的两个优先级成员即可，不必再重复设置。

## 第四章：位带操作

本章对应《9_STM32位带操作深度解析》15 页。先判断地址是否属于位带窗口，再计算目标位的别名地址，最后理解宏封装和单次访问的原子性边界。

### 4.1 为什么会需要位带

**课件知识点｜P1～P4、P9**

51 编译器里的 `sbit` 可以把一个端口位写成近似变量的形式。STM32 工程中的 `PBout(5)` 通常是教程自己封装的宏，不是 C 语言关键字，也不是标准库自动提供的函数。

如果要设置普通读写寄存器的一个位，最直接的 C 写法是：

```c
GPIOB->ODR |= (1UL << 5);
```

这行 C 代码通常包含“读取整个 ODR → 修改临时值 → 写回整个 ODR”。如果中断在读写之间修改同一个 ODR 的其他位，后续写回旧临时值就可能覆盖它。代码只占一行，不代表硬件操作就是一个不可分割的动作。

位带允许把一个目标位映射到一个别名地址，通过对别名地址的单次读写访问该位。对普通可读写位，`PBout(5)=1U` 就可以只把 ODR 的 bit 5 置为 1。

**核对补充：**GPIO 还有 BSRR/BRR 这类专门的置位、复位寄存器，不是只有“整寄存器读改写”和“位带”两种选择。标准库的 GPIO 置位、复位接口也可使用专用寄存器；不能把所有库函数都归为存在相同风险的读改写。

### 4.2 两个位带区，各映射到一个别名区

**课件知识点：P5～P6、P14。**

| 对象 | 原始位带区，大小 1 MB | 别名区，大小 32 MB |
| --- | --- | --- |
| SRAM | `0x20000000`～`0x200FFFFF` | `0x22000000`～`0x23FFFFFF` |
| 外设 | `0x40000000`～`0x400FFFFF` | `0x42000000`～`0x43FFFFFF` |

![位带课件第 6 页：位带区与别名区](C:/Users/27686/Desktop/嵌入式/笔记/32/课件6至10_配图/位带_地址区域.png)

一个源字节有 8 个位，每个位对应一个 4 字节的别名字，所以扩展倍数为 `8×4=32`。别名区是访问原有存储位的另一条地址路径，不是新增了一块 32 MB RAM。

**核对纠错｜P6、P14 的“1 MB SRAM”应理解为地址窗口。**STM32F103ZE 实际片内 SRAM 是 64 KB，不是 1 MB；只有已实现并可合法访问的存储器或寄存器才有实际用途。位带公式不能把未实现地址变成真实内存。[STM32F103ZE 官方规格](https://www.st.com/en/microcontrollers-microprocessors/stm32f103ze.html)

SysTick 位于 `0xE000E010` 附近，不在外设位带区内；不能用下面的 GPIO 位带宏操作 SysTick。对于其他 STM32 系列或内核，也必须查芯片手册，不能因为名字叫 Cortex-M 就断定支持同一套位带窗口。

### 4.3 看懂映射公式，再看宏

**课件知识点：P7。**

统一思路是：

```text
别名地址 = 别名区基址 + (目标字节地址 - 位带区基址) × 32 + 字节内位号 × 4
```

外设和 SRAM 只需换各自的基址：

```text
外设：alias = 0x42000000 + (A - 0x40000000) × 32 + n × 4
SRAM：alias = 0x22000000 + (A - 0x20000000) × 32 + n × 4
```

这里最原始的定义是：A 是目标字节的地址，n 为该字节的 bit 0～bit 7。对于 STM32F103 的小端地址布局，若 A 是一个对齐寄存器的起始地址，也可以直接使用该寄存器的位号 n：例如 bit 8 的 `n×4`，等价于下一字节 bit 0 的映射。

![位带课件第 7 页：一个 bit 对应一个别名字地址](C:/Users/27686/Desktop/嵌入式/笔记/32/课件6至10_配图/位带_位与字地址映射.png)

先用图里的首个字节检查理解：

| 源位置 | 对应别名字地址 |
| --- | --- |
| `0x20000000` 的 bit 0 | `0x22000000` |
| `0x20000000` 的 bit 7 | `0x2200001C` |
| `0x20000001` 的 bit 0 | `0x22000020` |

别名字地址均按 4 字节对齐，不能把它们当成连续的 1 字节布尔数组。对别名字读操作返回 0 或 1；写入值的 bit 0 决定目标位取值。因此示例明确写 0U 或 1U，不用“任意非零值都表示置 1”的假设。[Arm Cortex-M3 技术参考手册，Bit-banding](https://www.st.com/resource/en/programming_manual/cd00228163.pdf)

### 4.4 手算 PB5 输出与 PA0 输入地址

**对应课件 P7、P11 的公式和 GPIO 宏；以下是按 STM32F103 寄存器地址补充的算例。**

GPIOB 基地址是 `0x40010C00`，ODR 偏移是 `0x0C`，因此 PB5 输出对应 `0x40010C0C` 的 bit 5：

```text
PB5_ODR_alias
= 0x42000000 + (0x40010C0C - 0x40000000) × 32 + 5 × 4
= 0x42218194
```

GPIOA 基地址是 `0x40010800`，IDR 偏移是 `0x08`，因此 PA0 输入对应 `0x40010808` 的 bit 0：

```text
PA0_IDR_alias
= 0x42000000 + (0x40010808 - 0x40000000) × 32 + 0 × 4
= 0x42210100
```

| 目标 | 原寄存器地址 | 位号 | 别名字地址 | 操作方向 |
| --- | --- | --- | --- | --- |
| PB5 输出锁存值 | `0x40010C0C`，GPIOB ODR | 5 | `0x42218194` | 读、写 |
| PA0 当前输入 | `0x40010808`，GPIOA IDR | 0 | `0x42210100` | 只读 |
| PC2 输出锁存值 | `0x4001100C`，GPIOC ODR | 2 | `0x42220188` | 读、写 |

ODR 是输出锁存值，IDR 是引脚输入采样值。读 ODR 不能代替所有场景下的实际引脚电平检测，写 IDR 也不能驱动引脚。[ST RM0008，GPIO 寄存器](https://www.st.com/resource/en/reference_manual/rm0008-stm32f103xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)

### 4.5 把公式封装成可读的 C 宏

**课件知识点｜P8、P11：BITBAND → MEM_ADDR → BIT_ADDR → PAout/PAin。下面为补全类型和括号后的教学版本。**

```c
#include "stm32f10x.h"
#include <stdint.h>

/* 前提：addr 在两个合法的 1 MB 源区域中，bitnum 指向合法目标位。 */
#define BITBAND(addr, bitnum) \
    ((((uint32_t)(addr) & 0xF0000000UL) + 0x02000000UL) + \
     (((uint32_t)(addr) & 0x00FFFFFFUL) << 5U) + \
     ((uint32_t)(bitnum) << 2U))

#define MEM_ADDR(addr) \
    (*(volatile uint32_t *)(uintptr_t)(addr))

#define BIT_ADDR(addr, bitnum) MEM_ADDR(BITBAND((addr), (bitnum)))

#define GPIOA_ODR_ADDR 0x4001080CUL
#define GPIOA_IDR_ADDR 0x40010808UL
#define GPIOB_ODR_ADDR 0x40010C0CUL
#define GPIOB_IDR_ADDR 0x40010C08UL
#define GPIOC_ODR_ADDR 0x4001100CUL
#define GPIOC_IDR_ADDR 0x40011008UL

#define PAout(n) BIT_ADDR(GPIOA_ODR_ADDR, (n))
#define PBout(n) BIT_ADDR(GPIOB_ODR_ADDR, (n))
#define PCout(n) BIT_ADDR(GPIOC_ODR_ADDR, (n))

/* IDR 是只读寄存器，输入宏也用 const 限制误写。 */
#define PAin(n) \
    (*(volatile const uint32_t *)(uintptr_t)BITBAND(GPIOA_IDR_ADDR, (n)))
#define PBin(n) \
    (*(volatile const uint32_t *)(uintptr_t)BITBAND(GPIOB_IDR_ADDR, (n)))
#define PCin(n) \
    (*(volatile const uint32_t *)(uintptr_t)BITBAND(GPIOC_IDR_ADDR, (n)))
```

`uint32_t` 是明确宽度的无符号整数；`UL` 和无符号转换可避免有符号移位带来的问题。`uintptr_t` 用来表达可容纳指针的整数地址。`volatile` 保证编译器按需要真正发起硬件访问，不把连续读写随意当作普通变量处理。

课件统一宏中 `(addr & 0xF0000000)` 取出的是 `0x20000000` 或 `0x40000000`；课件 P8 的“0x20/0x40”只是对地址开头的口语缩写，不是这一步计算出来的完整数值。`addr & 0x00FFFFFF` 在合法的两个 1 MB 窗口内可得到相应偏移，但它**不检查地址合法性**，更不能让任意外设地址都支持位带。

GPIO 引脚号必须为 0～15，不能传负数或 16 以上的数。宏会多次使用 addr，不要传 `addr++` 等带副作用的表达式。工程里若已有同名宏，应统一使用一份，避免不同定义互相覆盖。

### 4.6 使用前仍要初始化 GPIO

**课件知识点｜P12～P13。**

位带只改变寄存器的访问方式，不能替代 RCC 时钟、GPIO 模式与外部电路配置。PC2 输出和 PA0 输入是本课件的一组**独立接线示例**；不表示开发板的板载 LED 就接在 PC2。前面 GPIO 课件中的 PB5/PE5 板载灯，应按对应原理图使用。

以下假定使用普通 3.3 V LED 电路：`3.3 V → 限流电阻 → LED 正极，LED 负极 → PC2`，因此 PC2=0 时亮、PC2=1 时灭；PA0 外接按键到 GND，松开时由上拉保持高电平。

```c
/* 与上面的宏定义放在同一工程中；使用 STM32F10x 标准库。 */
void BitBand_GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA |
                          RCC_APB2Periph_GPIOC, ENABLE);

    /* 先把输出锁存器置高，配置成输出后默认熄灭。 */
    GPIO_SetBits(GPIOC, GPIO_Pin_2);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_2;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOC, &GPIO_InitStructure);

    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
}
```

课件选 50 MHz 输出模式只是允许的输出速度设置，不代表 LED 必须以 50 MHz 变化。普通 LED 练习选 2 MHz 即可。位带操作输出的是高低电平，电平对应亮还是灭取决于接线，不是 `=1` 必然点亮。

**核对纠错｜P12 配图不是可照抄的接线依据。**图片中的 LED 模块清楚标有 DC12V，而文字描述的是由 GPIO 直接经限流电阻驱动的 LED。这两者不能混用；12 V 模块不能直接按上面的普通 LED 电路接到 F103 GPIO。笔记保留 PC2 的普通 LED 练习，不把这张装饰图片当作硬件设计。

完成初始化后，若已选定前章一种延时实现，可以写：

```c
/* 示意：DelayMs 是工程选定并统一提供的毫秒延时接口。 */
PCout(2) = 0U;  /* 低电平亮 */
DelayMs(500U);
PCout(2) = 1U;  /* 高电平灭 */
DelayMs(500U);
```

把这段放在循环内，就得到课件 P12 的闪烁。延时接口名要与工程一致，不能因复制例子又启动第二套 SysTick 配置。

### 4.7 按键输入：可读一个位，但仍要消抖

**课件知识点｜P13**

```c
if (PAin(0) == 0U)
{
    DelayMs(20U);
    if (PAin(0) == 0U)
    {
        PCout(2) = !PCout(2);
        while (PAin(0) == 0U)
        {
            /* 这个入门示例在这里阻塞等待释放。 */
        }
    }
}
```

这保留了课件“按下 → 延时确认 → 翻转 → 等释放”的流程。它适合观察基本现象，但等待释放会暂停主循环其他任务；释放也可能抖动。需要持续处理按键、串口等任务时，应进一步用周期扫描和状态机消抖。

**核对纠错：这里的取反不是一个原子翻转操作。**右边先读别名字，CPU 求反后，左边再写别名字；两次访问之间仍可能进入中断。若只有主循环拥有这个 LED 状态，入门例子可这样使用；若中断或其他任务也修改同一个输出，应设计唯一所有者，或用适当临界区保护整个读改写过程。

### 4.8 “原子”到底保证了什么

**对应 P4、P10、P15；对课件中“彻底消除竞争”“无需额外锁”的说法收窄。**

| 写法或场景 | 能否直接得到单次位带访问的保证 |
| --- | --- |
| `PBout(5)=1U` 或 `=0U` | 对支持位带的普通读写目标位，是单次硬件原子更新 |
| `v=PAin(0)` | 单次读取返回目标位的 0/1 |
| `PBout(5)=!PBout(5)` | 不能；先读后写，是两个访问 |
| 先检查一个标志，再修改另一个变量 | 不能；整个业务流程没有自动加锁 |
| 另一段代码读整个 ODR 后再写回 | 仍可能用旧整字值覆盖位带写入 |

硬件位带写在内部执行原子的读改写，**不是让 CPU 在整段 C 表达式执行期间关闭所有中断**。它保障这一次访问，不自动保证多步骤协议、共享数据结构或多位同时修改正确。[Arm 对 Cortex-M3 位带机制的说明](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/a-tour-of-the-cortex-m3-core)

### 4.9 状态标志和命令寄存器，不能见位就套宏

**核对补充｜对应 P15 的适用范围问题。**

地址位于外设位带窗口内，只是必要条件；还必须确认寄存器的访问语义。位带写内部有读改写，因此不能把普通 ODR 的操作方法直接迁移到特殊寄存器。

- 对 **W1C（写 1 清除）**寄存器，例如 EXTI PR，应按手册直接写目标掩码清除。若内部读改写把其他已为 1 的挂起位也写回 1，可能顺带清掉它们。
- 对 **写 0 清除、读清除、只写命令**等寄存器，同样应遵守其专用访问方式，不应因为有别名地址就绕过规则。
- BSRR/BRR 已提供 GPIO 置位、复位命令，直接按手册写入即可；没有必要再给命令寄存器套一层位带。

例如清 EXTI0 时使用 `EXTI_ClearITPendingBit(EXTI_Line0)` 或按手册写 `EXTI->PR=EXTI_PR_PR0`，不要照搬 `PBout(5)=1U` 的外观创建“清中断”宏。

## 第五章：串口 USART1 收发与接收中断

本章对应《10_串口》12 页，使用标准外设库和 ARMCC5/C90。先学接线、8N1、初始化和 RXNE，再学 CRLF 软件协议；硬件收到一个字节，与软件收到完整一行，是两层不同的事情。

### 5.1 UART、USART 与串行通信

**UART** 是通用异步收发器，英文为 Universal Asynchronous Receiver/Transmitter。**USART** 多了同步通信能力，英文为 Universal Synchronous/Asynchronous Receiver/Transmitter。本章虽然操作的外设名为 `USART1`，使用的是它的异步 UART 功能。[课件第 1～2 页]

| 概念 | 具体含义 | 本章实验如何使用 |
| --- | --- | --- |
| 串行 | 一条数据线上按时间顺序逐位传输 | TX 输出串行数据，RX 接收串行数据 |
| 并行 | 多条数据线同时传输多个数据位 | 本章不使用 |
| 同步 | 收发双方通过时钟信号协调数据时序 | SPI、I²C 是课件给出的例子 |
| 异步 | 不传送独立的同步时钟线，双方约定波特率等格式 | 本章 USART1 的工作方式 |
| 全双工 | 两个方向能够同时传输 | 一根 TX 线和一根 RX 线分别工作 |

异步通信仍然使用双方各自的内部时钟。接收方根据起始位找到一帧的开始，再按约定波特率采样，因此波特率和时钟误差仍须在允许范围内。[课件第 2 页；补充]

**课件纠错：** 第 3 页用早期 COM/LPT 接口说明串行和并行，但“并行一定比串行快 8 倍”“串行一定更慢、距离一定更长”不能作为普遍结论。实际速度和距离还取决于时钟、编码、电气接口、线缆与抗干扰措施。初学时抓住“逐位传”和“多位同时传”的区别即可。

UART 内部可概括为波特率发生器、发送器和接收器。发送器把 CPU 提交的数据转换成串行波形，接收器把串行波形还原成数据。[课件第 4 页结构框图]

### 5.2 一帧数据：起始位、数据位、校验位与停止位

在本章使用的 MCU 逻辑电平侧，UART 线路空闲时为逻辑 `1`。发送一帧时，先发逻辑 `0` 的起始位，再传数据，最后以逻辑 `1` 的停止位结束。[课件第 5 页及帧格式图]

![串口课件第 5 页：帧格式](C:/Users/27686/Desktop/嵌入式/笔记/32/课件6至10_配图/UART_帧格式.jpeg)

图中的校验位是可选项，8N1 不发送校验位。

| 部分 | 作用 | 本章配置 |
| --- | --- | --- |
| 起始位 | 提示接收器一帧开始 | 1 位，逻辑 0 |
| 数据位 | 真正需要传输的二进制数据 | 8 位，最低位先发 |
| 校验位 | 用奇偶性检查部分传输错误 | 无校验 |
| 停止位 | 标识该帧结束，并回到高电平 | 1 位，逻辑 1 |
| 空闲状态 | 当前没有正在传输的数据帧 | 逻辑 1，不是每帧固定多加的一位 |

`9600, 8N1` 表示波特率 9600、8 个数据位、No parity（无校验）、1 个停止位。双方必须约定相同的波特率、数据位、校验位和停止位。

- **波特率**表示每秒传输的符号数。在本章这种每个符号承载 1 bit 的二电平 UART 中，9600 baud 对应每秒 9600 bit。
- 9600 baud 时，每位时间为 `1 / 9600 ≈ 104.17 μs`。
- 8N1 每帧共 `1 + 8 + 1 = 10 bit`，因此一帧约 `1.0417 ms`。
- 连续传输的理论有效数据速度为 `9600 / 10 = 960 字节/秒`。软件停顿、帧间间隔等会降低实际速度。[课件第 5 页计算；补充单位说明]

常见设置包括 9600、19200、38400、57600、115200 baud。硬件支持的波特率由时钟和分频决定，并不只限于串口助手菜单上的几个选项。

奇校验、偶校验会把校验位计算在逻辑 `1` 的个数中，使总数分别为奇数或偶数。校验位能检测部分错误，不能保证发现所有错误，也不负责重传。[课件第 5 页；补充]

**课件纠错：** 标准 ASCII 是 7 位字符编码，实际串口常用 8 位数据承载一个字节，不能把“ASCII”与“UART 必须是 8 位”画等号。UART 也能发送任意二进制字节。中文采用 UTF-8 等编码时，一个汉字通常要发送多个字节，串口本身不解释字符含义。

**补充：** STM32F1 的 `USART_WordLength_8b` 配合无校验，得到本章的 8 个有效数据位。开启奇偶校验后，校验位会占用所选字长的最高位；需要“8 个有效数据位加校验位”时，须相应选择 9 位字长。

### 5.3 电气接口与 TX/RX 接线

**UART 规定串行收发格式，TTL/CMOS、RS-232、RS-422、RS-485 等涉及电气接口。** STM32 引脚上的串口逻辑电平与 RS-232 电压不能直接互接。[课件第 4 页；课件纠错]

| 接口 | 初学时应知道的区别 |
| --- | --- |
| MCU/USB-TTL 串口 | 常见为 3.3 V 或 5 V 逻辑，使用前确认模块信号电平与 MCU 引脚要求兼容 |
| RS-232 | 使用正负电压，逻辑极性也与 MCU 逻辑电平侧不同，需要 MAX3232 等电平转换收发器 |
| RS-422、RS-485 | 使用差分信号，需要对应收发器，不能把其 A/B 线直接当 MCU 的 TX/RX 使用 |

本章用 USB 转串口模块连接电脑时，按**信号的方向**接线：

| STM32F103ZE 默认引脚 | USB 转串口模块 |
| --- | --- |
| PA9 / USART1_TX，发送输出 | RXD，接收输入 |
| PA10 / USART1_RX，接收输入 | TXD，发送输出 |
| GND | GND |

也就是 **TX 接对方 RX，RX 接对方 TX，并共地**。全双工的两个方向各用一根数据线，GND 提供共同的电压参考。模块标注的 TXD/RXD 通常以模块自身为参照。电源线是否连接取决于开发板和模块的供电方案，不能把“共地”理解成“必须把两个电源输出也接在一起”。[补充：课件没有具体接线图]

### 5.4 USART1 的引脚、时钟和初始化顺序

本章使用默认映射：`USART1_TX = PA9`、`USART1_RX = PA10`。USART1 的外设时钟来自 **APB2 的 PCLK2**；USART2、USART3 等使用 PCLK1。计算 USART1 波特率时使用实际 PCLK2，不能直接把任意工程的系统频率当作串口时钟，也不要套用某些定时器的 APB 时钟倍频规则。[课件第 6、11～12 页；本地参考手册第 120、524～525 页核验]

初始化时按下面的因果关系理解，而不只是背函数名：[课件第 6～7 页]

1. **开外设时钟。** 用 `RCC_APB2PeriphClockCmd()` 使能 GPIOA 和 USART1。课件随后用 `USART_DeInit(USART1)` 复位串口，清除之前的配置。
2. **配置引脚。** PA9 为 `GPIO_Mode_AF_PP`（复用推挽输出），PA10 可为 `GPIO_Mode_IN_FLOATING`（浮空输入）或 `GPIO_Mode_IPU`（上拉输入）。
3. **配置通信格式。** 用 `USART_InitTypeDef` 设置波特率、字长、停止位、校验、收发模式和硬件流控，再调用 `USART_Init()`。
4. **配置中断两端。** `USART_ITConfig()` 打开 USART 内部中断源，`NVIC_Init()` 打开 CPU 一侧的 USART1 中断通道并设置优先级。
5. **使能 USART。** 调用 `USART_Cmd(USART1, ENABLE)` 开始工作。

程序还要提供名字准确的 `USART1_IRQHandler(void)`，与启动文件的中断向量对应。USART 接收中断不需要走 GPIO 的 EXTI 配置。

| 配置项 | 本章值 | 原因 |
| --- | --- | --- |
| PA9 | `GPIO_Mode_AF_PP` | 输出由 USART 外设控制，推挽输出高低电平 |
| PA10 | 浮空输入或上拉输入 | 接收外部逻辑电平；上拉有利于断开连接时保持 UART 空闲高电平 |
| `USART_BaudRate` | `9600` | 与电脑串口助手相同 |
| `USART_WordLength` | `USART_WordLength_8b` | 8 位字长 |
| `USART_StopBits` | `USART_StopBits_1` | 1 位停止位 |
| `USART_Parity` | `USART_Parity_No` | 无校验 |
| `USART_Mode` | `USART_Mode_Rx \| USART_Mode_Tx` | 接收、发送都启用 |
| `USART_HardwareFlowControl` | `USART_HardwareFlowControl_None` | 不使用 RTS/CTS |

**课件解释补正：** 第 6 页截图给 RX 配置了 `GPIO_Speed_50MHz`。这个字段用于 GPIO **输出驱动速度**，不是串口波特率，也不是输入采样率。SPL 的 `GPIO_Init()` 在输入模式下不使用它来配置输入速率。UART 接收采样由 USART 外设时钟和波特率分频逻辑决定。

**课件解释补正：** RX 能接收高低电平，并不要求“一定浮空”。参考手册明确允许 USART 全双工 RX 使用浮空输入或上拉输入。上拉输入同样能被对方的推挽 TX 拉低，不能因为有上拉就认为它只能读到高电平。

课件使用 `NVIC_PriorityGroup_2`，并把 USART1 的抢占优先级、子优先级均设置为 3。在该分组下，两者各占 2 位，数值范围均为 0～3。优先级分组影响整个系统，应在主程序中统一设置一次，再配置各外设的优先级。[课件第 6～7、10 页；补充]

### 5.5 RXNE 接收中断与状态标志的清除

课件的关键调用是：

```c
USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);
```

**课件纠错：** 第 7 页截图把这句注释成“开启串口溢出中断”，准确含义是**使能接收数据寄存器非空中断**。`RXNE` 是 Receive data register not empty。它表示数据已经接收到接收数据寄存器，可以由程序读走。`ORE` 才是接收溢出/过载错误标志。STM32F1 的 `RXNEIE` 也能使 ORE 触发中断，因此二者有关，但不能混为同一个事件。

正常收一个字节的过程为：外设收到完整数据，置 `RXNE=1`；当 USART 内部中断使能和 NVIC 通道都打开时，CPU 进入 `USART1_IRQHandler()`；程序读取 `DR` 获得数据，硬件清除 RXNE。

| 操作 | SPL 中的常见写法 | 含义 |
| --- | --- | --- |
| 查询状态标志 | `USART_GetFlagStatus(USART1, USART_FLAG_RXNE)` | 检查 SR 中的状态，不要求该中断已使能 |
| 查询中断事件 | `USART_GetITStatus(USART1, USART_IT_RXNE)` | 同时考虑对应状态和中断使能 |
| 读取数据 | `USART_ReceiveData(USART1)` | 读取 DR，同时清 RXNE；8N1 时取低 8 位 |

**课件代码修正：** 第 9 页已经执行 `USART_ReceiveData()`，随后在收到 `0x0A` 的分支又执行 `USART_ClearITPendingBit(USART1, USART_IT_RXNE)`。读取 DR 后 RXNE 已清除，正常接收不需要额外手动清除。该 SPL 函数确实支持以写 0 方式清 RXNE，不能说它完全不支持；但用它代替读 DR 会放弃接收数据，额外清标志还可能碰上随后到达的新数据。应优先完成“读取数据”这一必要操作。

**补充：** 若软件来不及读走前一个字节，后一个字节又接收完成，就可能置位 ORE 并丢数据。ORE、FE、NE、PE 等错误标志要按 STM32F1 的规定执行“**先读 SR，再读 DR**”的序列清除。不要把定时器或 EXTI 的清标志方法原样套到 USART，也不要在中断里做长时间等待、打印大量文字。

### 5.6 课件的 CRLF 文本接收协议

UART 硬件按数据帧接收字节，硬件不知道“一条命令”在哪里结束。课件另外设计了一个软件协议：收到连续的 `0x0D 0x0A`，即 `\r\n`，才认为一条文本接收完成。[课件第 8～10 页]

这里的 `USART_RX_STA` 是程序定义的**全局变量**，不是芯片里的 USART 寄存器。课件用一个 16 位变量同时保存状态和长度：

![串口课件第 8 页：接收状态变量的位分配](C:/Users/27686/Desktop/嵌入式/笔记/32/课件6至10_配图/UART_接收软件状态位.png)

| 位 | 掩码 | 含义 |
| --- | --- | --- |
| bit15 | `0x8000` | 本条接收完成 |
| bit14 | `0x4000` | 已收到 `0x0D`，正在等 `0x0A` |
| bit13～0 | `0x3FFF` | 已保存的有效数据字节数，不包括结尾 CRLF |

接收过程可按以下顺序理解：

1. 初始 `USART_RX_STA = 0`，把普通字节依次放入 `USART_RX_BUF[]`，长度加 1。
2. 收到 `0x0D` 后置 bit14，不把 CR 放进有效数据区，也不再增加长度。
3. 下一个字节是 `0x0A`，则置 bit15，主循环可以处理本条数据。
4. CR 后面收到的不是 LF，则课件丢弃本条并复位状态，等待后续数据。
5. 没有结束符而数据超出缓冲区容量时，丢弃本条并重新接收。
6. 主循环处理完后清状态，允许开始下一条。[课件第 8～10 页]

**补充和边界修正：** 这是适合入门的单缓冲文本协议。完整一条尚未处理时，新字节会被读取后丢弃。它没有接收超时，也不适合直接承载任意二进制内容。课件第 9 页“写入、长度加 1、再判断大于 `USART_REC_LEN-1`”的写法会在填满数组时复位；下面示例改成先判断容量，允许保存恰好 `USART_REC_LEN` 字节。

### 5.7 可放入工程的完整入门示例

下面是**整理后的独立示例**，把第 6～10 页的初始化、CRLF 接收和主循环回发连成一个文件，并修正上述边界问题。它以 9600、8N1 接收一行，再把原字节及 CRLF 回发。代码使用 SPL，不使用 HAL，不依赖 `printf` 重定向。

使用前准备 STM32F103ZE 标准库工程、正确的系统时钟文件和高容量器件启动文件，开启 `STM32F10X_HD` 与 `USE_STDPERIPH_DRIVER`，加入 GPIO、RCC、USART、`misc.c` 等所需源文件。启动文件会调用 `SystemInit()`；`USART_Init()` 根据当前 RCC 配置取得 PCLK2 并计算波特率。

将本例整体放在同一个 `.c` 文件中，工程内只能保留一份 `main()` 和一份 `USART1_IRQHandler()`。如果 `stm32f10x_it.c` 已有同名空 ISR，应移除重复的空定义；已有业务代码时应合并处理。本例状态变量使用 `static`，ISR 与这些变量须放在同一源文件，拆文件时需要另外设计声明与访问接口。

```c
#include "stm32f10x.h"

#define USART_REC_LEN  200U
#define RX_DONE        0x8000U
#define RX_GOT_CR      0x4000U
#define RX_LEN_MASK    0x3FFFU

static volatile uint8_t USART_RX_BUF[USART_REC_LEN];
static volatile uint16_t USART_RX_STA = 0U;

static void UART1_Init(uint32_t baud)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    USART_InitTypeDef USART_InitStructure;
    NVIC_InitTypeDef NVIC_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA |
                          RCC_APB2Periph_USART1, ENABLE);
    USART_DeInit(USART1);

    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_9;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;  /* RX also permits floating input. */
    GPIO_Init(GPIOA, &GPIO_InitStructure);        /* Speed field is ignored for input. */

    USART_StructInit(&USART_InitStructure);
    USART_InitStructure.USART_BaudRate = baud;
    USART_InitStructure.USART_WordLength = USART_WordLength_8b;
    USART_InitStructure.USART_StopBits = USART_StopBits_1;
    USART_InitStructure.USART_Parity = USART_Parity_No;
    USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None;
    USART_InitStructure.USART_Mode = USART_Mode_Rx | USART_Mode_Tx;
    USART_Init(USART1, &USART_InitStructure);

    NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 3U;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 3U;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);

    USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);
    USART_Cmd(USART1, ENABLE);
}

static void UART1_SendByte(uint8_t data)
{
    while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET)
    {
    }
    USART_SendData(USART1, (uint16_t)data);
}

void USART1_IRQHandler(void)
{
    uint32_t sr;
    uint8_t data;
    uint16_t len;

    sr = USART1->SR;
    if ((sr & (USART_SR_RXNE | USART_SR_ORE)) == 0U)
    {
        return;
    }

    /* Reading SR, then DR clears RXNE and receive error flags. */
    data = (uint8_t)(USART_ReceiveData(USART1) & 0x00FFU);

    /* Keep a completed line stable while main sends it. */
    if ((USART_RX_STA & RX_DONE) != 0U)
    {
        return;
    }

    if ((sr & (USART_SR_ORE | USART_SR_FE |
               USART_SR_NE | USART_SR_PE)) != 0U)
    {
        USART_RX_STA = 0U;          /* Discard an invalid partial line. */
        return;
    }
    if ((sr & USART_SR_RXNE) == 0U)
    {
        return;
    }

    if ((USART_RX_STA & RX_GOT_CR) != 0U)
    {
        if (data == 0x0AU)
        {
            USART_RX_STA |= RX_DONE;
        }
        else
        {
            USART_RX_STA = 0U;
        }
    }
    else if (data == 0x0DU)
    {
        USART_RX_STA |= RX_GOT_CR;
    }
    else
    {
        len = USART_RX_STA & RX_LEN_MASK;
        if (len < USART_REC_LEN)
        {
            USART_RX_BUF[len] = data;
            USART_RX_STA = (uint16_t)(len + 1U);
        }
        else
        {
            USART_RX_STA = 0U;
        }
    }
}

int main(void)
{
    uint16_t i;
    uint16_t len;

    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    UART1_Init(9600U);

    while (1)
    {
        if ((USART_RX_STA & RX_DONE) != 0U)
        {
            len = USART_RX_STA & RX_LEN_MASK;
            for (i = 0U; i < len; i++)
            {
                UART1_SendByte(USART_RX_BUF[i]);
            }
            UART1_SendByte(0x0DU);
            UART1_SendByte(0x0AU);
            while (USART_GetFlagStatus(USART1, USART_FLAG_TC) == RESET)
            {
            }
            USART_RX_STA = 0U;
        }
    }
}
```

代码中 ISR 先保存一次 SR，再读 DR，便于一起处理 ORE 等接收错误，因此没有再调用 `USART_GetITStatus()`。本例只使能接收中断源。不要直接把这个 ISR 复制去处理同时启用了 TXE、TC 等中断源的工程，新增的中断源需要对应服务逻辑。

验证范围：上例已使用原 `10-23` 工程头文件通过 ARMCC5、C90 模式的单文件编译检查，未进行开发板实测。

`USART_RX_STA` 和缓冲区由主循环与 ISR 共享，所以标为 `volatile`。这能要求编译器实际访问变量，不能替代互斥或完整的并发设计。本例依靠“完成标志置位后 ISR 只读走并丢弃新字节”保持缓冲区稳定。电脑应等待回发结束后再发送下一行。需要连续无丢包接收时，应另外学习环形缓冲区、双缓冲或 DMA。[补充]

**课件代码修正：** 第 10 页直接把 `USART_RX_BUF` 用作 `printf("%s", ...)` 的参数，但第 9 页没有保证数组以 `\0` 结束。`%s` 会一直读到 NUL，可能越过有效数据或数组末尾。上例按保存的长度逐字节回发，不要求 NUL。若要把数据当 C 字符串，必须在容量设计中预留一个字节并写入 `\0`，还要完成串口 `printf` 重定向。

### 5.8 TXE、TC 与发送低 8 位

| 标志 | 位 | 为 1 时说明什么 | 典型用途 |
| --- | --- | --- | --- |
| TXE | SR bit7 | 发送数据寄存器 TDR 已空，可以再写一个数据 | 连续发送时，每次写 DR 前等待 |
| TC | SR bit6 | TDR 为空，移位寄存器中的整帧也已发送完成 | 最后一个字节之后确认线路发送完毕 |

TXE 置位时，前一个字节可能还在 TX 引脚上逐位发送。TC 置位才表示最后一帧连同停止位都发完。第 10 页的 `SR & 0x40` 实际检查 **TC**，不是 TXE。逐字节等待 TC 能发出数据，但会减少连续发送的流水效果。上例每字节写之前等 TXE，整行最后再等 TC。[课件第 10 页；补充]

`USART_SendData()` 接口使用 `uint16_t`，用于支持 8/9 位字长；库函数会把参数低 9 位写入 DR。**本章 8N1 发送的是一个字节的低 8 位**，因此发送函数用 `uint8_t` 接收参数。若变量是 16 位或更宽的数，发送一个字节不会自动把它的所有字节都发完。发送 `0x1234` 这样的多字节数值，需要自己约定顺序并拆成 `0x12`、`0x34`，或转换成文本。

### 5.9 从标准库函数对应到寄存器

第 11～12 页开始转向寄存器配置。先理解每类寄存器负责什么，再考虑把标准库代码改为寄存器写法。[课件第 11～12 页；补充具体位含义]

| 寄存器 | 作用 | 本章重点 |
| --- | --- | --- |
| `USART_SR` | 状态 | RXNE、TXE、TC、ORE 等标志；不同标志的清除方法不同 |
| `USART_DR` | 数据 | 写操作进入发送通路，读操作取接收通路；二者共用地址但内部收发缓冲分开 |
| `USART_BRR` | 波特率分频 | bit15～4 保存整数部分，bit3～0 保存 1/16 为单位的小数部分 |
| `USART_CR1` | 基本控制与部分中断使能 | UE bit13、M bit12、PCE bit10、PS bit9、RXNEIE bit5、TE bit3、RE bit2 |
| `USART_CR2` | 停止位、同步时钟等 | STOP[13:12] 为 `00` 时是 1 个停止位；本章不启用同步 CK 输出 |
| `USART_CR3` | 流控、DMA、错误中断等 | 本章不启用 RTS/CTS，也不使用 DMA |

在 STM32F103 的 16 倍过采样下：

```text
USARTDIV = fPCLK / (16 × BaudRate)
USARTDIV = DIV_Mantissa + DIV_Fraction / 16
BRR = (DIV_Mantissa << 4) | DIV_Fraction
BaudRate = fPCLK / (16 × USARTDIV)
```

以 **USART1 的实际 PCLK2 = 72 MHz，目标波特率 115200** 为例：

```text
USARTDIV = 72 000 000 / (16 × 115200) = 39.0625
整数部分 DIV_Mantissa = 39 = 0x27
小数部分 DIV_Fraction = 0.0625 × 16 = 1
BRR = (0x27 << 4) | 1 = 0x0271

反推：72 000 000 / (16 × 39.0625) = 115200 baud
```

这也解释了第 11 页截图中的 `39.0625` 和 `fPCLK / 625`：`16 × 39.0625 = 625`。只有给出实际 PCLK，才能得到最终波特率；不能单看 39.0625 就认定某个固定波特率。

若同样是 PCLK2 = 72 MHz、波特率改为 9600：`USARTDIV = 468.75`，整数部分为 `468 = 0x1D4`，小数部分为 `0.75 × 16 = 12 = 0xC`，因此 `BRR = 0x1D4C`。

第 12 页写成 `pclk2 * 1000000`，前提是参数 `pclk2` 以 **MHz** 为单位，例如传入 72。如果已经是 72000000 Hz，就不能再乘一百万。分数舍入可能产生误差；小数部分四舍五入得到 16 时，应向整数部分进 1。日常使用 `USART_Init()` 即可让标准库根据实际时钟计算 BRR，不必在应用层使用浮点数。[课件第 11～12 页；补充分频与单位说明]

寄存器版的整体步骤仍与标准库版一致：开启 GPIOA/USART1 时钟，配置引脚，复位外设并结束复位，设置 BRR、CR1/CR2/CR3，配置中断通道和 ISR，使能接收中断与 USART。配置时避免随意覆盖保留位，也不要在正在传输时随意改变波特率或字长。

### 5.10 实验检查与易错点

1. 串口助手选择模块对应的 COM 口，设置 **9600、8 数据位、无校验、1 停止位、无硬件流控**。
2. 先发 ASCII 文本 `abc`，并启用“发送新行/回车换行”，确认实际上发送 `61 62 63 0D 0A`。本章示例只有收到 CRLF 才会回发，单独一个 LF 不算结束。
3. 完全无数据时，依次检查 TX/RX 是否交叉、是否共地、是否选择了正确串口和引脚、GPIO/USART 时钟是否打开。
4. 数据乱码时，检查双方波特率和格式、工程真实系统时钟/PCLK2、USB 转串口信号电平与终端字符编码。
5. 能发送但接收中断不工作时，检查 PA10、`USART_Mode_Rx`、`USART_IT_RXNE`、NVIC 通道、全局中断是否允许，以及 ISR 函数名是否与启动文件一致。
6. 接收几次后卡住或丢字节时，检查是否读 DR、是否处理 ORE、是否越界、是否把长操作放进 ISR，以及主循环是否及时释放接收完成状态。

## 第六章：独立看门狗 IWDG

对应《11_ 独立看门狗实验-IWDG》13 页，按“用途与原理 → 寄存器 → 超时计算 → 库函数与实验”学习。

### 6.1 看门狗检查的是什么（第 1～5 页）

程序正常执行时，定期执行一次“喂狗”；程序卡住、跑飞或没有按期完成任务时，停止喂狗，让看门狗超时产生系统复位。

**喂狗就是重新装载倒计数值。** 复位会让芯片重新走启动流程，并非从卡住的那一行继续执行。

| 项目 | IWDG | WWDG |
| --- | --- | --- |
| 时钟来源 | 独立低速 RC 振荡器 LSI | APB1 的 PCLK1 经分频 |
| 喂狗要求 | 在超时之前完成 | 在允许窗口内完成，过早、过晚都可能复位 |
| 常见用途 | 检测主程序长时间失去进展 | 检测程序执行时序偏离预期 |
| 中断 | 本芯片 IWDG 没有提前报警中断 | 可产生 EWI 提前唤醒中断 |

IWDG 启动后，LSI 可使它在主时钟异常时继续计时；它也能在 Stop、Standby 中工作。是否在调试暂停期间继续计数，要看 DBGMCU 的冻结配置。

### 6.2 从框图理解“独立”（第 4～6 页）

IWDG 使用自己的 LSI 时钟，经预分频后驱动 **12 位递减计数器**；重装载值来自 RLR。

![IWDG 课件第 6 页：独立看门狗框图](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/IWDG_结构框图.png)

读图顺序：**LSI → 预分频器 PR → 12 位计数器 → 超时复位**。CPU 通过 KR 写入命令，通过 PR、RLR 设定参数，通过 SR 确认参数更新状态。

IWDG 没有类似 `RCC_APB1Periph_IWDG` 的外设时钟使能项。下面的示例主动启动 LSI 并等它就绪，便于先完成参数更新，再启动看门狗。

### 6.3 四个寄存器与三个键值（第 6～10 页）

| 寄存器 | 有效位或字段 | 作用 |
| --- | --- | --- |
| `IWDG_KR` | KEY[15:0]，只写命令 | 解锁参数、启动、喂狗 |
| `IWDG_PR` | PR[2:0] | 选择 LSI 分频系数 |
| `IWDG_RLR` | RL[11:0]，0～4095 | 保存每次喂狗要重新装入的数值 |
| `IWDG_SR` | PVU、RVU | 指示预分频或重装载值是否正在更新 |

| 写入 KR 的值 | 对应标准库调用 | 动作 |
| --- | --- | --- |
| `0x5555` | `IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);` | 允许修改 PR、RLR |
| `0xAAAA` | `IWDG_ReloadCounter();` | 把 RLR 重新装入计数器，并恢复参数写保护 |
| `0xCCCC` | `IWDG_Enable();` | 启动 IWDG，并恢复参数写保护 |

`PVU=1`、`RVU=1` 表示更新尚未完成；等待硬件清零后再依赖新参数。SR 不提供“还剩多少时间”的实时计数值，也不是中断挂起寄存器。

**启动后的 IWDG 不能用普通软件关闭，只能通过复位结束本次运行。** 软件启动与选项字节配置的硬件自动启动要区分；本章代码按软件启动方式使用。

### 6.4 分频、重装载值与超时时间（第 8、11、13 页）

先把符号和单位写全：`D` 是实际分频系数，`RLR` 是寄存器值，`f_LSI` 单位为 Hz。

```text
计数频率 f_cnt = f_LSI / D
每减一次的时间 t_tick = D / f_LSI
名义超时时间 T_out ≈ (RLR + 1) × D / f_LSI      单位：秒
```

![IWDG 课件第 11 页：40 kHz LSI 下的超时范围](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/IWDG_40kHz超时表.png)

| PR 编码 | 实际分频 D | 对应标准库宏 | 40 kHz 下每步时间 |
| --- | --- | --- | --- |
| 0 | 4 | `IWDG_Prescaler_4` | 0.1 ms |
| 1 | 8 | `IWDG_Prescaler_8` | 0.2 ms |
| 2 | 16 | `IWDG_Prescaler_16` | 0.4 ms |
| 3 | 32 | `IWDG_Prescaler_32` | 0.8 ms |
| 4 | 64 | `IWDG_Prescaler_64` | 1.6 ms |
| 5 | 128 | `IWDG_Prescaler_128` | 3.2 ms |
| 6 或 7 | 256 | 使用 `IWDG_Prescaler_256` | 6.4 ms |

例如选 `/64`，希望名义超时约 1 秒：

```text
RLR + 1 = 1 × 40000 / 64 = 625
RLR = 624
T_out = 625 × 64 / 40000 = 1 s
```

最大设置 `/256`、`RLR=4095`，在 40 kHz 下约为 **26.2144 秒**。LSI 是 RC 时钟，40 kHz 是用于计算的典型值，实际超时会随芯片、温度和电压变化；它不适合作为精密时间基准。

**课件纠错：**第 11、13 页的公式省略了 `RLR+1` 中的 `+1`；按其同页表格，`RLR=0` 也有一个计数周期。`4×2^PR` 只适合 PR 编码 0～6，PR=7 仍是 `/256`。若用 kHz 代入，结果才直接是毫秒；用 Hz 代入则是秒。

### 6.5 初始化与喂狗的具体调用（第 12～13 页）

| 顺序 | 具体调用 | 目的 |
| --- | --- | --- |
| 1 | `RCC_LSICmd(ENABLE);` | 启动 LSI |
| 2 | `RCC_GetFlagStatus(RCC_FLAG_LSIRDY)` | 等待 LSI 就绪 |
| 3 | `IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);` | 允许写 PR、RLR |
| 4 | `IWDG_SetPrescaler(IWDG_Prescaler_64);` | 设置 `/64` |
| 5 | `IWDG_SetReload(624);` | 设置约 1 秒的名义超时 |
| 6 | `IWDG_GetFlagStatus(IWDG_FLAG_PVU)`、`IWDG_GetFlagStatus(IWDG_FLAG_RVU)` | 等待参数更新完成 |
| 7 | `IWDG_ReloadCounter();` | 装入初值 |
| 8 | `IWDG_Enable();` | 启动看门狗 |
| 运行时 | `IWDG_ReloadCounter();` | 确认任务正常后，在超时前喂狗 |

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_iwdg.h"

void IWDG_Init_About1s(void)
{
    RCC_LSICmd(ENABLE);
    while (RCC_GetFlagStatus(RCC_FLAG_LSIRDY) == RESET)
    {
    }

    IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);
    IWDG_SetPrescaler(IWDG_Prescaler_64);
    IWDG_SetReload(624);

    while ((IWDG_GetFlagStatus(IWDG_FLAG_PVU) != RESET) ||
           (IWDG_GetFlagStatus(IWDG_FLAG_RVU) != RESET))
    {
    }

    IWDG_ReloadCounter();
    IWDG_Enable();
}

void IWDG_Feed(void)
{
    IWDG_ReloadCounter();
}
```

这是一组初始化、喂狗函数，不是一个自行调度任务的完整主程序。调用 `IWDG_Init_About1s()` 后，主程序必须在正常任务取得进展时及时调用 `IWDG_Feed()`。

### 6.6 怎样安排喂狗与观察复位

先让正常主循环定期喂狗，再人为停止调用喂狗函数，观察经过超时时间后重新启动。实验里可让 PA0 控制是否喂狗；产品程序应以任务执行结果作为健康条件。

启动后可这样判断复位来源，判断完成再清标志：

```c
if (RCC_GetFlagStatus(RCC_FLAG_IWDGRST) != RESET)
{
    /* 记录：上一次发生过 IWDG 复位 */
}
RCC_ClearFlag();  /* 清除 RCC 的复位来源标志 */
```

不要在一个始终运行的定时中断里无条件喂狗，否则主循环卡住时，中断仍可能继续喂狗。看门狗能发现“没有按预期喂狗”，并不能自动判断所有业务逻辑是否正确。

## 第七章：窗口看门狗 WWDG

对应《12_窗口看门狗实验-WWDG》12 页，按“喂狗窗口 → 时钟和时间 → 寄存器 → 配置与实验”学习。

### 7.1 为什么增加一个时间窗口（第 1～2、7 页）

IWDG 主要限制“不能太晚喂狗”。如果程序跑错路径，却不断执行喂狗动作，仍可能逃过检查。WWDG 要求刷新发生在指定窗口内，因此还能帮助发现“提前跳过任务、过早刷新”等执行时序异常。

WWDG 仍然只检查约定的刷新行为，不能单靠它证明程序的计算结果正确。

### 7.2 计数器、窗口值与两个复位条件（第 3～5、8 页）

先分清三个量：`C` 为当前计数值，`T0` 为启动或刷新后装入的值，`W` 为窗口上限。它们都使用低 7 位。

![WWDG 课件第 3 页：刷新窗口与复位边界](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/WWDG_刷新窗口.png)

| 当前状态 | 结果或要求 |
| --- | --- |
| 看门狗已启用，当前 `C > W` 就刷新 | 过早刷新，产生复位 |
| 当前计数已经进入窗口，且还没有低于 `0x40` | 可以安排刷新；示例取窗口内部并留余量 |
| 当前 `C = 0x40` | 若启用 EWI，则产生提前唤醒中断 |
| 从 `0x40` 递减到 `0x3F` | T6 清零，产生复位 |

**初值不是窗口值。** 例如 `T0=0x7F`、`W=0x5F`：先从 127 倒数，等待进入窗口，刷新时又把计数器装回 127。

工程上选择 `W > 0x40`，把常规喂狗点安排在 `0x40 < C < W` 的内部，不依赖等于 W 的边界。`C=0x40` 是 EWI 的最后处理机会，应尽量留给异常处理。

### 7.3 时钟来源与寄存器（第 4、8～11 页）

WWDG 使用 **PCLK1**，先固定除以 4096，再除以 1、2、4 或 8。它不使用通用 TIM 的 APB 定时器倍频规则。

![WWDG 课件第 4 页：比较器、计数器与时钟链路](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/WWDG_结构框图.png)

| 寄存器 | 字段 | 作用 |
| --- | --- | --- |
| `WWDG_CR` | WDGA、T[6:0] | 启动看门狗，装入计数值；WDGA 启动后只能由复位清除 |
| `WWDG_CFR` | EWI、WDGTB[1:0]、W[6:0] | 使能 EWI、选择分频、设置窗口 |
| `WWDG_SR` | EWIF | 记录计数到达 `0x40`；软件写 0 清除 |

`WWDG_EnableIT()` 设置的是 EWI 请求使能，`NVIC_Init()` 设置 CPU 一侧的 WWDG 中断通道，两处都要准备好。EWI 使能位一旦置位，也要复位后才能关闭。

WWDG 启用后装入的计数值必须保留 T6=1，即低 7 位通常取 `0x40～0x7F`；不能把 `0x3F` 当作正常重装载值。

### 7.4 先算每步时间，再算窗口（第 6 页）

令 `D` 为实际分频 1、2、4、8；PCLK1 用 Hz 表示：

```text
计数频率 f_cnt = PCLK1 / (4096 × D)
每减一次的时间 t_tick = 4096 × D / PCLK1

到窗口边界的名义时间 ≈ (T0 - W) × t_tick
到 EWI 的名义时间     ≈ (T0 - 0x40) × t_tick
到复位的名义时间      ≈ (T0 - 0x3F) × t_tick
```

![WWDG 课件第 6 页：超时公式及单位](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/WWDG_超时公式.png)

若 PCLK1=36 MHz、`D=8`、`T0=0x7F`、`W=0x5F`：

| 要计算的量 | 结果 |
| --- | --- |
| 一个计数周期 | `4096×8/36000000 ≈ 0.9102 ms` |
| 到窗口边界 | `32×0.9102 ≈ 29.13 ms` |
| 到 EWI | `63×0.9102 ≈ 57.34 ms` |
| 到复位 | `64×0.9102 ≈ 58.25 ms` |

可以把正常刷新目标放在约 40 ms 这一类窗口内部的时刻。预分频器相位、任务耗时、中断延迟都会影响可用余量，上表适合设计估算，不应把临界时刻当作无误差的保证。

**课件纠错：**第 6 页正文把“计数频率×计数步数”写成中断时间，量纲不对。时间应是“步数÷频率”。该页图片公式使用 PCLK1 的 kHz 数值，所以结果是 ms；若代入 Hz，应先得到秒。`WDGTB` 是编码 0～3，对应实际分频 `2^WDGTB`。

### 7.5 标准库配置与刷新（第 9～12 页）

| 顺序 | 具体调用 |
| --- | --- |
| 1. 开 WWDG 时钟 | `RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);` |
| 2. 设置 `/8` | `WWDG_SetPrescaler(WWDG_Prescaler_8);` |
| 3. 设置窗口值 | `WWDG_SetWindowValue(0x5F);` |
| 4. 清 EWI 旧标志 | `WWDG_ClearFlag();` |
| 5. 配置可选的 EWI | `WWDG_EnableIT();`，以及 WWDG_IRQn 的 NVIC 配置 |
| 6. 启动并装入初值 | `WWDG_Enable(0x7F);` |
| 7. 窗口内确认任务正常后刷新 | `WWDG_SetCounter(0x7F);` |

下面示例保留 EWI 用于记录“已接近超时”，**不在 EWI 中无条件喂狗**。`Tasks_OK` 应来自主程序对必要任务的健康检查。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_wwdg.h"
#include "misc.h"

volatile uint8_t WWDG_EarlyEvent = 0;

/* 前提：系统已统一设置 NVIC_PriorityGroup_2 */
void WWDG_Window_Init(void)
{
    NVIC_InitTypeDef NVIC_InitStructure;

    RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);
    WWDG_SetPrescaler(WWDG_Prescaler_8);
    WWDG_SetWindowValue(0x5F);
    WWDG_ClearFlag();
    NVIC_ClearPendingIRQ(WWDG_IRQn);

    NVIC_InitStructure.NVIC_IRQChannel = WWDG_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 0;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);

    WWDG_EnableIT();
    WWDG_Enable(0x7F);
}

/* 主循环中及时调用；这里只演示“健康条件 + 窗口检查” */
void WWDG_FeedIfHealthy(uint8_t Tasks_OK)
{
    uint8_t counter;

    counter = (uint8_t)(WWDG->CR & 0x7F);
    if ((Tasks_OK != 0) && (counter < 0x5F) && (counter > 0x40))
    {
        WWDG_SetCounter(0x7F);
    }
}

void WWDG_IRQHandler(void)
{
    if (WWDG_GetFlagStatus() != RESET)
    {
        WWDG_ClearFlag();
        WWDG_EarlyEvent = 1;
    }
}
```

窗口检查和写入之间仍有执行时间，调用处要留足余量，不可在接近下边界时依赖一次读值。没有及时刷新时，即使已经进入 EWI，下一计数步仍可能复位；清 EWIF 不会重装载计数器。

### 7.6 EWI、复位来源与调试

- EWI 发生在 `0x40`，到 `0x3F` 复位前只剩约一个计数周期。中断里不适合阻塞式长串口打印或长延时。
- 若实验要在 EWI 中演示自救，应先及时刷新，再执行很短的处理。自动刷新会改变故障检测效果，不能把它等同于主程序健康检查。
- 可用 `RCC_GetFlagStatus(RCC_FLAG_WWDGRST)` 判断看门狗复位来源，记录后再 `RCC_ClearFlag()`。
- IWDG、WWDG 的调试冻结是各自独立的 DBGMCU 配置；单步调试的结果不等于正常连续运行的时间行为。

## 第八章：通用定时器基本原理

对应《13_通用定时器基本原理》13 页。先认识定时器种类，再沿“时钟 → PSC → CNT → ARR/CCR → 事件”读框图，最后理解输入捕获和 PWM。

### 8.1 STM32F103ZE 有哪些 TIM（第 1～3 页）

本芯片共有 8 个 TIM 外设。SysTick 属于内核定时器，不算在这 8 个 TIM 外设中。

| 类型 | F103ZE 中的编号 | 计数器与模式 | 通道与常见用途 |
| --- | --- | --- | --- |
| 高级定时器 | TIM1、TIM8 | 16 位，向上、向下、中心对齐 | 每个 4 个捕获/比较通道，另有互补输出、死区、刹车、重复计数器等 |
| 通用定时器 | TIM2、TIM3、TIM4、TIM5 | 16 位，向上、向下、中心对齐 | 每个 4 个捕获/比较通道，用于定时、计数、捕获、比较、PWM 等 |
| 基本定时器 | TIM6、TIM7 | 16 位，只支持向上计数 | 无外部捕获/比较通道，常用作内部时基、DAC 触发 |

![通用定时器课件第 2 页：不同 F103 型号的资源对照](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_型号资源对照.png)

**课件纠错：**第 2 页“F10x 系列最多 8 个定时器”不能推广到整个系列；同图中的更大容量型号就列出了更多资源。本文限定 F103ZE。第 3 页把基本定时器也写成可向下、向上/下计数，应改为只向上。不要把其他 STM32 系列的“TIM2 是 32 位”套到本芯片上。

### 8.2 先看懂完整框图（第 4～7 页）

定时器包含一套时基和若干输入/输出通道。只做周期中断时，先读时基，不必一次理解图中所有连线。

![通用定时器课件第 7 页：TIM 总体框图](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_总体框图.png)

| 模块 | 作用 | 先回答的问题 |
| --- | --- | --- |
| 时钟选择/从模式控制 | 选择内部或外部计数来源、触发和同步 | 由什么信号推动计数？ |
| PSC 预分频器 | 将输入时钟按 `PSC+1` 分频 | 多少个输入时钟，CNT 才走一步？ |
| CNT 计数器 | 保存当前计数值 | 现在数到哪里？ |
| ARR 自动重装载值 | 确定计数边界 | 数到哪里发生回卷或转向？ |
| CCR1～CCR4 | 捕获时锁存 CNT，比较时保存比较值 | 测量哪个时刻，或在哪个计数值改变输出？ |
| 事件、中断和 DMA | 把硬件状态通知 CPU 或 DMA | 事件是否产生了请求，是否被响应？ |

每个 TIM 有自己的 CNT、PSC、ARR 等寄存器，但同一个 TIM 的多个通道共用这套时基。它们还共享 RCC 时钟体系、总线和系统的中断管理，不能把“各定时器独立”理解成所有系统资源都互不关联。

### 8.3 计数时钟可以从哪里来（第 8 页；课件 14 第 3 页）

| 时钟/触发来源 | 怎样理解 |
| --- | --- |
| 内部时钟 CK_INT | 使用 RCC 提供的 TIMxCLK，最适合先学习周期中断 |
| 外部时钟模式 1 | 通过选定的触发输入计数，常见来源为 TI1、TI2 等 |
| 外部时钟模式 2 | 通过 ETR 外部输入计数 |
| 内部触发 ITR0～ITR3 | 在手册规定的互连关系中，让其他定时器提供触发/计数来源 |

**课件纠错：**第 8 页图片写成了 ITR1～ITR4，应按寄存器定义和框图使用 ITR0～ITR3。TIx 输入、ETR 输入还涉及极性、滤波和输入分频，不等于把任意 GPIO 接入就自动开始计数。

本笔记定时中断例子选择内部时钟：

```c
TIM_InternalClockConfig(TIM3);
```

### 8.4 从 APB 总线得到 TIMxCLK

TIM2～TIM7 位于 APB1；TIM1、TIM8 位于 APB2。总线分频值决定定时器时钟是否加倍。

![定时器中断课件第 4 页：APB 时钟与 TIM 时钟关系](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_APB时钟关系.png)

```text
对应 APB 预分频 = 1：TIMxCLK = PCLKx
对应 APB 预分频 ≠ 1：TIMxCLK = 2 × PCLKx
```

例如 HCLK=72 MHz、APB1 二分频，则 PCLK1=36 MHz，但 TIM3CLK=72 MHz。USART2 和 WWDG 使用的仍是 PCLK1，不跟着变成 72 MHz。

**系统时钟须以当前工程设置为准。** 调用 `SystemCoreClockUpdate()` 只是更新 HCLK 频率变量，不能替你配置成 72 MHz。用 `RCC_GetClocksFreq()` 查到的 PCLK1，也要再按上述条件换算 TIM3CLK。

### 8.5 三种计数模式（第 6、9 页；课件 14 第 6～9 页）

以 ARR=6 为例，先看计数值怎样变化：

| 模式 | 计数序列示意 | 一整轮所需的计数步数 |
| --- | --- | --- |
| 向上 | `0,1,2,3,4,5,6,0,...` | `ARR+1=7` |
| 向下 | `6,5,4,3,2,1,0,6,...` | `ARR+1=7` |
| 中心对齐 | `0,1,2,3,4,5,6,5,4,3,2,1,0,...` | 完整三角周期为 `2×ARR=12`，ARR>0 |

![通用定时器课件第 6 页：中心对齐、向上与向下计数](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_三种计数模式.png)

向上/向下的周期公式含 `ARR+1`；中心对齐不能机械改成 `2×(ARR+1)`。通用定时器在两个端点均可产生更新事件，完整三角周期与两次更新之间的间隔也要分开。

![定时器中断课件第 9 页：中心对齐 ARR=6 时的事件与标志](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_中心对齐事件.png)

图中的 UEV 是瞬时事件，UIF 是保持到软件清除的状态位。UIF 不是一个会自动跟随每次 UEV 上下跳变的方波。中心对齐不同 CMS 设置还会影响捕获/比较标志在哪个方向置位，不能只看计数方向就推断所有中断时刻。

### 8.6 PSC、ARR 与更新事件 UEV（第 9～10 页）

寄存器中写的是参数，真正参与计数的还可能是内部缓冲后的值。

![通用定时器课件第 9 页：时基单元与重装载](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_时基单元.png)

| 项目 | 应掌握的行为 |
| --- | --- |
| PSC | 16 位寄存器，实际分频为 `PSC+1`，范围 1～65536；预分频参数经过缓冲，在更新事件时装入有效值 |
| ARR，ARPE=0 | 写入后直接传到有效重装载值，不等待下一次更新事件 |
| ARR，ARPE=1 | 写入预装载值，等更新事件再转入有效值，便于平稳切换周期 |
| EGR.UG | 软件触发更新，用来装入预分频等参数并初始化计数过程 |
| CR1.URS | 选择哪些来源可以提出更新中断/DMA 请求；不是总的计数开关 |
| CR1.UDIS | 禁止更新事件；与仅关闭 UIE 中断请求有不同的效果 |

课件第 4 页写“分频系数 1～65535”少了一个最大值；可写的 PSC 是 0～65535，实际分频是 1～65536。第 9 页的 `TIM1_CR1` 在讲通用定时器时应理解为对应的 `TIMx_CR1`。

当 `URS=1` 时，UG 仍可更新内部参数，但不会因此提出更新中断请求；当 `URS=0` 时，软件 UG 也可能使 UIF 置位。`TIM_TimeBaseInit()` 内部会写 UG，所以初始化后常要清一次 UIF，再使能中断。

课件第 10 页提到的重复计数器属于高级定时器 TIM1/TIM8，不属于通用 TIM2～TIM5。不能给 TIM3 套一个 RCR 来降低更新频率。

### 8.7 输入捕获：把边沿到来的时刻记下来（第 11～12 页）

输入捕获时，指定边沿到达后，硬件把当时的 CNT 锁存进对应 CCRx，供程序稍后读取。

![通用定时器课件第 12 页：输入捕获通道结构](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_输入捕获.png)

处理路径是：**引脚输入 → 极性/数字滤波 → 捕获分频 → CCRx 锁存 → CCxIF 标志 → 可选中断/DMA**。

- 输入捕获分频可选择每 1、2、4、8 个有效边沿捕获一次；它与时基 PSC 的作用不同。
- ICxF 的 4 位配置选择数字滤波条件，不是简单地说“滤波四次”。
- CCxIF 表示发生捕获；来不及处理而再次捕获，可能置 CCxOF 过捕获标志。
- 在同一个 TIM 中，四个通道使用同一计数时基，但各有 CCRx、输入选择等配置。

若 CNT 每 1 μs 加 1，连续两个上升沿的捕获值相差 1000，且两次之间没有未计入的回卷，则信号周期约 1000 μs，频率约 1 kHz。

```text
时间差 = 计数差 / f_cnt
周期测量且每个上升沿都捕获时：频率 = f_cnt / 计数差
```

跨回卷要按 `ARR+1` 处理，测量间若可能跨越多轮，还需要统计溢出次数。输入捕获锁存的是时间刻度，不是直接把外部电压幅值转为数字量。

### 8.8 输出比较与 PWM（第 11、13 页）

输出比较让硬件比较 CNT 和 CCRx，在指定时刻改变输出；PWM 则周期性地产生可调脉宽的波形。

![通用定时器课件第 13 页：边沿/中心对齐 PWM 及课件算例](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_PWM模式.png)

对于向上计数、PWM 模式 1、有效高电平的常见配置：

```text
PWM 频率 = TIMxCLK / [(PSC+1) × (ARR+1)]
占空比   = CCRx / (ARR+1)       常规 CCRx 取值范围内
```

课件例子给定 TIM2CLK=72 MHz，希望 40 kHz、50%：

```text
PSC = 0
ARR = 1799       → 72 MHz / 1800 = 40 kHz
CCR = 900        → 900 / 1800 = 50%
```

**课件纠错：**第 13 页图片写 CCR=899；按上述模式，它约为 49.944%，精确 50% 应写 900。输出极性、PWM 模式或中心对齐方式变化时，应重新分析波形，不能照搬同一个占空比公式。

同一 TIM 的各 PWM 通道共用 PSC、ARR，通常具有相同的周期，各自用 CCR1～CCR4 设置脉宽。使用外部 PWM 引脚时还需要对应 GPIO 复用配置；单纯做内部定时中断则不需要配置 TIM 通道输出引脚。

## 第九章：定时器中断实验 TIMER

对应《14_定时器中断实验-TIMER》19 页。本章使用 TIM3，每 500 ms 产生更新中断，并翻转 PE5 上的 LED1。

### 9.1 先明确时钟与实验条件（第 1～6 页）

沿用 GPIO 章节的 LED 接线：PE5 低电平点亮、高电平熄灭。下面的固定参数示例要求 **TIM3CLK=72 MHz**，例如 HCLK=72 MHz、PCLK1=36 MHz、APB1 二分频的配置。

课件第 5 页说“默认调用 SystemInit 后 72 MHz”，应理解为对应工程的时钟设置，不能推广到任意新建工程。板子晶振、系统文件和分频设置变化后，先核对 TIM3CLK，再代入公式。

计数时钟选择、三种计数模式已在第八章说明。先掌握内部时钟、向上计数，再试外部计数和中心对齐。

### 9.2 500 ms 是怎样算出来的（第 7～9、16、19 页）

向上计数时，计数器从 0 数到 ARR，再回到 0。一轮包含 `ARR+1` 个计数时钟。

![定时器中断课件第 8 页：向上计数、UEV 与 UIF](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_向上计数事件.png)

```text
计数频率 f_cnt = TIM3CLK / (PSC+1)
更新周期 T_update = (ARR+1) / f_cnt
                 = (PSC+1) × (ARR+1) / TIM3CLK
```

课件第 16 页的参数是：

```text
PSC = 7199       → 分频 7200，计数频率 10 kHz
ARR = 4999       → 5000 个计数时钟构成一轮
更新周期 = 7200 × 5000 / 72000000 = 0.5 s
```

| TIM3CLK=72 MHz 时的目标周期 | PSC 寄存器值 | ARR 寄存器值 |
| --- | --- | --- |
| 1 ms | 71 | 999 |
| 10 ms | 7199 | 99 |
| 500 ms | 7199 | 4999 |
| 1 s | 7199 | 9999 |
| 2 s | 7199 | 19999 |

**每 500 ms 翻转一次，LED 的完整亮灭周期是 1 秒。** 中断周期与输出信号完整周期不是同一个量。改变 PSC 或 ARR 都能改变周期，但取值必须满足寄存器宽度及目标分辨率。

### 9.3 本实验会用到哪些寄存器（第 10～15 页）

先看总开关 CEN 和更新相关的位，再联系 CNT、PSC、ARR。

![定时器中断课件第 14 页：CR1 中的计数与更新控制位](C:/Users/27686/Desktop/嵌入式/笔记/32/课件11至14_配图/TIM_CR1控制位.png)

| 寄存器/字段 | 本实验作用 | 典型标准库函数 |
| --- | --- | --- |
| RCC.APB1ENR.TIM3EN | 为 TIM3 提供工作时钟 | `RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);` |
| TIM3.PSC | 设置分频值 7199 | `TIM_TimeBaseInit(TIM3, &TIM_TimeBaseStructure);` |
| TIM3.ARR | 设置重装载值 4999 | 同上，结构体 `TIM_Period` 成员 |
| TIM3.CNT | 当前计数值，初始化为 0 | `TIM_SetCounter(TIM3, 0);` |
| TIM3.CR1.CEN | 启动/停止计数器 | `TIM_Cmd(TIM3, ENABLE);` |
| TIM3.CR1.CKD | 设置滤波、死区等使用的采样时钟分频 | 结构体 `TIM_ClockDivision` 成员 |
| TIM3.EGR.UG | 软件更新，装入 PSC 等参数 | `TIM_TimeBaseInit()` 内部会触发 |
| TIM3.DIER.UIE | 允许更新中断请求 | `TIM_ITConfig(TIM3, TIM_IT_Update, ENABLE);` |
| TIM3.SR.UIF | 记录更新请求对应的状态 | `TIM_GetITStatus()`、`TIM_ClearITPendingBit()` |
| NVIC 的 TIM3 通道 | 优先级与 CPU 响应许可 | `NVIC_Init(&NVIC_InitStructure);` |

**`TIM_ClockDivision=TIM_CKD_DIV1` 不是计数频率的 PSC 分频。** 计数频率仍按 `TIM3CLK/(PSC+1)` 计算；CKD 主要影响 tDTS 等采样时钟。

### 9.4 初始化的实际步骤（第 16～18 页）

| 顺序 | 具体代码/函数 | 作用 |
| --- | --- | --- |
| 1 | `NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);` | 系统统一设置分组 |
| 2 | `RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);` | 开 TIM3 时钟 |
| 3 | `TIM_InternalClockConfig(TIM3);` | 使用内部时钟 |
| 4 | 填写 PSC、ARR、模式等，再 `TIM_TimeBaseInit(TIM3, &TIM_TimeBaseStructure);` | 配置时基 |
| 5 | `TIM_SetCounter(TIM3, 0);` | 从初始计数值开始 |
| 6 | `TIM_ClearITPendingBit(TIM3, TIM_IT_Update);`、`NVIC_ClearPendingIRQ(TIM3_IRQn);` | 清除初始化产生或遗留的挂起 |
| 7 | `TIM_ITConfig(TIM3, TIM_IT_Update, ENABLE);` | 打开定时器内部更新中断请求 |
| 8 | 填写通道、优先级等，再 `NVIC_Init(&NVIC_InitStructure);` | 打开 NVIC 的 TIM3 通道 |
| 9 | `TIM_Cmd(TIM3, ENABLE);` | 最后启动计数 |
| 运行时 | `void TIM3_IRQHandler(void)` | 检查、清除来源标志并处理事件 |

`CEN`、`UIE`、NVIC 通道使能各有用途：只开 CEN 可以计数而不进中断；UIF 置位也不代表 CPU 已经响应。TIM3 更新中断不走 EXTI，不需要 AFIO 映射。

### 9.5 独立的标准库实验代码（第 19 页）

以下是一个独立 `main.c` 示例。TIM3 中断入口只能在工程中定义一份；若已有同名入口，应合并内容。它不使用 SysTick，也不需要调用旧的 `delay_ms()`。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_gpio.h"
#include "stm32f10x_tim.h"
#include "misc.h"

void LED1_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOE, ENABLE);
    GPIO_SetBits(GPIOE, GPIO_Pin_5);

    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOE, &GPIO_InitStructure);
}

/* 前提：TIM3CLK = 72 MHz，系统已设置分组 2 */
void TIM3_Init_500ms(void)
{
    TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
    NVIC_InitTypeDef NVIC_InitStructure;

    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
    TIM_Cmd(TIM3, DISABLE);
    TIM_InternalClockConfig(TIM3);

    TIM_TimeBaseStructure.TIM_Prescaler = 7199;
    TIM_TimeBaseStructure.TIM_Period = 4999;
    TIM_TimeBaseStructure.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM3, &TIM_TimeBaseStructure);

    TIM_SetCounter(TIM3, 0);
    TIM_ClearITPendingBit(TIM3, TIM_IT_Update);
    NVIC_ClearPendingIRQ(TIM3_IRQn);
    TIM_ITConfig(TIM3, TIM_IT_Update, ENABLE);

    NVIC_InitStructure.NVIC_IRQChannel = TIM3_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);

    TIM_Cmd(TIM3, ENABLE);
}

void TIM3_IRQHandler(void)
{
    if (TIM_GetITStatus(TIM3, TIM_IT_Update) != RESET)
    {
        TIM_ClearITPendingBit(TIM3, TIM_IT_Update);

        if (GPIO_ReadOutputDataBit(GPIOE, GPIO_Pin_5) == RESET)
        {
            GPIO_SetBits(GPIOE, GPIO_Pin_5);
        }
        else
        {
            GPIO_ResetBits(GPIOE, GPIO_Pin_5);
        }
    }
}

int main(void)
{
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    LED1_Init();
    TIM3_Init_500ms();

    while (1)
    {
    }
}
```

主循环没有调用 `TIM3_IRQHandler()`。硬件持续计数，更新请求经过 NVIC 后，CPU 自动进入中断入口。本例只在中断里进行短小的 LED 翻转；耗时业务应在中断中记录事件，再由主循环处理。

### 9.6 为什么初始化后要先清 UIF

`TIM_TimeBaseInit()` 会触发 UG，使新的预分频立即装入；在对应更新请求配置下，这也可能留下 UIF。如果直接开启 UIE/NVIC，就可能在启动时立刻进入一次中断，让“第一次 500 ms”看起来变短。

因此本例在时基初始化之后、打开中断之前清 TIM3 来源标志，再清 NVIC 挂起。若运行中改变 PSC/ARR，也要先明确预装载是否使能、何时发生更新，不能只给结构体重新赋值。

### 9.7 不同标志，清除方法不同

| 模块与标志 | 主要清除行为 | 常用接口 |
| --- | --- | --- |
| EXTI.PR | 对目标位写 1 清除 | `EXTI_ClearITPendingBit()` |
| TIM.SR.UIF | 对目标位写 0 清除 | `TIM_ClearITPendingBit()` |
| WWDG.SR.EWIF | 写 0 清除 | `WWDG_ClearFlag()` |
| USART.SR.RXNE | 读取接收数据 DR 清除 | `USART_ReceiveData()` |
| SysTick.CTRL.COUNTFLAG | 读取 CTRL 会清除；写 VAL 也会清除 | 注意读写副作用 |
| IWDG.SR.PVU/RVU | 参数更新完成后硬件清除 | 软件轮询，不当作普通中断位清除 |

不能把 EXTI 的“写 1 清除”照搬到 TIM.SR，也不能用 NVIC 清挂起来替代清外设来源。`TIM_GetFlagStatus()` 主要查看状态位；`TIM_GetITStatus()` 还结合对应中断使能状态。

### 9.8 实验排查与本章自查

| 现象 | 优先检查 |
| --- | --- |
| 中断完全不进 | TIM3 时钟、CEN、DIER.UIE、NVIC 通道、中断函数名、全局中断屏蔽 |
| 一启动立刻进一次 | 时基初始化 UG 后留下的 UIF 是否清除 |
| 周期差一倍 | APB1 到 TIM3 的倍频规则，或把翻转间隔当成完整亮灭周期 |
| 周期小幅或明显偏差 | 时钟实际值、PSC+1、ARR+1、计算中的单位 |
| 中断进了但 LED 不变 | PE5 是否与板上 LED1 对应、GPIOE 时钟、输出模式、有效电平 |
| 修改结构体后硬件没变化 | 是否重新调用配置函数，以及缓冲参数是否已经更新 |

如果需要保留 SysTick 给其他延时或软件时基，可让通用 TIM 单独承担周期中断；同一硬件资源应有统一的配置者。改成 1 ms 中断后，软件计数变量每次加 1，才有“毫秒数”的意义。

## 第十章：定时器 PWM 输出

本章对应《15_定时器PWM输出实验-TIMER》13 页。实验使用 **TIM3_CH2 部分重映射到 PB5**，调节板上低电平点亮的 LED。时基、中断和 PWM 可以使用同一类定时器，但配置目标不同。

### 10.1 PWM 的频率、占空比和亮度（第 2～6 页）

PWM 是脉冲宽度调制。周期固定时，改变每个周期内高、低电平各持续多久，就能改变 LED 平均通电时间。

| 量 | 含义 | 本章例子 |
| --- | --- | --- |
| 周期 T | 一次完整波形持续的时间 | 1 ms |
| 频率 f | 每秒有多少个完整周期，f=1/T | 1 kHz |
| 高电平占空比 D高 | 高电平持续时间 / 周期 | 25%、50%、75% |
| LED 点亮占空比 D亮 | LED 实际导通时间 / 周期 | 本板 LED 低有效，因此 D亮=D低 |

PWM 引脚输出的仍是高低电平脉冲。用万用表测到的平均电压，不能替代示波器对波形和占空比的观察。LED 的视觉亮度也不一定与占空比完全线性。

![课件15第3页：CNT、ARR、CCR与PWM波形](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/PWM_计数比较波形.png)

读图时先看 CNT 逐步上升，再看 CNT 何时与 CCR 相交。**ARR 决定计数周期，CCR 决定周期内的比较位置**。图中的电平关系还要结合 PWM 模式和输出极性判断。

### 10.2 从计数器到输出引脚（第 4 页）

```text
定时器输入时钟 → PSC 分频 → CNT 计数，与 ARR 决定周期
                              ↓ 与 CCRx 比较
                    PWM 模式产生 OCxREF
                              ↓ CCxP 输出极性、CCxE 通道使能
                       复用输出引脚 TIMx_CHx
```

![课件15第4页：输出比较信号与通道使能](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/PWM_输出通道框图.png)

`OCxREF` 是定时器内部的参考信号，`TIMx_CHx` 是映射到 GPIO 的通道功能。只有定时器运行、通道输出使能、引脚复用正确，才会在目标引脚看到 PWM。

**PWM 可以由硬件连续输出，不需要每个周期都进入中断。** 用中断改变 CCR 是一种调节办法，产生基础 PWM 本身不要求开启 NVIC。

### 10.3 PWM 模式和输出极性要一起看（第 5～6 页）

以下限定为**向上计数、边沿对齐**，CNT 从 0 数到 ARR。

| PWM 模式 | CNT < CCRx 时的 OCxREF | CNT ≥ CCRx 时的 OCxREF |
| --- | --- | --- |
| PWM1：`TIM_OCMode_PWM1` | 有效，即内部参考信号为高 | 无效，即内部参考信号为低 |
| PWM2：`TIM_OCMode_PWM2` | 无效，即内部参考信号为低 | 有效，即内部参考信号为高 |

| 输出极性 | GPIO 输出与 OCxREF 的关系 |
| --- | --- |
| `TIM_OCPolarity_High`，CCxP=0 | 同向 |
| `TIM_OCPolarity_Low`，CCxP=1 | 反向 |

![课件15第6页：向上计数时PWM1的边界情况](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/PWM_模式1边界.png)

原图 ARR=8，所以一个周期有 **9 个计数节拍**。PWM1、输出极性高时，CCR=4 对应高电平占空比 4/9；CCR=8 是 8/9；CCR=9 才能得到持续高电平。不能把 CCR=ARR 一律当成 100%。

在 `0 ≤ CCR ≤ ARR+1` 范围内：

```text
PWM1 + 输出极性高：D高 = CCR / (ARR+1)
PWM2 + 输出极性高：D高 = 1 - CCR / (ARR+1)

PB5 LED 低电平点亮：D亮 = 1 - D高
因此 PWM2 + 输出极性高时：D亮 = CCR / (ARR+1)
```

本章选择 PWM2、输出极性高，让 **CCR 越大，低电平时间越长，LED 越亮**。如果换成高电平点亮的外接 LED，这个亮度关系也会改变。

**理解补充：**本芯片 CCR 是 16 位。ARR=65535 时，ARR+1=65536 已经超出 CCR 的可写范围；需要持续电平时，可使用强制输出等办法，不能把 65536 填入 16 位比较值参数。

### 10.4 频率与比较值怎样计算

向上计数、边沿对齐时：

```text
fCNT = fTIM / (PSC+1)
fPWM = fTIM / [(PSC+1) × (ARR+1)]
TPWM = (PSC+1) × (ARR+1) / fTIM
```

示例假设 TIM3CLK=72 MHz：

```text
PSC=71     → 72 MHz / 72 = 1 MHz，每个计数为 1 μs
ARR=999    → 一个周期 1000 个计数，即 1 ms，PWM 为 1 kHz
CCR2=250   → PWM2、高极性时，PB5 低电平 250 μs，LED 点亮占比 25%
CCR2=500   → LED 点亮占比 50%
CCR2=1000  → PB5 持续低电平，LED 持续点亮
```

若要 40 kHz PWM，可以取 PSC=0、ARR=1799；PWM1、高极性、CCR=900 时高电平占空比恰为 50%。这些公式不直接套用于中心对齐模式，见第八章的计数模式说明。

### 10.5 ARR 与 CCR 的预装载（第 7～8 页）

运行中直接改变周期或比较位置，可能让当前周期中途变化。预装载允许先写入新参数，再在更新事件 UEV 时统一送入实际工作的寄存器。

| 控制位 | 0 | 1 | 标准库函数 |
| --- | --- | --- | --- |
| CR1.ARPE | ARR 不使用预装载缓冲，写后直接更新工作值 | ARR 使用预装载，UEV 时装入工作值 | `TIM_ARRPreloadConfig(TIM3, ENABLE)` |
| CCMR1.OC2PE | CCR2 不使用预装载，写后直接更新工作值 | CCR2 使用预装载，UEV 时装入工作值 | `TIM_OC2PreloadConfig(TIM3, TIM_OCPreload_Enable)` |

![课件15第8页：ARPE=1时ARR在更新事件处装入](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/PWM_ARR预装载.png)

图中软件写入新 ARR 后，影子寄存器仍保持原值，直到 UEV 才切换。**核对提醒：**课件第 8 页“ARPE=1 立即生效、ARPE=0 下个周期生效”写反了，应按上表和原图理解；原文中的 APRE 也应为 ARPE。

```c
TIM_OC2PreloadConfig(TIM3, TIM_OCPreload_Enable);
TIM_ARRPreloadConfig(TIM3, ENABLE);

/* 启动前产生更新事件，装入初始的 PSC、ARR、CCR 等缓冲参数 */
TIM_GenerateEvent(TIM3, TIM_EventSource_Update);
TIM_ClearFlag(TIM3, TIM_FLAG_Update);
```

`UG` 触发的是更新事件，并不要求打开更新中断。运行中每次改变 CCR 后通常等待自然更新即可，频繁手动 UG 会重新初始化计数过程，影响周期。

### 10.6 为什么 PB5 需要 TIM3 部分重映射（第 9、13 页）

![课件15第9页：TIM3通道引脚重映射表](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/PWM_TIM3引脚映射.png)

| TIM3 通道 | 默认映射 | 部分重映射 | 完全重映射 |
| --- | --- | --- | --- |
| CH1 | PA6 | PB4 | PC6 |
| CH2 | PA7 | **PB5** | PC7 |
| CH3 | PB0 | PB0 | PC8 |
| CH4 | PB1 | PB1 | PC9 |

课件的板载 LED 在 PB5，因此必须选择 TIM3_CH2 的部分重映射。GPIOB 和 AFIO 挂在 APB2，TIM3 挂在 APB1：

```c
RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
RCC_APB2PeriphClockCmd(
    RCC_APB2Periph_GPIOB | RCC_APB2Periph_AFIO, ENABLE);
GPIO_PinRemapConfig(GPIO_PartialRemap_TIM3, ENABLE);
```

PB5 配为 `GPIO_Mode_AF_PP`，让定时器控制输出。后续调占空比用 `TIM_SetCompare2()`，不要同时让主循环反复用普通 GPIO 翻转函数控制 PB5。本例只用 PB5，不需要为了旁边未使用的 PB4 关闭 JTAG。

### 10.7 关键寄存器与标准库接口（第 4、10～11 页）

| 配置目标 | 寄存器或位 | 对应接口 |
| --- | --- | --- |
| 分频、周期、计数方向 | PSC、ARR、CR1.DIR/CMS | `TIM_TimeBaseInit(TIM3, &TIM_TimeBaseStructure)` |
| 通道作为输出 | CCMR1.CC2S=00 | `TIM_OC2Init(TIM3, &TIM_OCInitStructure)` |
| PWM1 / PWM2 | CCMR1.OC2M=110 / 111 | 结构体 `TIM_OCMode` |
| 比较值 | CCR2 | 结构体 `TIM_Pulse`；运行时 `TIM_SetCompare2(TIM3, value)` |
| 输出使能、极性 | CCER.CC2E、CC2P | `TIM_OutputState`、`TIM_OCPolarity` |
| 比较值预装载 | CCMR1.OC2PE | `TIM_OC2PreloadConfig(TIM3, TIM_OCPreload_Enable)` |
| 周期预装载 | CR1.ARPE | `TIM_ARRPreloadConfig(TIM3, ENABLE)` |
| 计数使能 | CR1.CEN | `TIM_Cmd(TIM3, ENABLE)` |

`TIM_OCInitTypeDef` 中还有互补输出、空闲状态等字段，主要用于高级定时器。先用 `TIM_OCStructInit()` 填默认值，再改本例需要的成员；它只是初始化结构体，真正写硬件的是 `TIM_OC2Init()`。

### 10.8 PB5 呼吸灯完整独立示例（第 12～13 页）

条件：TIM3CLK=72 MHz，PB5 LED 低电平点亮。TIM3 输出 1 kHz PWM，SysTick 只提供 1 ms 软件计时，每 2 ms 改一次 CCR。一次变亮约 2 s，再变暗约 2 s。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_gpio.h"
#include "stm32f10x_tim.h"

GPIO_InitTypeDef GPIO_InitStructure;
TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
TIM_OCInitTypeDef TIM_OCInitStructure;
volatile uint32_t Tick_ms = 0;

void PWM_Init(void)
{
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
    RCC_APB2PeriphClockCmd(
        RCC_APB2Periph_GPIOB | RCC_APB2Periph_AFIO, ENABLE);
    GPIO_PinRemapConfig(GPIO_PartialRemap_TIM3, ENABLE);

    GPIO_SetBits(GPIOB, GPIO_Pin_5);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    TIM_Cmd(TIM3, DISABLE);
    TIM_InternalClockConfig(TIM3);
    TIM_TimeBaseStructure.TIM_Prescaler = 71;
    TIM_TimeBaseStructure.TIM_Period = 999;
    TIM_TimeBaseStructure.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM3, &TIM_TimeBaseStructure);

    TIM_OCStructInit(&TIM_OCInitStructure);
    TIM_OCInitStructure.TIM_OCMode = TIM_OCMode_PWM2;
    TIM_OCInitStructure.TIM_OutputState = TIM_OutputState_Enable;
    TIM_OCInitStructure.TIM_Pulse = 0;  /* 初始 PB5 为高，LED 熄灭 */
    TIM_OCInitStructure.TIM_OCPolarity = TIM_OCPolarity_High;
    TIM_OC2Init(TIM3, &TIM_OCInitStructure);

    TIM_OC2PreloadConfig(TIM3, TIM_OCPreload_Enable);
    TIM_ARRPreloadConfig(TIM3, ENABLE);
    TIM_GenerateEvent(TIM3, TIM_EventSource_Update);
    TIM_ClearFlag(TIM3, TIM_FLAG_Update);
    TIM_Cmd(TIM3, ENABLE);
}

void SysTick_Handler(void)
{
    Tick_ms++;
}

int main(void)
{
    uint32_t last_time = 0;
    uint16_t PWM_Value = 0;
    uint8_t PWM_Up = 1;

    SystemCoreClockUpdate();
    if (SysTick_Config(SystemCoreClock / 1000U) != 0U)
    {
        while (1) {}
    }
    PWM_Init();

    while (1)
    {
        if ((uint32_t)(Tick_ms - last_time) >= 2U)
        {
            last_time = Tick_ms;
            if (PWM_Up != 0U)
            {
                PWM_Value++;
                if (PWM_Value >= 1000U) PWM_Up = 0;
            }
            else
            {
                PWM_Value--;
                if (PWM_Value == 0U) PWM_Up = 1;
            }
            TIM_SetCompare2(TIM3, PWM_Value);
        }
    }
}
```

这是独立示例。现有工程若已经定义 `SysTick_Handler()`，只保留一个入口并合并计时逻辑；也可直接使用工程现有的毫秒变量。`SystemCoreClockUpdate()` 只更新频率变量，实际 72 MHz 时钟应由工程原有系统时钟初始化建立。

### 10.9 改用 TIM1 可以吗

可以，但要同时核对**时钟总线、通道引脚和高级定时器输出开关**。

```c
/* TIM1 在 APB2；例如 TIM1_CH1 默认输出到 PA8 */
RCC_APB2PeriphClockCmd(
    RCC_APB2Periph_TIM1 | RCC_APB2Periph_GPIOA, ENABLE);

/* 完成 PA8 复用推挽、TIM1 时基及 OC1 配置后，还要打开主输出 */
TIM_CtrlPWMOutputs(TIM1, ENABLE);  /* BDTR.MOE */
TIM_Cmd(TIM1, ENABLE);
```

PB5 并不是 TIM1 主通道 PWM 的任意可选引脚，不能只把代码中的 TIM3 全部替换成 TIM1 就保留原接线。**仅使用 TIM1 内部更新中断时不需要 MOE；让 TIM1 向引脚输出 PWM 时需要打开 MOE。** TIM1 更新中断入口是 `TIM1_UP_IRQHandler()`，捕获比较中断入口则是 `TIM1_CC_IRQHandler()`。

## 第十一章：定时器输入捕获

本章对应《16_输入捕获实验-TIMER》15 页。课件以 **TIM5_CH1 / PA0** 测量高电平脉宽，并用更新中断累计溢出次数。课件多页沿用“PWM 概述”标题，实际内容应归入输入捕获。

### 11.1 输入捕获到底捕获什么（第 2～3 页）

输入捕获检测通道引脚上的有效边沿，在边沿到来时，**硬件把当时 CNT 的值锁存到 CCRx**，并置位捕获标志 CCxIF。

```text
PA0 输入边沿 → 滤波、边沿选择、通道映射、捕获分频
                                ↓
                         CNT 的值锁存到 CCR1
                                ↓
                  CC1IF=1，可轮询，也可申请中断
```

![课件16第3页：输入捕获通道框图](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/捕获_输入通道框图.png)

中断函数通常晚于边沿执行，但 CCR1 保存的是硬件捕获时的计数值。因此应读取 `TIM_GetCapture1(TIM5)`，而不是等进入中断后才读取 CNT 来代表边沿时刻。捕获有输入同步、滤波等延迟，也不是无限精度。

| 对比项 | PWM 输出 | 输入捕获 |
| --- | --- | --- |
| 信号方向 | 定时器控制引脚输出 | 外部信号进入定时器通道 |
| CCRx 的用途 | 软件设置比较位置 | 硬件记录边沿到来的计数值 |
| GPIO 模式 | 复用推挽输出 | 根据接线选浮空、上拉或下拉输入 |
| 常见用途 | 调光、控制脉冲 | 测周期、频率、脉宽 |

同一个通道的 CCMRx 会因输入/输出选择不同而赋予相应位不同含义。不能把 PWM 的 OC1M 配置直接搬到输入捕获通道。

### 11.2 通道的五个设置（第 4～8 页）

| 设置 | 寄存器字段 | 作用 | 本章初学示例 |
| --- | --- | --- | --- |
| 输入滤波 | CCMR1.IC1F | 设采样时钟与连续确认次数，抑制部分短毛刺 | `TIM_ICFilter = 0x00` |
| 捕获边沿 | CCER.CC1P | 0 选上升沿，1 选下降沿 | 先上升、后下降 |
| 通道映射 | CCMR1.CC1S | 选择 IC1 接 TI1、TI2 或 TRC | `TIM_ICSelection_DirectTI` |
| 捕获分频 | CCMR1.IC1PSC | 每 1、2、4、8 个有效边沿捕获一次 | `TIM_ICPSC_DIV1` |
| 捕获使能 | CCER.CC1E | 允许该通道进行捕获 | `TIM_ICInit()` 会启用所选通道 |

**滤波不是毫秒级按键消抖。** IC1F 决定采样方式和连续有效样本数，不是“填 8 就延时 8 ms”。较强滤波会增加边沿确认延迟，也可能滤掉较窄的真实脉冲。

例如 CK_INT=72 MHz、CKD=DIV1、IC1F=0011 时，采样时钟是 72 MHz，需要连续 8 次确认，时间尺度约为 8/72 MHz，而不是 8 ms。具体识别延迟还与边沿相对采样时刻有关。

![课件16第6页：输入通道的直接与间接映射](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/捕获_通道映射.png)

通道 1 的 DirectTI 表示 IC1 接 TI1；IndirectTI 表示 IC1 接 TI2。通道 2 的 DirectTI 表示 IC2 接 TI2；IndirectTI 表示 IC2 接 TI1。这个**定时器内部的输入选择**与 AFIO 引脚重映射是两件事。

![课件16第7页：捕获分频器](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/捕获_输入分频器.png)

IC1PSC 的 DIV4 表示每 4 个合格边沿捕获一次，不改变 CNT 的计数速度。CNT 速度由时基 PSC 决定。若测同极性边沿且捕获分频为 4，相邻捕获值之间包含的是 4 个信号周期。

### 11.3 PA0 与 TIM5_CH1 的连接（第 9、12 页）

TIM5_CH1 默认对应 PA0，TIM5_CH2 默认对应 PA1。测主动驱动的方波可按接线采用浮空输入；课件使用下拉输入，使未驱动时有确定低电平。

```c
RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM5, ENABLE);
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPD;
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
GPIO_Init(GPIOA, &GPIO_InitStructure);
```

默认映射下，这个例子不需要 `GPIO_EXTILineConfig()`，也不需要启用 EXTI0。信号走的是 TIM5 输入捕获通道，使用 `TIM5_IRQn` 和 `TIM5_IRQHandler()`。

PA0 若仍连接板上 WK_UP 按键、外部模块或其他输出，应先确认电气连接。用 PB5 的 PWM 接到 PA0 做测试时，两个模块需共地，避免再按下与输出电平冲突的按键。

### 11.4 时基、脉宽、周期和频率

本章以 TIM5CLK=72 MHz、PSC=71、ARR=65535 为例：

```text
fCNT = 72 MHz / (71+1) = 1 MHz
每个计数 = 1 μs
一次回卷 = 65536 个计数 = 65.536 ms
```

| 捕获的两个时刻 | 计数差对应什么 |
| --- | --- |
| 上升沿、随后下降沿 | 高电平脉宽 |
| 下降沿、随后上升沿 | 低电平脉宽 |
| 两次相邻上升沿 | 一个完整周期 |
| 两次相邻下降沿 | 一个完整周期 |

```text
高电平时间 = 高电平对应计数差 / fCNT
周期 T = 完整周期对应计数差 / fCNT
频率 f = fCNT / 完整周期对应计数差
高电平占空比 = 高电平计数差 / 完整周期计数差
```

假设捕获上升沿为 1000、下降沿为 1500，之后上升沿为 2000：高电平 500 μs，周期 1000 μs，频率 1 kHz，高电平占空比 50%。只测到一个高电平宽度，不能直接断言信号频率。

| 操作 | 具体函数 | 说明 |
| --- | --- | --- |
| 配置时基 | `TIM_TimeBaseInit(TIM5, &TIM_TimeBaseStructure)` | 确定每个计数代表多长时间 |

**核对提醒：**课件第 11 页把 `TIM_GetCapture1()` 的返回类型写为 uint32_t；本工程标准库原型实际为 **uint16_t**，与 F103ZE 的 16 位捕获寄存器对应。

课件用 `TIM_OC1PolarityConfig()` 切换捕获边沿。虽然名字带 OC，这个函数实际修改 CC1P；本工程中 `TIM_OCPolarity_High` 对应 CC1P=0，上升沿，`TIM_OCPolarity_Low` 对应 CC1P=1，下降沿。另一种清晰写法是修改捕获结构体的 `TIM_ICPolarity`，再调用 `TIM_ICInit()`。

### 11.6 短脉冲测量的完整独立示例

为先理解两个边沿，本例让 TIM5 连续计数，记录上升沿和下降沿的两个 CCR1 值，再做 16 位无符号减法。**高电平必须小于 65.536 ms**，并且边沿间隔要足够让中断完成切换。适合先测 1 kHz、50% 的方波，结果约 500 μs。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_gpio.h"
#include "stm32f10x_tim.h"
#include "misc.h"

GPIO_InitTypeDef GPIO_InitStructure;
TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
TIM_ICInitTypeDef TIM_ICInitStructure;
NVIC_InitTypeDef NVIC_InitStructure;

static uint16_t Capture_Start = 0;
static uint8_t Capture_State = 0;
volatile uint16_t Pulse_us = 0;
volatile uint8_t Capture_Ready = 0;
volatile uint16_t Last_Pulse_us = 0;

void TIM5_Arm(void)
{
    TIM_ITConfig(TIM5, TIM_IT_CC1, DISABLE);
    TIM_CCxCmd(TIM5, TIM_Channel_1, TIM_CCx_Disable);
    Capture_State = 0;
    Capture_Ready = 0;
    TIM_OC1PolarityConfig(TIM5, TIM_OCPolarity_High); /* 上升沿 */
    TIM_ClearFlag(TIM5, TIM_FLAG_CC1 | TIM_FLAG_CC1OF);
    NVIC_ClearPendingIRQ(TIM5_IRQn);
    TIM_ITConfig(TIM5, TIM_IT_CC1, ENABLE);
    TIM_CCxCmd(TIM5, TIM_Channel_1, TIM_CCx_Enable);
}

void TIM5_Capture_Init(void)
{
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM5, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPD;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    TIM_Cmd(TIM5, DISABLE);
    TIM_InternalClockConfig(TIM5);
    TIM_TimeBaseStructure.TIM_Prescaler = 71;
    TIM_TimeBaseStructure.TIM_Period = 65535;
    TIM_TimeBaseStructure.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM5, &TIM_TimeBaseStructure);

    TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
    TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
    TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
    TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
    TIM_ICInitStructure.TIM_ICFilter = 0x00;
    TIM_ICInit(TIM5, &TIM_ICInitStructure);
    TIM_ClearFlag(TIM5, TIM_FLAG_Update | TIM_FLAG_CC1 | TIM_FLAG_CC1OF);

    NVIC_InitStructure.NVIC_IRQChannel = TIM5_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStructure);

    TIM_Cmd(TIM5, ENABLE);
    TIM5_Arm();
}

void TIM5_IRQHandler(void)
{
    uint16_t captured;

    if (TIM_GetITStatus(TIM5, TIM_IT_CC1) != RESET)
    {
        captured = TIM_GetCapture1(TIM5); /* 读取后 CC1IF 清除 */
        TIM_CCxCmd(TIM5, TIM_Channel_1, TIM_CCx_Disable);

        if (Capture_State == 0U)
        {
            Capture_Start = captured;
            Capture_State = 1;
            TIM_OC1PolarityConfig(TIM5, TIM_OCPolarity_Low); /* 下降沿 */
            TIM_CCxCmd(TIM5, TIM_Channel_1, TIM_CCx_Enable);
        }
        else
        {
            TIM_ITConfig(TIM5, TIM_IT_CC1, DISABLE);
            Pulse_us = (uint16_t)(captured - Capture_Start);
            Capture_Ready = 1;
        }
    }
}

int main(void)
{
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
    TIM5_Capture_Init();

    while (1)
    {
        if (Capture_Ready != 0U)
        {
            Last_Pulse_us = Pulse_us; /* 可在调试器中观察 */
            TIM5_Arm();              /* 处理完后等待下一次上升沿 */
        }
    }
}
```

这个减法也能处理**不足一个计数周期但跨越了回卷点**的脉宽。例如起点 65000、终点 464，16 位相减得到 1000。超过一个完整计数周期就会丢失整圈信息，因此本例不能拿来测 1 秒长按。

本例不处理长期无下降沿、过捕获或高速连续采样。测量短到中断来不及切换边沿的脉冲，应考虑两个捕获通道、PWM 输入模式或 DMA；不能仅提高中断优先级就认为不会丢边沿。

### 11.7 课件如何扩展测量较长脉冲（第 13～15 页）

![课件16第13页：高电平测量与溢出过程](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/捕获_脉宽与溢出.png)

课件在上升沿后把 CNT 清零，随后等待下降沿。高电平期间每次计数器溢出，都在更新中断里累计一次；下降沿到达时读取最后不足一圈的 CCR1。

```text
等待上升沿：记录开始，清零 CNT 和溢出次数，切换为下降沿捕获
等待下降沿：发生更新中断时，溢出次数加 1
收到下降沿：读取 CCR1，标记完成，恢复上升沿选择
主循环处理：把溢出次数与 CCR1 换算成时间，再允许下一次测量
```

![课件16第13页：课件自定义的捕获状态变量](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/捕获_软件状态位.png)

| 软件变量或位 | 课件中的含义 |
| --- | --- |
| `TIM5CH1_CAPTURE_STA` 的 bit7 | 一次测量完成；超长脉冲也可能被强制标记完成 |
| bit6 | 已开始，正在等待下降沿 |
| bit5～bit0 | 已累计的计数器溢出次数，最多表示 63 |
| `TIM5CH1_CAPTURE_VAL` | 下降沿捕获值，也就是最后不足一圈的部分 |

这些名字是课件程序自己定义的变量，**不是 STM32 硬件寄存器**。`0x80`、`0x40`、`0x3F` 是操作上述软件状态位的掩码。

以课件“开始后清 CNT”的算法计算：

```text
总计数 ≈ 溢出次数 × (ARR+1) + 下降沿 CCR1
时间 = 总计数 / fCNT

ARR=65535、fCNT=1 MHz：
总时间(μs) ≈ 溢出次数 × 65536 + 下降沿 CCR1
```

**核对提醒：**完整一圈是 ARR+1，不能每圈乘 65535。课件把“太长”也置为完成，主循环应将其识别为超时或超量程，不能当成一个真实下降沿测量值。课件在上升沿中断内才清 CNT，会带入中断响应和软件操作的时间误差；前一节用两个硬件捕获时间戳相减，可减少这部分误差。

若改为不清 CNT 的连续计数方式，一般公式为 `N × (ARR+1) + CCR结束 - CCR开始`，N 是两次捕获之间实际发生的回卷次数。不要把这两种算法的公式混用。

### 11.8 UIF、CC1IF、CC1OF 分别是什么

| 标志 | 含义 | 软件处理 |
| --- | --- | --- |
| UIF | 更新事件留下的标志，可能来自计数溢出或软件 UG 等 | 用作溢出计数时，先排除初始化留下的标志 |
| CC1IF | 发生一次通道 1 捕获 | 读取 CCR1；或写 0 清对应标志 |
| CC1OF | 上一次 CC1IF 尚未处理，又发生一次捕获 | 说明可能丢样，写 0 清除并按需要重测 |
| NVIC pending | CPU 侧尚待处理的中断请求 | 不能代替清定时器状态标志 |

![课件16第15页：捕获状态机与中断处理原例](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/捕获_课件中断示例.png)

看原例时先找更新中断分支，再找捕获分支，最后找状态位变化。更新与捕获共用 `TIM5_IRQHandler()`，一次进入可能同时有多个标志。临近回卷的捕获若要精确扩展时间，需要根据捕获值和挂起状态判断归属，不能不加区分地多加或少加一圈。

共享中断末尾笼统清所有标志，可能清掉处理期间新来的事件。实际连续采集应及时处理对应标志，并检查过捕获；学习阶段先用已知低频方波验证基本流程。

| 现象 | 优先检查 |
| --- | --- |
| 一直捕获不到 | 通道对应引脚、输入电平、CC1S、CC1E、CEN、是否真的有跳变 |
| 有标志却不进入中断 | DIER.CC1IE、NVIC.TIM5_IRQn、入口函数名、全局中断屏蔽 |

## 第十二章：电容触摸按键

本章对应《17_ 电容触摸按键》11 页。课件利用 **RC 充电时间随电容改变**的现象，用 **PA1 / TIM5_CH2** 输入捕获测时间。这里使用普通 GPIO 和定时器组合实现触摸检测。

### 12.1 手指触摸为什么能被检测（第 2～5 页）

触摸焊盘与周围电路之间原本就存在杂散电容 Cs。手指靠近或触摸后，通过人体与环境的耦合增加等效电容 Cx。同样的电阻和充电条件下，电容越大，电压上升到同一阈值所需的时间越长。

![课件17第5页：杂散电容与手指引入的电容](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/触摸_等效电容原理.png)

原图的 Cs、Cx 是便于理解的等效模型。检测目标是充电时间的变化，并不要求手指通过机械触点把 PA1 直接接成高电平或低电平。

### 12.2 RC 充电公式（第 2～4 页）

课件给出：

```text
V(t) = V0 + (V1-V0) × [1-exp(-t/(R×C))]

V0：电容初始电压
V1：最终趋近的电压
R：充电电阻，单位 Ω
C：等效电容，单位 F
t：时间，单位 s
```

从 0 V 向 VDD 充电时：

```text
V(t) = VDD × [1-exp(-t/(R×C))]
时间常数 τ = R×C
t=τ 时，电压约达到 VDD 的 63.2%
```

![课件17第4页：不同电容到达同一阈值的时间](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/触摸_电容与充电时间.png)

图中 B 的电容较大，到达 Vth 的时间也更长。这里的“充电完成”是**到达 GPIO 能识别为高电平的门限附近**，不是电容已经精确充到 3.3 V。

把 V(t)=Vth 代入，可得到理解补充公式：

```text
t阈值 = -R×C × ln(1-Vth/VDD)
```

R、供电、初始电压、阈值等条件固定时，t阈值 与 C 成正比。实际 GPIO 阈值、寄生电容、温湿度和布线都会影响结果，所以程序通常比较“当前值与无触摸基准的差”，而不是拿这个公式直接精确测量手指电容。

### 12.3 先核对 PA1 的硬件连接（第 5、7 页）

![课件17第7页：PA1、TPAD与板上连接排针](C:/Users/27686/Desktop/嵌入式/笔记/32/课件15至17_配图/触摸_PA1硬件接线.png)

原图上 TPAD 经 **R41=1 MΩ** 接到 VCC3.3，PA1 所在网络标为 STM_ADC。需要按开发板说明在 P10 处正确连接 TPAD 与 STM_ADC，才把触摸焊盘接到 PA1。具体以自己的板卡原理图和跳帽为准。

| 对象 | 本课件用途 |
| --- | --- |
| 外接 1 MΩ 电阻 | 限制充电速度，使时间变化便于测量 |
| PA1 推挽输出低 | 主动把触摸电容放电 |
| PA1 浮空输入 | 释放引脚，让外部电阻给电容充电 |
| PA1 的 TIM5_CH2 复用输入 | 电压上升为逻辑高时，捕获 CNT 到 CCR2 |

PA1 默认支持 TIM5_CH2，也支持 TIM2_CH2 等复用功能，需选择实际配置的那一个定时器。这个例子无需把 PA1 配成模拟输入，也不使用 ADC 读取电压。

**这里应使用浮空输入。** 内部上拉会与外部 1 MΩ 充电电阻并联，显著改变充电过程；内部下拉可能让节点电压达不到高电平门限。不要直接沿用上一章 PA0 的下拉输入配置。

### 12.4 一次测量的顺序（第 6、9、11 页）

| 顺序 | 做什么 | 目的 |
| --- | --- | --- |
| 1 | 关闭 CH2 捕获，PA1 配成推挽输出低 | 避免残留电压影响本次测量 |
| 2 | 保持低电平一小段时间 | 等待电容充分放电 |
| 3 | 清 CNT、CC2IF 和旧状态，准备上升沿捕获 | 统一计时起点，排除上次结果 |
| 4 | 打开捕获，将 PA1 改成浮空输入 | 外部电阻开始给电容充电 |
| 5 | 等待 CC2IF，读取 CCR2 | 得到到达高电平门限的计数值 |
| 6 | 与无触摸基准比较 | 充电变慢且差值足够大时判断触摸 |

先启动计时并准备捕获，再释放引脚，可避免错过很快出现的边沿。软件清 CNT 与释放引脚不是完全同时发生，因此测量包含少量固定操作开销，基准校准和实际扫描应使用相同流程。

可以轮询 `TIM_FLAG_CC2` 等待捕获。**硬件捕获不要求一定启用中断**，所以本章示例不配置 NVIC，也不用修改 `stm32f10x_it.c`。

### 12.5 课件中的几个函数（第 9～11 页）

| 函数或变量 | 应完成的工作 |
| --- | --- |
| `TIM5_CH2_Cap_Init()` | 配置 TIM5 时基、PA1 与 CH2 上升沿捕获 |
| `TPAD_Reset()` | PA1 输出低放电，清计数与旧标志，改为浮空输入开始充电 |
| `TPAD_Get_Val()` | 执行一次复位和捕获，返回本次充电计数 |
| `TPAD_Get_MaxVal()` | 连续测量若干次，返回其中最大值 |
| `TPAD_Init()` | 初始化并测量未触摸时的基准 |
| `tpad_default_val` | 软件保存的未触摸基准，不是硬件寄存器 |
| `TPAD_Scan()` | 比较当前值与基准，产生触摸事件 |
| `TPAD_GATE_VAL` | 判定差值门限，其单位与捕获计数一致 |

课件建议启动时测量 10 次，去掉两端的较大、较小值，再对中间 6 次或 8 次取平均。**应先排序再取中间值**，仅取采样顺序中的中间几次并不能剔除最大最小值。校准时不要触摸焊盘。

```text
当前充电计数 > tpad_default_val + TPAD_GATE_VAL
                         ↓
                   本次扫描认为有触摸
```

门限没有适合所有板卡的固定值。应观察未触摸时的波动和触摸后的增量，再选择门限。多次测量取最大值能突出触摸增量，但也容易受到单次向上毛刺影响，噪声大时可考虑中值、连续确认或带迟滞的判断。

### 12.6 最小独立示例：触摸一次翻转 PB5

这是根据课件流程编写的学习示例。假设 **TIM5CLK=72 MHz，PSC=71**，每个捕获计数为 1 μs；PA1 外接课件所示充电电阻和触摸焊盘。触摸事件确认后翻转 PB5，持续触摸只触发一次，释放后允许再次触发。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_gpio.h"
#include "stm32f10x_tim.h"

#define TPAD_INVALID       0xFFFFU
#define TPAD_TIMEOUT_COUNT 30000U
#define TPAD_GATE_VAL      10U  /* 演示门限：10 个计数，需按实测调整 */

GPIO_InitTypeDef GPIO_InitStructure;
TIM_TimeBaseInitTypeDef TIM_TimeBaseStructure;
TIM_ICInitTypeDef TIM_ICInitStructure;
uint16_t tpad_default_val = 0;
volatile uint16_t TPAD_LastValue = 0;

/* 依靠持续运行的 TIM5 计数；每次参数小于 65536 μs */
void TPAD_Delay_us(uint16_t us)
{
    uint16_t start;

    start = TIM_GetCounter(TIM5);
    while ((uint16_t)(TIM_GetCounter(TIM5) - start) < us) {}
}

void TIM5_CH2_Cap_Init(void)
{
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM5, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

    GPIO_ResetBits(GPIOA, GPIO_Pin_1);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_1;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    TIM_Cmd(TIM5, DISABLE);
    TIM_InternalClockConfig(TIM5);
    TIM_TimeBaseStructure.TIM_Prescaler = 71;
    TIM_TimeBaseStructure.TIM_Period = 65535;
    TIM_TimeBaseStructure.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_TimeBaseStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM5, &TIM_TimeBaseStructure);

    TIM_ICInitStructure.TIM_Channel = TIM_Channel_2;
    TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
    TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
    TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
    TIM_ICInitStructure.TIM_ICFilter = 0x00;
    TIM_ICInit(TIM5, &TIM_ICInitStructure);
    TIM_CCxCmd(TIM5, TIM_Channel_2, TIM_CCx_Disable);
    TIM_ClearFlag(TIM5, TIM_FLAG_Update | TIM_FLAG_CC2 | TIM_FLAG_CC2OF);
    TIM_Cmd(TIM5, ENABLE);
}

void TPAD_Reset(void)
{
    TIM_CCxCmd(TIM5, TIM_Channel_2, TIM_CCx_Disable);

    GPIO_ResetBits(GPIOA, GPIO_Pin_1);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_1;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
    TPAD_Delay_us(50); /* 放电时间按实际电路调整 */

    TIM_SetCounter(TIM5, 0);
    TIM_ClearFlag(TIM5, TIM_FLAG_Update | TIM_FLAG_CC2 | TIM_FLAG_CC2OF);
    TIM_CCxCmd(TIM5, TIM_Channel_2, TIM_CCx_Enable);

    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IN_FLOATING;
    GPIO_Init(GPIOA, &GPIO_InitStructure); /* 释放 PA1，开始充电 */
}

uint16_t TPAD_Get_Val(void)
{
    uint16_t value;

    TPAD_Reset();
    while (TIM_GetFlagStatus(TIM5, TIM_FLAG_CC2) == RESET)
    {
        if (TIM_GetCounter(TIM5) >= TPAD_TIMEOUT_COUNT)
        {
            TIM_CCxCmd(TIM5, TIM_Channel_2, TIM_CCx_Disable);
            return TPAD_INVALID;
        }
    }
    value = TIM_GetCapture2(TIM5);
    TIM_CCxCmd(TIM5, TIM_Channel_2, TIM_CCx_Disable);
    if (value >= TPAD_TIMEOUT_COUNT) return TPAD_INVALID;
    return value;
}

uint16_t TPAD_Get_MaxVal(uint8_t times)
{
    uint8_t i;
    uint16_t value;
    uint16_t max_value = 0;

    for (i = 0; i < times; i++)
    {
        value = TPAD_Get_Val();
        if (value == TPAD_INVALID) return TPAD_INVALID;
        if (value > max_value) max_value = value;
    }
    return max_value;
}

uint8_t TPAD_Init(void)
{
    uint16_t values[10];
    uint16_t temp;
    uint32_t sum = 0;
    uint8_t i;
    uint8_t j;

    TIM5_CH2_Cap_Init();
    for (i = 0; i < 10; i++)
    {
        values[i] = TPAD_Get_Val();
        if (values[i] == TPAD_INVALID) return 0;
    }

    /* 从小到大排序，去掉最低两个与最高两个 */
    for (i = 0; i < 9; i++)
    {
        for (j = 0; j < 9U - i; j++)
        {
            if (values[j] > values[j + 1])
            {
                temp = values[j];
                values[j] = values[j + 1];
                values[j + 1] = temp;
            }
        }
    }
    for (i = 2; i < 8; i++) sum += values[i];
    tpad_default_val = (uint16_t)(sum / 6U);
    return 1;
}

uint8_t TPAD_Scan(void)
{
    static uint8_t Press_Flag = 0;
    uint16_t value;

    value = TPAD_Get_MaxVal(3);
    TPAD_LastValue = value;
    if (value == TPAD_INVALID) return 0; /* 超时不能当作触摸 */

    if ((uint32_t)value > (uint32_t)tpad_default_val + TPAD_GATE_VAL)
    {
        if (Press_Flag == 0U)
        {
            Press_Flag = 1;
            return 1;
        }
    }
    else
    {
        Press_Flag = 0;
    }
    return 0;
}

int main(void)
{
    uint8_t i;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
    GPIO_SetBits(GPIOB, GPIO_Pin_5);
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    if (TPAD_Init() == 0U)
    {
        while (1) {} /* 校准超时，检查 PA1 与 TPAD 连接 */
    }

    while (1)
    {
        if (TPAD_Scan() != 0U)
        {
            if (GPIO_ReadOutputDataBit(GPIOB, GPIO_Pin_5) == RESET)
                GPIO_SetBits(GPIOB, GPIO_Pin_5);
            else
                GPIO_ResetBits(GPIOB, GPIO_Pin_5);
        }
        for (i = 0; i < 10; i++) TPAD_Delay_us(1000); /* 约 10 ms */
    }
}
```

先在调试器观察 `tpad_default_val` 与 `TPAD_LastValue`：未触摸时应围绕基准波动，触摸时通常增大。`0xFFFF` 表示本例超时，不是一个很大的有效触摸值。`TPAD_GATE_VAL=10` 只是可调整的起点，课件没有给出适合所有接线的统一门限。

若触摸增量只有一两个计数，可提高 TIM5 计数频率，例如降低 PSC；改动后要同时重算延时、超时计数与门限，并重新校准，不能只改分频值。示例的 50 μs 放电与 30 ms 超时也属于演示参数。

### 12.7 与普通按键、上一章捕获实验的区别

| 对比项 | PA0 普通按键 / 脉冲捕获 | 本章 PA1 电容触摸 |
| --- | --- | --- |
| 检测对象 | 明确的电平或外部输入脉冲 | RC 充电达到门限的时间变化 |
| 引脚配置 | 常保持一种输入模式 | 每次在输出低与浮空输入之间切换 |
| 判定依据 | 有效电平、两个边沿间隔 | 当前计数是否明显大于无触摸基准 |
| 干扰来源 | 机械抖动、输入毛刺等 | 寄生电容、环境漂移、布线与输入噪声等 |
| 初始化注意 | 检查上拉/下拉与有效电平 | 无触摸校准，测量期间释放引脚 |

第十一章 TIM5_CH1 脉宽例子与本章 TIM5_CH2 例子应先作为**两个独立实验**。同一 TIM5 的通道共享 PSC、ARR、CNT；本章反复清 CNT，会干扰另一个通道正在进行的时间测量。需要同时运行时，应换用独立定时器，或重新设计共享时基的测量过程。

### 12.8 本章排查与自查

| 现象 | 优先检查 |
| --- | --- |
| 一直超时 | TPAD 与 PA1 跳帽、外部上拉电阻、是否误用了下拉输入、CC2 配置 |
| 数值总是很小、触摸变化不明显 | 是否启用了内部上拉、计数分辨率、焊盘与线路连接 |
| 上电后一直认为被触摸 | 校准时是否触摸、门限是否过小、基准是否无效 |
| 偶尔误触发 | 多次取最大值放大毛刺、门限、供电与布线、是否需要连续确认 |
| 长按不停切换 LED | 是否记录了“已经触摸”的软件状态，释放后再允许下一次事件 |
| 与其他 TIM5 功能一起用就异常 | 共享 CNT 被反复清零，PSC/ARR 是否被其他模块改写 |
