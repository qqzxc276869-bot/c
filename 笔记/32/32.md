# 第一章 STM32F103ZET6 单片机基础

> 本章使用的芯片是 **STM32F103ZET6**。先认识芯片和开发板，再学习 GPIO、定时器等具体外设。芯片具有某项功能，不等于开发板一定把对应引脚或接口接了出来；实际接线要看开发板原理图。

## 一、什么是 STM32 单片机

单片机也叫微控制器（MCU）。它把 CPU、程序存储器、数据存储器和控制外部设备的外设集成在一块芯片里。

| 部分 | 作用 | 容易理解的例子 |
| --- | --- | --- |
| CPU（Cortex-M3 内核） | 逐条执行指令，进行计算和控制 | 判断按键有没有按下 |
| Flash | 保存编译后的程序，断电后内容仍在 | 存放写好的固件 |
| SRAM | 程序运行时临时存放变量、栈等，断电后内容丢失 | 存放当前的计数值 |
| GPIO | 与外部电路交换数字高低电平 | 读取按键、控制 LED |
| 片上外设 | 完成计时、采样、通信等专门工作 | 定时器、ADC、串口 |

可以把一次控制过程理解为：**外部信号输入 → GPIO/ADC 等外设接收 → CPU 按程序处理 → GPIO/通信等外设输出结果**。学习过 51 单片机后，C 语言的判断、循环、函数仍然适用，但 STM32 的引脚命名、供电电压和外设配置方式要按它自己的资料来。

## 二、读懂 STM32F103ZET6 这个型号

把型号拆成 `STM32 | F | 103 | Z | E | T | 6`：

| 字段 | 含义 |
| --- | --- |
| STM32 | ST 的 Arm 32 位微控制器系列 |
| F | 通用型产品 |
| 103 | F103 性能系列 |
| Z | 144 个封装引脚 |
| E | 512 KB 片内 Flash |
| T | LQFP 封装（四边都有引脚） |
| 6 | 工业级环境温度范围：−40～+85 °C |

**注意：144 个封装引脚不等于 144 个 GPIO。**电源、地、复位、时钟等也占用引脚；该芯片最多有 **112 个 GPIO**。例如 `PA0` 是一个引脚的功能名称，封装上的“第几脚”则要去引脚图中查，两个编号不是一回事。

## 三、这颗芯片有哪些资源

| 项目 | STM32F103ZET6 |
| --- | --- |
| 内核 | Arm Cortex-M3，32 位 |
| 主频 | 最高 72 MHz；上电后并非自动以 72 MHz 运行 |
| 程序存储器 | 512 KB Flash |
| 运行内存 | 64 KB SRAM |
| 封装 | LQFP144 |
| 工作供电 | 2.0～3.6 V，开发板通常使用 3.3 V |
| 数字输入输出 | 最多 112 个 GPIO，部分引脚与其他功能复用 |
| 常见外设 | 3 个 12 位 ADC、2 个 12 位 DAC、定时器、DMA、USART、SPI、I²C、CAN、USB 全速、SDIO 等 |

这里的 **Flash 容量**决定能保存多少程序，**SRAM 容量**限制运行时变量和栈的空间。72 MHz 是芯片允许配置的最高主频，不表示每个工程实际都运行在 72 MHz。USB 全速是芯片的外设能力，也不等于板上一定有可用的 USB 接口或能直接用 USB 下载程序。

## 四、引脚、电平和供电

### 1. 看懂引脚名称

`PA0` 表示 **GPIOA 端口的第 0 号引脚**；`PB13` 表示 **GPIOB 端口的第 13 号引脚**。同一个引脚可能承担普通 GPIO、ADC 输入、定时器通道或串口等不同功能，具体以数据手册的引脚功能表和当前配置为准。

GPIO 作为输出时，程序可以让引脚输出高电平或低电平；作为输入时，程序读取外部电路给它的电平。**引脚输出高电平，不一定等于外接设备“打开”**：例如接法不同，LED 或蜂鸣器可能在低电平时工作。判断现象要先看接线，再看引脚电压。

### 2. 供电名称

| 名称 | 作用 |
| --- | --- |
| VDD / VSS | 数字电源 / 地 |
| VDDA / VSSA | 模拟部分电源 / 地；即使暂时不用 ADC，也要按芯片和开发板设计正确连接 |
| VBAT | 在主电源断开时，给 RTC 和后备域供电的可选电源 |
| NRST | 复位输入，拉低可让芯片复位 |

这颗芯片的 VDD 工作范围是 **2.0～3.6 V**。开发板的 USB 口即使输入 5 V，也通常要经过板上的电源电路再给芯片供电，**不能把 5 V 直接接到 VDD**。数据手册标为 `FT` 的某些数字 I/O 可耐受 5 V 输入，但并非全部引脚都可以；尤其不能把“部分引脚 5 V 容忍”理解成芯片使用 5 V 供电。接 5 V 模块之前，先查具体引脚和模块电平。

## 五、时钟：程序为什么能按节奏运行

时钟为 CPU 和外设提供运行节拍。先记住四个名字：

| 名称 | 本章需要理解的意思 |
| --- | --- |
| HSI | 芯片内部的 8 MHz 时钟；复位后默认先用它作系统时钟 |
| HSE | 板上若装有外部晶振或时钟源，可选择使用它；频率要看实物和原理图 |
| PLL | 将选定的时钟处理后，获得所需的更高频率 |
| SYSCLK | 当前选定的系统时钟，之后还会分给 CPU 和各外设总线 |

**72 MHz 是“最高可以配置到的主频”，不是“通电就有 72 MHz”。**启动文件或系统时钟配置代码可能在进入 `main()` 前修改时钟，所以实际频率要查看工程配置。后续学习延时函数、串口波特率和定时器时，都要先确认实际时钟。

## 六、复位后从哪里运行程序

复位时，芯片根据启动引脚选择启动位置：

| BOOT0 | BOOT1（PB2） | 启动位置 | 常见用途 |
| --- | --- | --- | --- |
| 0 | 任意 | 用户 Flash | 正常运行自己烧录的程序 |
| 1 | 0 | 系统存储器 | 使用芯片内置的系统引导程序 |
| 1 | 1 | SRAM | 特殊调试场景 |

平时运行自己的程序，通常让 **BOOT0=0**。内置系统引导程序位于系统存储器，STM32F103 高密度系列可通过 **USART1** 使用它；不要仅凭芯片具有 USB 外设，就认为出厂引导程序支持 USB 下载。

从用户 Flash 启动时，可以把过程简化为：**复位 → 执行启动代码 → 初始化运行环境 → 进入 `main()`**。程序代码主要放在 Flash；运行中变化的普通变量、栈等使用 SRAM。断电后 SRAM 中的运行数据会消失。

## 七、下载与调试：认识 SWD

**SWD** 是常用的下载和调试接口。STM32F103ZET6 的 `PA13` 是 `SWDIO`，`PA14` 是 `SWCLK`；还需要共地，并让调试器识别目标板的电压。使用 ST-LINK 等工具时，可通过 SWD 把程序写入 Flash，也可以设置断点、单步运行和查看变量。初学 GPIO 时，先不要把 PA13、PA14 当作普通 LED 引脚使用，以免影响调试连接。

一份程序从编写到运行，大致经过：**C 源码 → 编译和链接 → 生成固件 → 下载到 Flash → 复位执行**。如果沿用 Keil 的 STM32F1 标准外设库工程，目标器件应选 `STM32F103ZE`，并使用对应高密度器件宏 `STM32F10X_HD`；头文件存在并不代表相关 `.c` 文件已经加入工程，编译和链接都通过才算建立好工程。

## 八、本章动手检查

1. 看芯片表面丝印，确认是不是 `STM32F103ZET6`；不要只凭开发板商品名称判断。
2. 找开发板原理图，指出 3.3 V、GND、BOOT0、NRST、SWDIO、SWCLK 分别接在哪里。
3. 在数据手册引脚图中查一个准备使用的 GPIO，分清 `PA0` 这类功能名与封装物理脚号。
4. 看开发板是否焊有外部晶振、LED 接在哪个引脚。**不要预设所有 STM32F103ZET6 开发板的 LED 都接在同一脚。**

能完成这四项，再进入下一章的 GPIO 输入和输出实验，接线、写程序和排错会更有依据。

## 面试常考知识点

### 1. 分清内核、芯片、开发板三个层次

Cortex-M3 是处理器内核；STM32F103ZET6 是 ST 围绕该内核集成存储器和外设做出的 MCU；开发板又在芯片外增加电源、晶振、接口和实验电路。

面试回答“用过什么单片机”时，应能接着说清：**具体型号 → 内核 → 主频 → Flash/SRAM → 实际用过的外设**。不要只背资源表，还要知道这些资源在项目里做了什么。

### 2. “32 位”与芯片资源

32 位主要描述处理器通用寄存器、常用数据处理宽度等架构特征，不表示每个变量都必须占 32 位，也不表示每条指令都只需一个时钟周期。变量的大小由类型和编译环境决定。

本章型号需要熟悉：Cortex-M3、最高 72 MHz、512 KB Flash、64 KB SRAM、LQFP144。`PA0` 是端口引脚名；封装物理脚号要查引脚图。

### 3. Flash、SRAM 与 C 程序的存放位置

| 内容 | 常见裸机工程中的安排 | 复习时要理解的原因 |
| --- | --- | --- |
| 机器指令、只读常量 | 通常放在 Flash | 程序需要掉电保存 |
| 有初值的全局变量、静态变量 | 运行时在 SRAM；初值通常存于 Flash | 启动时把初值复制到可写存储区 |
| 未显式初始化或零初始化的全局/静态变量 | 运行时通常在 SRAM 的零初始化区 | C 运行环境在进入 `main()` 前将其置零 |
| 局部自动变量、函数调用现场 | 常使用栈，也可能被优化到寄存器 | 生命周期和存储位置受代码及优化影响 |
| 动态分配空间 | 若工程启用堆，通常从预留 SRAM 区域取得 | `malloc` 不会凭空增加物理 RAM |

这些是常见链接布局，最终以链接配置和 map 文件为准；`const` 表示通过该对象不能修改其值，不能仅凭这个关键字断言所有情形都存于 Flash。

### 4. 地址空间与存储器映射

STM32F103ZE 的用户 Flash 从 `0x08000000` 开始，512 KB 对应到 `0x0807FFFF`；64 KB SRAM 从 `0x20000000` 到 `0x2000FFFF`。外设寄存器也有地址，CPU 通过访问这些地址配置硬件，这叫**存储器映射 I/O**。

芯片容量、链接器里设置的 Flash/RAM 大小、实际生成程序的占用量，是三个需要相互核对的量。

### 5. 时钟树与分频

先确定时钟源，再确定 PLL、系统时钟和总线分频。F103ZE 的 AHB、APB2 最高 72 MHz，APB1 最高 36 MHz。一个常见配置是：**8 MHz HSE → PLL ×9 → SYSCLK=72 MHz → HCLK=72 MHz、PCLK1=36 MHz、PCLK2=72 MHz**，它要求相应分频设置正确，且板上确实有匹配的 8 MHz 时钟源。

外设工作频率要沿自己的时钟路径计算，不能把所有外设时钟都写成 CPU 主频。关于这些上限和时钟源，应查 [RM0008 的 RCC 章节](https://www.st.com/resource/en/reference_manual/cd00171190-stm32f101-103-105-107-stm32f100-series-armbased-32bit-mcus-stmicroelectronics.pdf)。

### 6. 复位默认时钟、PLL 与 Flash 等待周期

复位后默认先使用 8 MHz HSI。对于本章 F103ZE，HSI 进入主 PLL 前先除以 2，配合最高 ×16 倍频只能得到 64 MHz；不能套用 `8×9=72` 到 HSI 路径。

提高主频还要匹配 Flash 读取等待周期和总线分频，并等待振荡器、PLL 就绪后再切换。单改 `SystemCoreClock` 变量的数值，不会改变硬件时钟。

### 7. BOOT 选择与启动地址

BOOT0=0 时从用户 Flash 启动；BOOT0=1 时，再由 BOOT1 选择系统存储器或 SRAM。启动映射让处理器能从启动地址取得向量，但不意味着 Flash 的物理地址从此变成了零。

用户 Flash 中是自己下载的固件；系统存储器中的出厂引导程序由 ST 提供。支持什么下载接口，要按芯片型号查 AN2606，不能只根据芯片具有 USB 外设来推断。

### 8. 启动文件和 C 运行环境

复位后，Cortex-M3 从启动向量读取初始主栈指针 MSP 和复位处理入口。启动代码与运行库负责完成必要的系统初始化、数据复制和零初始化，随后进入 `main()`；具体调用顺序以启动文件和工具链为准。

需要认识 `Reset_Handler`、`SystemInit()`、向量表、`main()` 的关系。程序卡在 `main()` 之前，排查对象就应包含启动文件、时钟等待和运行环境初始化。

### 9. 最小系统与电源

一个可靠运行的系统要有符合要求的供电和地、去耦、复位与启动电平，并选择可用的时钟源。内部 HSI 可用于运行，所以“最小系统一定要外部高速晶振”并不成立。

VDD/VSS、VDDA/VSSA、VBAT 作用不同。VBAT 用于后备域，不能代替 VDD 给整个 MCU 正常供电；USB 接口输入 5 V，也不能说明芯片 VDD 使用 5 V。

### 10. SWD、JTAG 与调试连接

SWD 使用 SWDIO、SWCLK 两条主要调试信号线；实际接线仍需 GND、目标电压参考等，NRST 常用于复位控制。JTAG 使用更多调试信号。二者是调试接口，不是普通串口通信协议。

“下载不进去”与“下载成功但程序不运行”应分开排查。前者先看连接、供电、复位和接口配置；后者再查启动位置、时钟、程序流程及外设电路。

### 11. 编译、链接、固件与库文件

`#include` 让编译器看到声明和宏；将实现所在的 `.c` 文件加入目标，或链接对应库，才能提供函数实现。声明存在而实现缺失，常在链接阶段出现未定义符号。

ELF/AXF 通常包含程序段、地址及调试信息；HEX 带地址信息；BIN 是原始字节流，烧录时通常还要指定起始地址。下载的是哪个文件、文件是否来自最新构建，都要确认。

### 12. 寄存器、库函数与 `volatile`

标准外设库、HAL 和寄存器写法最终都要操作同一片硬件，但 API、初始化方式和工程依赖不同。回答问题时应说明自己使用哪套库。

寄存器定义常用 `volatile`，提醒编译器相关访问具有可观察作用。它不提供互斥，也不把“读取、修改、写回”自动变成原子操作；并发问题仍需按访问方式处理。
