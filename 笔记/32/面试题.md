##  面试常见题目（25 题，含参考答案与追问）

### 基础理解题

#### 1. 介绍一下 STM32F103ZET6，你会从哪些方面回答？

**参考答案：**它是基于 Arm Cortex-M3 的 32 位 MCU，最高主频 72 MHz，片内 512 KB Flash、64 KB SRAM，采用 LQFP144 封装。介绍完资源后，应接着说自己用 GPIO、定时器、串口等外设完成过什么功能。

**常见追问：**这些是芯片资源，开发板是否引出了相应接口，还要看原理图；自己没用过的外设不必假装熟悉。

#### 2. Cortex-M3、STM32 和开发板有什么区别？

**参考答案：**Cortex-M3 是处理器内核；STM32 是 ST 的 MCU 产品系列，芯片还包含存储器、总线和外设；开发板在芯片外接上供电、下载接口和实验电路。三者属于不同层次。

#### 3. 什么是 MCU？它和 MPU 的常见区别是什么？

**参考答案：**MCU 通常把 CPU、Flash、RAM 和外设集成在一颗芯片中，适合控制任务；MPU 通常更强调运算与系统能力，常配合外部存储器使用。实际产品有交叉，应结合具体芯片说明。

#### 4. “32 位单片机”是否意味着所有变量都占 4 字节？

**参考答案：**不是。32 位是处理器架构特征，变量大小由类型和编译环境决定。常见 STM32 C 编译环境中，`uint8_t` 是 1 字节、`uint16_t` 是 2 字节、`uint32_t` 是 4 字节；结构体还可能有对齐填充。

**常见追问：**72 MHz 表示每秒 7200 万个时钟周期，不能直接等同每秒执行 7200 万条 C 语句。

#### 5. 型号里 Z、E、T、6 的含义是什么？144 引脚是否就是 144 个 GPIO？

**参考答案：**Z 对应 144 引脚，E 对应 512 KB Flash，T 表示 LQFP，6 对应 −40～+85 °C 温度等级。封装脚还包括供电、地、时钟、复位等，GPIO 数必须查该型号数据手册，不能按封装脚数直接计算。

#### 6. Flash 和 SRAM 有什么区别？芯片重新上电后变量会怎样？

**参考答案：**Flash 非易失，适合保存固件和需要长期保留的数据；SRAM 易失，保存运行时可写数据。重新上电后，不能依赖 SRAM 原来的内容；正常 C 启动过程会给全局/静态对象建立规定的初值。

**常见追问：**某个变量需要掉电保存时，可以设计 Flash 或外部非易失存储方案，但还要考虑擦写次数、掉电一致性和写入耗时。

#### 7. 全局变量、局部变量和 `const` 变量分别放哪里？

**参考答案：**常见裸机工程里，全局/静态可写对象运行时位于 SRAM；局部自动对象常在栈上或寄存器中；只读常量常被链接到 Flash。带初值的可写全局变量，其初始值可能在 Flash，运行时对象仍在 SRAM。

**常见追问：**不能只看 C 关键字推断最终物理位置；应结合优化结果、链接配置与 map 文件。

#### 8. Flash 从什么地址开始？SRAM 从什么地址开始？外设寄存器又是什么？

**参考答案：**本章芯片用户 Flash 从 `0x08000000` 开始，SRAM 从 `0x20000000` 开始。外设寄存器是映射到地址空间的硬件控制或状态单元，读写它们可改变外设配置或取得状态。

### 时钟与启动题

#### 9. HSI、HSE、PLL、SYSCLK 分别是什么？

**参考答案：**HSI 是内部高速时钟源，HSE 是外部高速时钟源，PLL 用于按芯片支持的路径进行倍频，SYSCLK 是选择后供系统使用的时钟。SYSCLK 经过 AHB、APB 分频后，再供给相应总线和外设。

**常见追问：**F103ZE 复位后默认先用 8 MHz HSI；进入 `main()` 时是否还是这个频率，要看前面的系统初始化。

#### 10. 板上有 8 MHz 晶振，如何得到常见的 72 MHz 配置？

**参考答案：**选择合适的 HSE 路径，经 PLL ×9 得到 72 MHz，配置 AHB 不分频、APB1 二分频、APB2 不分频，可得到 HCLK=72 MHz、PCLK1=36 MHz、PCLK2=72 MHz。还要配置 Flash 等待周期，并等待时钟源与 PLL 就绪后切换。

**常见追问：**如果板上的晶振不是 8 MHz，就必须重新按时钟树计算，不能只照抄倍频数。

#### 11. 不接外部晶振能运行吗？只用 HSI 能配置出 72 MHz 吗？

**参考答案：**能用内部 HSI 运行。对本章 F103ZE，HSI 作为主 PLL 输入时先除以 2，最高再乘 16，得到 64 MHz；因此该路径不能配置成 72 MHz。HSI 的精度和温漂也要满足应用需求。

#### 12. 为什么不能把所有外设时钟都当成 72 MHz？

**参考答案：**各外设挂在不同总线，可能还有专用分频或时钟选择。F103ZE 的 APB1 最高 36 MHz，APB2 最高 72 MHz。计算串口、ADC、定时器时，要沿对应时钟路径核对；部分定时器还有与 APB 分频相关的倍频规则。

#### 13. 提高主频时，为什么还要配置 Flash 等待周期？

**参考答案：**CPU 时钟提高后，Flash 不一定能在一个 CPU 时钟周期内完成读取，需要按手册增加等待周期，保证取指和读数据的时序。等待周期不足可能使程序运行异常。

**常见追问：**调整硬件时钟需要正确的切换顺序；把 `SystemCoreClock` 写成 `72000000` 只是改了软件记录值。

#### 14. BOOT0、BOOT1 如何选择启动模式？

**参考答案：**BOOT0=0 时从用户 Flash 启动，BOOT1 无关；BOOT0=1、BOOT1=0 时从系统存储器启动；两者都为 1 时从 SRAM 启动。启动电平在复位阶段被采样，正常运行用户固件通常使用 BOOT0=0。

#### 15. 用户 Flash 和系统存储器有什么区别？有 USB 就能用 USB 下载吗？

**参考答案：**用户 Flash 保存自己下载的程序，系统存储器保存 ST 出厂引导程序。引导程序支持的接口随芯片型号而变化，本章 F103 高密度器件应按 AN2606 核对 USART1 等具体支持情况，不能由“带 USB 外设”推断能通过 USB 出厂引导下载。

#### 16. 单片机上电后是否直接执行 `main()`？向量表前两项是什么？

**参考答案：**不是。处理器先从启动向量取得初始 MSP 和复位处理入口，进入 `Reset_Handler`。启动代码与运行库完成系统及 C 环境准备后再进入 `main()`。向量表前两个字分别是初始主栈指针值与复位向量。

**常见追问：**栈初值不是某个普通函数地址；复位向量也不是要求把 `main` 的地址直接写进去。

#### 17. 启动文件、`SystemInit()`、`main()` 各做什么？

**参考答案：**启动文件提供向量表和复位入口等基础代码；`SystemInit()` 常负责系统级和时钟相关初始化；`main()` 负责应用逻辑。数据复制、清零通常还会涉及工具链的运行库，具体执行顺序应看当前工程。

#### 18. 按复位键与断电重启有什么不同？复位后 SRAM 是否一定全部变成 0？

**参考答案：**断电会使普通 SRAM 数据不再可靠；系统复位不等于逐字节清空全部 SRAM。重新执行 C 启动过程会初始化相应的数据区，但不能推断所有 SRAM 地址都被清零。

**常见追问：**故意保留数据的特殊段需要链接器和启动代码配合，也要判断复位原因，不能仅凭“我试过还在”作为可靠设计。

### 工程与排错题

#### 19. SWD 和 JTAG 有什么区别？SWD 只需要两根线吗？

**参考答案：**两者都可用于调试，SWD 主要使用 SWDIO、SWCLK 两条信号线，JTAG 使用更多信号。实际调试连接还需要共地、目标电压参考，常连接 NRST，所以“两条信号线”不等于整套接线只有两根线。

#### 20. ST-LINK 连接不上芯片，你会按什么顺序排查？

**参考答案：**先测供电与共地，再核对 SWDIO、SWCLK、NRST 和目标电压参考连接；确认调试器选择 SWD，并尝试降低连接速度。若用户程序很快改变调试引脚或进入特殊状态，可尝试复位下连接；之后再检查器件型号、读保护和工具报错。

**常见追问：**重新烧录时若涉及解除保护或擦除，应先确认需要保留的数据；不能把所有连接问题都归因于驱动。

#### 21. STM32 的最小系统通常需要哪些部分？外部高速晶振一定必须有吗？

**参考答案：**需要合规供电和地、去耦、可靠的复位与启动电平、可用时钟源；实际调试还要准备下载连接。使用内部 HSI 时可以没有外部高速晶振，但使用 HSE 的工程必须有匹配的外部时钟电路。

#### 22. USB 插口输入 5 V，是否可以把 VDD 直接接 5 V？VBAT 能给整个芯片供电吗？

**参考答案：**不可以。开发板通常先把 USB 的 5 V 转换为芯片所需电压；VDD 应满足芯片工作范围。VBAT 服务于 RTC 和后备域，不能代替 VDD 使 CPU 和全部外设正常工作；VDDA/VSSA 也要按供电方案连接。

#### 23. 已经包含头文件，为什么链接时还提示某函数未定义？

**参考答案：**头文件通常提供函数声明，而实现需要相应的 `.c` 文件参与构建，或来自已链接的库。应检查源文件是否加入当前 Target、是否被排除构建、条件编译宏是否匹配、函数名与声明是否一致。

#### 24. ELF/AXF、HEX、BIN 有什么区别？烧录成功能证明程序正确吗？

**参考答案：**ELF/AXF 常含段信息、地址和调试符号；HEX 带地址；BIN 通常是没有地址记录的原始数据，烧录时需匹配起始地址。烧录成功只说明下载环节完成，不能证明时钟、引脚配置和应用逻辑正确。

**常见追问：**调试时应核对最新构建的产物、下载路径、Flash 起始地址，以及仿真器或真实板当前加载的文件。

#### 25. 程序编译通过、下载成功，LED 却不工作，如何说明排错思路？

**参考答案：**先确认 CPU 是否到达并持续执行预期代码，再检查 BOOT、复位和时钟；随后查 GPIO 时钟、引脚号、模式和输出电平，最后查 LED 极性、限流电阻及有效电平。用断点确认流程，用万用表或示波器确认实际信号。

**回答重点：**把问题分为“程序有没有运行、引脚有没有正确变化、电路是否响应”三个可验证环节，每次只改变一个条件。

启动向量与处理器行为可进一步查阅 [ST PM0056：Cortex-M3 编程手册](https://www.st.com/resource/en/programming_manual/cd00228163-stm32f10xxx20xxx21xxxl1xxxx-cortexm3-programming-manual-stmicroelectronics.pdf)；芯片容量、电压和地址以 [DS5792 数据手册](https://www.st.com/resource/en/datasheet/stm32f103ze.pdf)为准。

# 第二章 GPIO 输入与输出（STM32F103ZET6）

> 本章用 **PB13 接按键、PA0 接外置 LED** 说明 GPIO。它们只是本章约定的实验引脚；先查看开发板原理图，确认这两个引脚没有被板上其他电路占用。

## 一、先分清“输入”和“输出”

GPIO 是通用输入输出引脚。**输入**时，外部电路决定引脚电压，单片机读取它；**输出**时，单片机控制引脚电压，外部电路接收它。

| 方向 | 谁决定引脚电压                              | 单片机做什么             | 例子              |
| ---- | ------------------------------------------- | ------------------------ | ----------------- |
| 输入 | 按键、传感器等外部电路，以及配置的上拉/下拉 | 读取引脚当前是高还是低   | 读 PB13 上的按键  |
| 输出 | 单片机的输出驱动电路                        | 让引脚变为高电平或低电平 | 控制 PA0 上的 LED |

**读到 1/0、输出 1/0，描述的是引脚的电平，不直接描述 LED、蜂鸣器等器件“开/关”。**器件是否工作，还取决于它的接线和高电平有效还是低电平有效。

## 二、GPIO 输入：读取外部电平

### 1. STM32F1 常见输入模式

| 标准外设库模式          | 引脚内部状态                                         | 常见用途                            |
| ----------------------- | ---------------------------------------------------- | ----------------------------------- |
| `GPIO_Mode_IN_FLOATING` | 浮空输入，内部不提供确定的上拉/下拉                  | 外部电路已经保证稳定的 0 V 或 3.3 V |
| `GPIO_Mode_IPU`         | 输入上拉，用内部弱电阻把未被外部驱动的引脚拉向高电平 | 按键另一端接 GND                    |
| `GPIO_Mode_IPD`         | 输入下拉，用内部弱电阻把未被外部驱动的引脚拉向低电平 | 按键另一端接 3.3 V                  |
| `GPIO_Mode_AIN`         | 模拟输入，交给 ADC 等模拟功能使用                    | 测量模拟电压                        |

**浮空输入不等于默认低电平。**如果引脚既无上拉/下拉，也没有外部电路给出确定电压，读数可能不稳定。`GPIO_Mode_IPU` 仍是输入模式，只提供较弱的默认高电平；它不会像推挽输出那样主动驱动负载。

### 2. 用 PB13 读取按键

本章接线：`PB13 ── 按键 ── GND`，PB13 配成 `GPIO_Mode_IPU`。按键松开时，内部上拉使 PB13 接近 3.3 V；按下时，按键把 PB13 接到 GND，使它接近 0 V。单片机和按键电路必须共地。

| 按键 | PB13 电压 | `GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13)` |
| ---- | --------- | ------------------------------------------- |
| 松开 | 约 3.3 V  | `Bit_SET`（1）                              |
| 按下 | 约 0 V    | `Bit_RESET`（0）                            |

所以，**`Bit_RESET` 在这里表示“按下”**，原因是这个按键接法把按下动作变成了低电平。若改成输入下拉、按键另一端接 3.3 V，按下就会读到高电平，判断条件也要随之改变。

## 三、GPIO 输出：控制引脚电平

### 1. 推挽输出与开漏输出

| 标准外设库模式              | 写 0 时            | 写 1 时            | 先记住的用途         |
| --------------------------- | ------------------ | ------------------ | -------------------- |
| `GPIO_Mode_Out_PP` 推挽输出 | 主动拉低，接近 0 V | 主动拉高，接近 VDD | 普通 LED 控制等      |
| `GPIO_Mode_Out_OD` 开漏输出 | 主动拉低，接近 0 V | 释放引脚，呈高阻态 | 需要外部上拉的线路等 |

**开漏输出“写 1”不是主动输出 3.3 V。**没有合适的上拉电路时，该引脚不能得到稳定的高电平。串口、定时器等外设占用引脚时还可能使用复用输出模式；先学会普通 GPIO，再学习引脚复用。

### 2. 用 PA0 控制外置 LED

本章接线：`PA0 ── 330 Ω 限流电阻 ── LED 正极 ── LED 负极 ── GND`。PA0 配成 `GPIO_Mode_Out_PP`。按这个接法，PA0 高电平时电流流经 LED，LED 亮；PA0 低电平时 LED 灭。

| 程序操作                            | PA0 电平       | 本章接法的 LED |
| ----------------------------------- | -------------- | -------------- |
| `GPIO_SetBits(GPIOA, GPIO_Pin_0)`   | 高，接近 3.3 V | 亮             |
| `GPIO_ResetBits(GPIOA, GPIO_Pin_0)` | 低，接近 0 V   | 灭             |

如果 LED 改接成 `3.3 V ── 电阻 ── LED ── PA0`，它就可能变成 **低电平亮**。所以排错时先判断 **PA0 实际是高还是低**，再判断 LED 应该亮还是灭。

`GPIO_Speed_2MHz` 表示 GPIO 输出驱动的速度档位，**不是 LED 每秒闪烁 200 万次**；本章只控制亮灭，不靠这个参数生成延时。输入模式下，`GPIO_InitTypeDef` 中的 `GPIO_Speed` 字段不参与输入配置。

## 四、从电路到程序：按下亮、松开灭

先给 GPIOA、GPIOB 开启外设时钟，再分别配置 PB13 和 PA0，最后在循环中读取 PB13、设置 PA0。对于 STM32F1 普通 GPIO，端口时钟通过 APB2 开启。

| 步骤 | 要做的事               | 本例对应的标准外设库调用                    |
| ---- | ---------------------- | ------------------------------------------- |
| 1    | 开启 GPIOA、GPIOB 时钟 | `RCC_APB2PeriphClockCmd(...)`               |
| 2    | 配置 PB13 为上拉输入   | `GPIO_Init(GPIOB, ...)`                     |
| 3    | 配置 PA0 为推挽输出    | `GPIO_Init(GPIOA, ...)`                     |
| 4    | 读取 PB13 实际电平     | `GPIO_ReadInputDataBit(...)`                |
| 5    | 设置 PA0 高/低电平     | `GPIO_SetBits(...)` / `GPIO_ResetBits(...)` |

### 完整 `main.c`（Keil 标准外设库工程）

```c
#include "stm32f10x.h"

int main(void)
{
    GPIO_InitTypeDef gpio;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA | RCC_APB2Periph_GPIOB, ENABLE);

    gpio.GPIO_Pin = GPIO_Pin_13;
    gpio.GPIO_Mode = GPIO_Mode_IPU;
    gpio.GPIO_Speed = GPIO_Speed_2MHz;  /* 输入模式不使用此速度字段 */
    GPIO_Init(GPIOB, &gpio);

    GPIO_ResetBits(GPIOA, GPIO_Pin_0);  /* 切换为输出前预置低电平：LED 初始灭 */
    gpio.GPIO_Pin = GPIO_Pin_0;
    gpio.GPIO_Mode = GPIO_Mode_Out_PP;
    gpio.GPIO_Speed = GPIO_Speed_2MHz;
    GPIO_Init(GPIOA, &gpio);

    while (1)
    {
        if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13) == Bit_RESET)
        {
            GPIO_SetBits(GPIOA, GPIO_Pin_0);   /* 按下：PB13=0，PA0=1，亮 */
        }
        else
        {
            GPIO_ResetBits(GPIOA, GPIO_Pin_0); /* 松开：PB13=1，PA0=0，灭 */
        }
    }
}
```

这段代码依赖 STM32F1 **标准外设库**。Keil 工程选择 `STM32F103ZE`，定义 `STM32F10X_HD` 和 `USE_STDPERIPH_DRIVER`，并把 `stm32f10x_gpio.c`、`stm32f10x_rcc.c`、对应启动文件和系统文件加入目标。若工程使用 HAL 库，API 名称不同，不要把两套库的代码混用。

### 按行推导结果

| PB13 输入                | `if` 是否成立   | PA0 输出 | 本章 LED 接法 |
| ------------------------ | --------------- | -------- | ------------- |
| 松开，高电平 `Bit_SET`   | 否，进入 `else` | 低电平   | 灭            |
| 按下，低电平 `Bit_RESET` | 是              | 高电平   | 亮            |

把这张表记成一个顺序：**先看 PB13 的真实电压 → 再看条件判断 → 再看 PA0 的电压 → 最后看 LED 接法**。这样不会把“引脚为高”直接误判成“所有外设都打开”。

## 五、常见问题怎么查

1. **按键怎么按都不变：**测 PB13 对 GND 的电压。松开应接近 3.3 V，按下应接近 0 V；若不变，检查按键接线、共地、GPIOB 时钟和输入模式。
2. **PB13 电压正确，PA0 不变：**检查程序是否真正下载到当前芯片、GPIOA 时钟和 PA0 配置，再测 PA0 对 GND 的电压。
3. **PA0 高低变化正确，LED 现象不对：**检查 LED 正负极、限流电阻以及它是高电平亮还是低电平亮。
4. **读数时有时无：**检查输入是否浮空。浮空输入需要外部电路提供确定电平，或改用合适的上拉/下拉模式。

STM32F103ZET6 使用 3.3 V 逻辑进行本例实验。**不要把 5 V 信号直接接到未经核对的 GPIO。**数据手册只有标注 `FT` 的特定引脚具备相应的 5 V 输入容忍条件，而且使用条件还要按手册检查。

## 面试常考知识点

### 1. STM32F1 的八种 GPIO 模式

| 模式         | 标准外设库名称          | 引脚行为与典型用途                        |
| ------------ | ----------------------- | ----------------------------------------- |
| 模拟输入     | `GPIO_Mode_AIN`         | 关闭相应数字输入通路，用于 ADC 等模拟功能 |
| 浮空输入     | `GPIO_Mode_IN_FLOATING` | 无内部上拉/下拉，电平由外部电路决定       |
| 上拉输入     | `GPIO_Mode_IPU`         | 未被外部驱动时提供默认高电平              |
| 下拉输入     | `GPIO_Mode_IPD`         | 未被外部驱动时提供默认低电平              |
| 普通推挽输出 | `GPIO_Mode_Out_PP`      | GPIO 输出锁存值控制主动拉高、拉低         |
| 普通开漏输出 | `GPIO_Mode_Out_OD`      | GPIO 输出锁存值控制拉低或释放             |
| 复用推挽输出 | `GPIO_Mode_AF_PP`       | 由外设驱动输出，如某些串口、SPI 输出信号  |
| 复用开漏输出 | `GPIO_Mode_AF_OD`       | 由外设控制开漏输出，如 I²C 信号           |

“复用”说明由谁控制输出，“推挽/开漏”说明输出电路如何驱动线路，两组概念不能混为一谈。这是 F1 的配置方式，移植到其他 STM32 系列时应重新检查寄存器和库接口。

### 2. 高阻态、浮空与逻辑电平

高阻态表示引脚不主动拉高或拉低，不等于低电平；浮空表示线路缺少确定的电平约束，容易受干扰。浮空输入虽然可被外部电路驱动，但外部也不驱动时，读到的值就不可靠。

逻辑 0/1 是输入电压经过门限判断后的数字结果。高电平不必精确等于 3.3 V，低电平也不必精确等于 0 V；可靠判断要满足数据手册规定的 VIH、VIL 条件。

### 3. 推挽输出与开漏输出的内部行为

推挽输出通过内部上下驱动器主动拉高或拉低；开漏输出只主动拉低，写 1 时关断下拉驱动，把线路交给上拉电阻或其他电路。

多个开漏输出可以按电气条件共线：所有器件都释放时由上拉拉高，任意一个器件拉低时线路为低，这常称“线与”。两个推挽输出若一个输出高、另一个输出低，会发生输出争用。

### 4. 上拉、下拉与电阻取值

上拉/下拉通过电阻建立默认电平，与推挽输出的主动驱动不同。电阻较小，抗干扰或充电速度可能更好，但线路被拉低时电流更大；电阻较大，功耗较小，但与线路电容形成的上升时间可能更长。

内部弱上拉适合某些短线、低速输入；长线或高速总线应按电容、速度和驱动能力选外部电阻，不能认为内部上拉适用于所有 I²C 总线。

### 5. STM32F1 上下拉的特殊配置方式

在 F1 中，先通过 `CRL/CRH` 把引脚设为上拉/下拉输入，再通过对应 `ODR` 位选择方向：`ODR=1` 选择上拉，`ODR=0` 选择下拉。标准外设库的 `GPIO_Mode_IPU/IPD` 已处理这些细节。

因此，`ODR` 位不只在输出模式下有意义；直接对整个 `ODR` 赋值，也可能改变同端口其他输入引脚的上下拉选择。

### 6. GPIO 时钟、引脚掩码与初始化顺序

F1 的 GPIOA、GPIOB 等端口时钟通过 APB2 开启。使用普通 GPIO 不代表必须开启 AFIO；涉及重映射、调试接口配置或相关 EXTI 路由时，再按功能开启 AFIO 时钟。

`GPIO_Pin_13` 是第 13 位为 1 的掩码，即 `1U << 13`、十六进制 `0x2000`，不是数字 13。多个引脚使用按位或 `|` 组合，而不是把“引脚编号”相加。

初始化输出时，常先预置所需的输出锁存值，再切换到输出模式，以减少模式切换时出现不希望的短暂电平。

### 7. GPIO 主要寄存器

| 寄存器 | 作用                             | 容易被追问的细节                                        |
| ------ | -------------------------------- | ------------------------------------------------------- |
| `CRL`  | 配置 Px0～Px7                    | 每个引脚用 4 位，包含 MODE 和 CNF                       |
| `CRH`  | 配置 Px8～Px15                   | PB13 配置字段位于 GPIOB_CRH 的 [23:20]                  |
| `IDR`  | 读取数字输入通路采样到的引脚电平 | 反映线路电平，不等于输出锁存值                          |
| `ODR`  | 输出数据锁存寄存器               | 输出模式控制目标值；F1 上下拉输入模式还参与选择上/下拉  |
| `BSRR` | 按位置 1 或清 0                  | 低 16 位写 1 置位，高 16 位写 1 复位；写 0 不操作相应位 |
| `BRR`  | 按位清 0                         | 对相应低 16 位写 1，复位对应 ODR 位                     |
| `LCKR` | 锁定相应引脚的配置               | 用于防止后续误改模式，不等同于锁定输出电平              |

这些是 F1 寄存器；“CRH 是高电平寄存器”是错误理解，H 在这里指高编号引脚配置。

### 8. BSRR 与读改写的区别

`GPIOA->ODR |= GPIO_Pin_0` 包含读取、修改、写回。若中断在中间修改同一端口的其他位，之后写回旧值可能覆盖中断的修改。

`GPIOA->BSRR = GPIO_Pin_0` 可用一次外设写操作将目标位置 1，并保留未指定引脚。BSRR 能解决这种位设置中的读改写问题，但不能让一串操作、条件判断或同一引脚的多方控制自动变成并发安全。

### 9. 输出速度与实际翻转频率

F1 常见速度档位为 2、10、50 MHz，它配置输出驱动的速度能力。实际波形还取决于程序或外设、负载电容、供电及布线；选择 50 MHz 不会自动生成 50 MHz 方波。

速度档位满足信号需求即可，边沿过快可能增加干扰。慢速 LED 控制通常不需要最高档位；输入模式下 `GPIO_Speed` 不决定采样频率。

### 10. 有效电平、灌电流和拉电流

GPIO 向外部负载提供电流称拉电流；电流从负载流入 GPIO、再经内部下拉流向地，称灌电流。两种 LED 接法的有效电平可能相反：

| 接法                      | 亮时的 GPIO 电平 | 电流方向             |
| ------------------------- | ---------------- | -------------------- |
| GPIO → 电阻 → LED → GND   | 高               | GPIO 向外供电流      |
| 3.3 V → 电阻 → LED → GPIO | 低               | 电流从 LED 流入 GPIO |

“高电平有效/低电平有效”描述外接电路的动作条件；`Bit_SET/Bit_RESET` 描述读取或设置的逻辑状态，两者需要按电路建立对应关系。

### 11. 电流、电压与负载驱动

LED 限流电阻可先用 `R≈(电源电压−LED正向压降)/目标电流` 估算，再核对实际输出压降和 GPIO 电流规格。单引脚电流、端口/芯片总电流也有限制，不能把绝对最大额定值当成长期工作目标。

电机、裸继电器线圈等负载通常需要三极管/MOSFET 或驱动器；感性负载还要考虑续流与瞬态抑制。GPIO 的任务是提供控制信号，而不是承担大负载供电。

### 12. 5 V 容忍与电平转换

标为 FT 的引脚，在数据手册规定条件下可承受相应的 5 V 数字输入；这不使 3.3 V 供电的推挽输出自动变成 5 V。接入高于 VDD 的信号时，还要核对上下拉、模式和供电条件。

开漏配外部上拉也不应无条件接到 5 V，必须确认两端器件和引脚都满足要求。需要可靠跨电压通信时，可根据接口选择电平转换电路。

### 13. 按键消抖与“按一次触发一次”

消抖解决触点在切换瞬间多次跳变；边沿检测或状态机解决“持续按住时只触发一次”。两者是不同问题，仅在 `if` 中加入延时，不一定能同时解决。

常见做法是周期采样，候选状态持续满足一定时间后才更新稳定状态，并在稳定状态从松开变为按下时产生一次事件。消抖时间需结合实际按键和响应要求确定，不能认为某个固定毫秒数适合所有情况。

### 14. 引脚复用、调试引脚与 AFIO

F1 的外设复用与重映射由相关配置共同决定，不是随便选择任何一个 GPIO 都能连到指定外设。PA13/PA14 涉及 SWD；PA15、PB3、PB4 等还可能涉及 JTAG。

若只需要释放 JTAG 引脚并保留 SWD，标准外设库可按配置使用 `GPIO_Remap_SWJ_JTAGDisable`；不要误用完全关闭 SWJ 的设置。相关重映射操作需要 AFIO 时钟，并应核对当前下载方式。

### 15. 复位状态与排错证据

普通 GPIO 在复位后通常为浮空输入，调试等特殊引脚需按其默认状态核对。程序执行到 GPIO 初始化之前，外部负载也可能需要电阻或驱动器保证默认关闭。

排错依次核对：**输入引脚真实电压 → IDR/读取结果 → 分支是否执行 → 输出锁存与模式 → 输出引脚真实电压 → 负载响应**。万用表适合看稳态电压，示波器更适合看抖动、脉冲和上升沿。

上述模式与寄存器可查 [RM0008 的 GPIO/AFIO 章节](https://www.st.com/resource/en/reference_manual/cd00171190-stm32f101-103-105-107-stm32f100-series-armbased-32bit-mcus-stmicroelectronics.pdf)；电平与电流条件应查 [DS5792 的 I/O 电气特性](https://www.st.com/resource/en/datasheet/stm32f103ze.pdf)。

## 面试常见题目（30 题，含参考答案与代码分析）

### 模式与电气原理题

#### 1. STM32F1 GPIO 有哪八种常见模式？如何理解复用输出？

**参考答案：**模拟、浮空、上拉、下拉四种输入，普通推挽、普通开漏、复用推挽、复用开漏四种输出。普通输出主要由 GPIO 输出数据控制，复用输出由对应外设控制；推挽或开漏则决定输出级如何驱动引脚。

#### 2. 浮空输入、高阻态、低电平有什么区别？复位后 GPIO 一定是低电平吗？

**参考答案：**高阻态表示不主动驱动；浮空表示缺少确定的电平约束；低电平表示实际电压满足输入低电平条件。普通 GPIO 复位后通常为浮空输入，线路电压取决于外部电路，调试等特殊引脚还要单独核对。

#### 3. 上拉输入是不是输出高电平？为什么按键接地后不会把芯片电源直接短路？

**参考答案：**上拉输入仍是输入，内部通过弱电阻连接到电源。按键接地时电流受到上拉电阻限制，引脚被拉低；这与把推挽高电平输出直接接地不同，后者可能产生较大电流。

#### 4. PB13 上拉、按键接 GND，松开和按下分别读什么？换成下拉会怎样？

**参考答案：**上拉接法松开读 1，按下读 0。如果接线仍是按键接 GND，却只把配置改成下拉，松开和按下都会趋向低电平，无法正常区分。想让按下读高，应配下拉并让按键另一端接合适的高电平电源。

#### 5. 推挽和开漏有什么区别？开漏写 1 时为什么可能测不到稳定高电平？

**参考答案：**推挽主动拉高或拉低；开漏主动拉低或释放。开漏写 1 时若无有效上拉，线路可能浮空，所以输出锁存值为 1 不代表引脚被主动驱动到 3.3 V。

#### 6. 为什么 I²C 常用开漏结构？两路推挽输出能直接并接吗？

**参考答案：**开漏配上拉后，任意器件都可拉低线路，其他器件释放即可，适合共享线路上的仲裁、应答等机制。推挽并接时一高一低会造成输出争用，不能按开漏共享线的方式连接。

#### 7. 上拉电阻越小越好吗？内部上拉能替代所有外部上拉吗？

**参考答案：**不是。较小电阻可缩短线路电容充电时间，但低电平时电流更大，驱动器必须有能力拉低；较大电阻电流小，但上升沿可能过慢。内部上拉通常较弱，应按总线速度、线路电容、干扰与功耗综合选择。

#### 8. 输入高电平一定要等于 3.3 V 吗？施密特触发器有什么作用？

**参考答案：**不必精确等于 3.3 V，但应满足该引脚数据手册中的输入高电平门限；低电平同理。带迟滞的施密特输入用不同的上升、下降切换门限，减轻门限附近小噪声引起的反复翻转，但不能替代所有按键消抖。

#### 9. GPIO 标注 FT，是否能输出 5 V？能否直接把任意 GPIO 接到 5 V 模块？

**参考答案：**FT 主要表示规定条件下的输入容忍能力，不表示输出高电平是 5 V。连接前要核对具体引脚、数字/模拟模式、内部上下拉及供电条件；模块名称带“5 V”也不代表它的信号输出一定是 5 V。

#### 10. `GPIO_Speed_50MHz` 设好后，GPIO 就会以 50 MHz 翻转吗？

**参考答案：**不会。该参数选择输出驱动速度档位，翻转由程序或外设信号决定，实际波形还受负载影响。用循环翻转 GPIO 的速度不能只按这个枚举值计算；输入采样也不是由此字段设置。

### 寄存器与初始化题

#### 11. 使用 GPIO 时，为什么先开端口时钟？AFIO 时钟是否也必须一起开？

**参考答案：**先开启端口时钟，才能按要求配置和访问端口寄存器。普通 GPIO 输入输出不要求无条件开启 AFIO；使用重映射、调试接口配置及相关路由时，再开启 AFIO 并配置对应功能。

#### 12. `GPIO_Pin_13` 为什么不是整数 13？如何同时选择两个引脚？

**参考答案：**它是位掩码 `0x2000`，即二进制第 13 位为 1。多个引脚使用 `GPIO_Pin_0 | GPIO_Pin_1` 组合；GPIOA、GPIOB 是不同端口，即使掩码相同，也要分别传入正确端口。

#### 13. CRL、CRH 有什么区别？PB13 的配置字段在哪里？

**参考答案：**CRL 管理 0～7 号引脚，CRH 管理 8～15 号引脚，每个引脚 4 位。PB13 在 CRH 中的起始位是 `(13−8)×4=20`，所以字段为 [23:20]。配置时应只改目标字段，保留其他引脚配置。

#### 14. IDR 和 ODR 有什么区别？开漏写 1 后，IDR 一定为 1 吗？

**参考答案：**IDR 反映数字输入通路采到的线路电平，ODR 保存输出锁存值；F1 上下拉输入还使用 ODR 选择方向。开漏写 1 只是释放线路，外部若仍拉低，IDR 可以为 0，即使 ODR 为 1。

#### 15. BSRR 的高低 16 位分别做什么？对某一位写 0 会清零吗？

**参考答案：**低 16 位中写 1 的位置把对应 ODR 位置 1，高 16 位中写 1 的位置把对应 ODR 位清 0。写 0 表示不操作，不会清除对应引脚。

**常见追问：**用 BSRR 控制某一引脚时，不需要先读 BSRR，也不应把它当普通数据寄存器做 `|=`；直接写入操作掩码即可。

#### 16. `ODR |= mask` 与 `BSRR = mask` 有什么区别？`volatile` 能解决竞争吗？

**参考答案：**前者是读改写，可能把中断刚改过的其他位覆盖掉；后者对指定位置位可通过一次外设写完成，未指定位置不变。`volatile` 不能让读改写自动获得原子性。

**常见追问：**若主循环和中断都控制同一个引脚，仍需约定所有权或做同步；“先读当前值再翻转”的整个过程，也不能只因最后用了 BSRR 就认为安全。

#### 17. 把 `GPIOA->ODR` 直接赋为 `GPIO_Pin_0` 会有什么影响？

**参考答案：**这会把有效的其他输出锁存位写成 0，而不是只改变 PA0。若同端口有其他输出或上拉/下拉输入，也可能受到影响。只设置 PA0 时，可用相应 BSRR 写入或标准库按位置位函数。

#### 18. 为什么经常先预置输出值，再把引脚配置为输出？

**参考答案：**模式切换时会使用输出锁存值，预置它可减少切换瞬间输出错误电平的机会。比如低电平有效的负载若希望初始关闭，应预置高电平；本章高电平亮的 LED 则预置低电平。

**常见追问：**这只能处理初始化切换阶段；从复位到初始化之前的安全默认状态，还需外部电阻或驱动电路保证。

### 按键、负载与排错题

#### 19. 同样调用 `GPIO_SetBits`，为什么有的 LED 亮，有的 LED 灭？

**参考答案：**该函数设置引脚高电平，LED 是否亮由电流路径决定。GPIO 向 LED 供电的接法通常高电平亮；LED 经电阻接到电源、由 GPIO 灌电流的接法通常低电平亮。

#### 20. LED 限流电阻怎样估算？能直接驱动继电器线圈吗？

**参考答案：**例如假定电源 3.3 V、LED 正向压降约 2.0 V、目标电流 4 mA，理想估算 `R=(3.3−2.0)/0.004=325 Ω`，可再结合标准阻值与实际电气条件选取。还要检查 GPIO 的输出压降、单引脚和总电流限制。

普通 GPIO 不适合直接驱动裸继电器线圈、电机等负载，应使用合适驱动级；感性负载还要处理断电瞬态。有驱动电路的模块则应先确认模块输入要求。

#### 21. 按一次按键为什么会计数多次？消抖后长按仍连续计数又是什么原因？

**参考答案：**按下瞬间多次跳变属于机械抖动，应先获得稳定状态；长按时主循环每次都满足“已按下”条件，属于把状态当事件处理，应只在稳定状态由松开变为按下时触发一次。

**常见追问：**消抖与单次触发要一起设计，不能认为延时一次就必然解决所有重复触发。

#### 22. 怎样设计不会长时间阻塞主循环的按键消抖？

**参考答案：**定时采样或基于系统时间记录候选状态；若新状态持续达到消抖时间，再更新稳定状态并产生按下/松开事件。采样间隔与确认时间要满足按键和响应需求，避免在主循环中用长延时等松手。

**常见追问：**改为外部中断后抖动依然存在，仍要消抖；中断处理尽量短，把事件交给主循环处理。

#### 23. PB13 的电压切换正常，LED 却不动，下一步查什么？

**参考答案：**先看程序读到的输入是否正确、对应分支是否执行；再查 PA0 端口时钟、模式及实际电压。若 PA0 电压变化正确，就检查 LED 极性、电阻和有效电平；若电压不变，继续查程序、配置与引脚占用。

#### 24. PA15、PB3、PB4 用作普通 GPIO 时异常，或改了 PA13/PA14 后无法调试，可能是什么原因？

**参考答案：**这些引脚可能被 JTAG/SWD 占用。应核对调试复用状态；要释放 JTAG 并保留 SWD，可按工程配置关闭 JTAG 而保留 SWD。若误关整个 SWJ，可能需要借助复位下连接等方式重新接入。

#### 25. GPIO 初始化代码从别的项目复制过来为什么可能不能直接用？

**参考答案：**首先核对芯片系列、端口总线、库类型、引脚是否实际引出及板上接线。F1 使用 CRL/CRH，其他系列可能使用 MODER 等寄存器；HAL 与标准外设库的结构体、函数名和依赖也不同，不能只改头文件。

### 笔试代码题

以下是放在已准备好的 STM32F1 标准外设库工程中的局部片段，默认已包含 `stm32f10x.h`；分析题另给出了必要前提。

#### 26. 同时配置 PA0、PA1 为普通推挽输出，如何选择引脚？

**参考片段：**

```c
GPIO_InitTypeDef gpio;

RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
GPIO_ResetBits(GPIOA, GPIO_Pin_0 | GPIO_Pin_1);

gpio.GPIO_Pin = GPIO_Pin_0 | GPIO_Pin_1;
gpio.GPIO_Mode = GPIO_Mode_Out_PP;
gpio.GPIO_Speed = GPIO_Speed_2MHz;
GPIO_Init(GPIOA, &gpio);
```

**答案要点：**端口是 GPIOA，引脚掩码通过按位或组合。这里先将两引脚的输出锁存值预置为低，再配置输出；若两个引脚需要不同模式，就不能只用这一组配置一起初始化。

#### 27. 用一次 BSRR 写入，让 PA0 置高、PA1 置低，并保持其他引脚锁存值不变。

**参考片段：**

```c
GPIOA->BSRR = (uint32_t)GPIO_Pin_0
            | ((uint32_t)GPIO_Pin_1 << 16U);
```

**答案要点：**低半字中的 bit0 置位 PA0，高半字中的 bit17 复位 PA1；写入值是 `0x00020001`。这里没有先读 ODR，不会因读改写覆盖其他未指定引脚的锁存值。前提是端口时钟和引脚模式已配置正确。

#### 28. 分析下面的寄存器代码：执行后 PA1 的输出锁存值是什么？

前提：GPIOA 时钟已开，PA0、PA1 均为普通推挽输出，开始时两者输出锁存值都为 1。

```c
GPIOA->ODR = GPIO_Pin_0;
```

**参考答案：**PA1 的输出锁存值变为 0，因为赋值会写整个输出锁存寄存器，只有掩码中为 1 的 PA0 保持高。若只想将 PA0 置高并保留其他位，应使用 `GPIOA->BSRR = GPIO_Pin_0;`。

#### 29. 分析下面的分支：按下和松开时 PA0 分别是什么电平？LED 是否一定亮？

前提：PB13 为上拉输入，按键另一端接 GND；PA0 已配置为普通推挽输出。

```c
if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13) == Bit_RESET)
{
    GPIO_ResetBits(GPIOA, GPIO_Pin_0);
}
else
{
    GPIO_SetBits(GPIOA, GPIO_Pin_0);
}
```

**参考答案：**按下时 PB13=0，条件成立，PA0 输出低；松开时 PB13=1，PA0 输出高。若按本章“PA0 → 电阻 → LED → GND”接线，表现为按下灭、松开亮；若改成适合低电平点亮的接法，现象会反过来。

#### 30. 写出“PB13 按下时本章 PA0 LED 亮”的初始化与轮询核心片段。

**参考片段：**

```c
GPIO_InitTypeDef gpio;

RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA |
                      RCC_APB2Periph_GPIOB, ENABLE);

gpio.GPIO_Pin = GPIO_Pin_13;
gpio.GPIO_Mode = GPIO_Mode_IPU;
gpio.GPIO_Speed = GPIO_Speed_2MHz; /* 输入配置不使用速度字段 */
GPIO_Init(GPIOB, &gpio);

GPIO_ResetBits(GPIOA, GPIO_Pin_0);
gpio.GPIO_Pin = GPIO_Pin_0;
gpio.GPIO_Mode = GPIO_Mode_Out_PP;
gpio.GPIO_Speed = GPIO_Speed_2MHz;
GPIO_Init(GPIOA, &gpio);

while (1)
{
    if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13) == Bit_RESET)
    {
        GPIO_SetBits(GPIOA, GPIO_Pin_0);
    }
    else
    {
        GPIO_ResetBits(GPIOA, GPIO_Pin_0);
    }
}
```

**答案要点：**依次写清端口时钟、PB13 上拉输入、PA0 推挽输出、初始电平和按键有效电平。这里是持续按住亮、松开灭的状态控制；若题目改成“按一下翻转一次”，还需加入消抖与按下事件检测。

## 本章面试易错判断

| 说法                                    | 判断 | 正确理解                                           |
| --------------------------------------- | ---- | -------------------------------------------------- |
| 高阻态就是低电平                        | 错   | 高阻态不主动驱动，线路电平由外部条件决定           |
| 输入上拉就是推挽输出高电平              | 错   | 上拉输入通过弱电阻建立默认值，仍由输入通路读取线路 |
| 开漏写 1 就主动输出高电平               | 错   | 写 1 是释放引脚，需要合适上拉才能得到高电平        |
| `GPIO_Pin_13` 等于十进制 13             | 错   | 它是 `1U << 13`，即 `0x2000`                       |
| `GPIO_Speed_50MHz` 自动生成 50 MHz 方波 | 错   | 它是输出驱动速度配置，不能代替时序信号源           |
| ODR=1，IDR 就一定为 1                   | 错   | 开漏释放后，外部器件仍可能把线路拉低               |
| BSRR 任意位写 0 就会清除对应输出        | 错   | 0 表示不操作；复位需向高半字的对应位写 1           |
| `volatile` 能保证读改写不被中断打断     | 错   | 可观察访问和原子性是不同概念                       |
| 有 FT 标记就能无条件接 5 V              | 错   | 必须同时满足具体引脚、模式和电气条件               |
| 按键用了外部中断就不需要消抖            | 错   | 中断不会消除机械触点抖动                           |
| 消抖后长按就一定只触发一次              | 错   | 还要通过稳定状态边沿产生单次事件                   |
